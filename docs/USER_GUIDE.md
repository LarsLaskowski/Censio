# Censio user guide

Censio reads the statistics of a running Anno 117 game on Windows and shows them live and over time in a web application: a Windows Companion extracts the data, a Blazor Server application stores and displays it. The status and the quick start are in the [README](../README.md).

Deutsche Version: [Censio-Benutzerhandbuch](#censio-benutzerhandbuch)

## Installation

### Server (Docker)

The Censio server runs as the Docker image `networlddev/censio` (linux/amd64) on Docker Hub. Every release publishes the tag `<version>` (for example `0.4.0`) and moves the tag `latest` to the newest release. The versions are listed on the release page `https://github.com/LarsLaskowski/Censio/releases` and the tags on `https://hub.docker.com/r/networlddev/censio/tags`. You need Docker 23 or later (Linux Docker Engine, or Docker Desktop for Windows with the WSL 2 backend and Linux containers). The commands below use the version `0.4.0`; replace it with the version you want, or with `latest`. Run the commands one at a time: a command that fails makes the next one fail too. Not yet tried: pulling and running the published image `0.3.0`.

#### Pull

```text
docker pull networlddev/censio:0.4.0
```

`docker run` pulls a missing image itself, so this step only fetches it in advance. A failed pull leaves nothing half-installed.

#### Run

Start the container with a named volume for the data directory `/config`:

```text
docker run -d --name censio -p 8080:8080 -v censio-config:/config networlddev/censio:0.4.0
```

Check that it answers (the response is `Healthy`; not yet tried: in Windows PowerShell 5.1 `curl` is an alias of `Invoke-WebRequest`, which should show `StatusCode` `200` and `Content` `Healthy` and may ask for a confirmation first) and read its log:

```text
curl http://localhost:8080/health
```

```text
docker logs censio
```

Open `http://localhost:8080/` for the start page. After a few seconds `docker ps` shows the container as `(healthy)`: the image probes `/health` itself every 10 seconds. If a run failed, remove the container before starting it again, because its name is taken:

```text
docker rm -f censio
```

#### Port

Inside the container the server listens on port 8080. If port 8080 is taken on the host, Docker reports "port is already allocated"; map another host port:

```text
docker run -d --name censio -p 9000:8080 -v censio-config:/config networlddev/censio:0.4.0
```

To change the port the server itself listens on, set `ASPNETCORE_HTTP_PORTS` (the health probe follows the first port of the list; `ASPNETCORE_URLS` is not supported by the image):

```text
docker run -d --name censio -e ASPNETCORE_HTTP_PORTS=9090 -p 9090:9090 -v censio-config:/config networlddev/censio:0.4.0
```

#### Data directory and NAS hosts

`/config` is the directory for the server's data; it holds the data-protection key ring in `/config/data-protection-keys` and, while `CENSIO__INGEST__TOKENFILE` is unset, the ingest token in `/config/ingest-token` (*Ingest endpoint and token*); it also holds the database `/config/censio.db` (*Data and logs*). The image sets `CENSIO__DATADIRECTORY=/config`; point it to another absolute path with `-e CENSIO__DATADIRECTORY=<path>`. It cannot be switched off in the image: `docker run -e` cannot unset it and an empty value stops the start. The image declares no `VOLUME`, so every command above passes `-v`. A named volume (`censio-config`) is the default and the only form on Docker Desktop for Windows. The container never starts as root: it runs as user `1654`.

On a NAS whose shares belong to another user (Unraid `nobody:users` is `99:100`, a Synology user such as `1026:100`), start the container with that user and group; replace the path with your share:

```text
docker run -d --name censio --user 99:100 -p 8080:8080 -v /mnt/user/appdata/censio:/config networlddev/censio:0.4.0
```

Or hand the directory to the image's user and start without `--user`:

```text
chown -R 1654:1654 /mnt/user/appdata/censio
```

```text
docker run -d --name censio -p 8080:8080 -v /mnt/user/appdata/censio:/config networlddev/censio:0.4.0
```

The database file lies on the disk SQLite writes it to, and SQLite's file locking is unreliable on network file systems: on a NAS keep `/config` on a local disk (a volume or a share of the NAS itself that Docker mounts locally), not on a share the NAS mounts from another machine. A directory the container user cannot write stops the container at start with exit code 1; `docker logs censio` then shows `The data-protection key ring cannot be stored in '/config/data-protection-keys'; the server stops. Make the data directory writable for the user the server runs as.` A value of `CENSIO__DATADIRECTORY` that is not an absolute path also stops it with exit code 1; `docker logs censio` then shows `The data directory (Censio:DataDirectory) must be an absolute path, not '<value>'; the server stops.` Pull the image on the NAS itself; `docker run` does it when the image is missing:

```text
docker pull networlddev/censio:0.4.0
```

Building the image from source and starting it with the commands of this guide was tried on Docker Desktop for Windows in PowerShell 7. An automated check on Linux Docker Engine runs the `--user 99:100` command with a bind mount owned by `99:100`; Windows PowerShell 5.1, the other commands of this section (the `chown` remedy, the pull on the NAS), the stop at start for an unwritable directory on NAS hardware, and Unraid or Synology hardware have not been tried yet.

#### Recreate and update

Recreate the container to change a setting or to move to a newer image: the data lives in the volume, not in the container. Update to a newer version by pulling its tag first (`0.2.1` here stands for the version you want); `docker run` reuses an image of the same tag that is already on the host, so with `latest` the pull is what fetches the newer image:

```text
docker pull networlddev/censio:0.2.1
```

```text
docker stop censio
```

```text
docker rm censio
```

Then start the container with the same command as under *Run*, with the new tag (and with every `-e`, `-p`, `--user` and `--mount` you used before):

```text
docker run -d --name censio -p 8080:8080 -v censio-config:/config networlddev/censio:0.2.1
```

- **What the volume keeps.** The key ring, the ingest token and the database in `/config`. The new container logs `The ingest token is read from '/config/ingest-token'.` and `The database '/config/censio.db' was opened.` (or `The database '/config/censio.db' was updated to the current schema.` when the new version changed the schema), and the token of the Companion keeps working.
- **A token file of your own.** If you started with `CENSIO__INGEST__TOKENFILE`, pass the same `-e` and the same `--mount` again (*Ingest endpoint and token*); without them the server generates a new token in `/config`, and the Companion is refused.
- **Without `-v`.** The server then writes into the container, and removing the container deletes the key ring, the token and the database.
- **A deleted volume.** The next start is a first start: the server generates a new token, which you read and put in the token file of a replay (`--token-file`) again.
- **Updating from `0.2.0`.** That image has no ingest token and no database, so the volume keeps only the key ring: the new container logs the first-start lines (`An ingest token was generated and stored in '/config/ingest-token'.` and `The database '/config/censio.db' was created.`). Read the new token and put it in the token file of a replay (`--token-file`).
- **Updating from `0.3.0`.** The volume keeps the key ring, the token and the database; the new container logs `The database '/config/censio.db' was updated to the current schema.`, and the profiles and ticks stored by `0.3.0` stay. They become the start of the history: the first retention run after the start folds every whole hour that ended 7 days or more ago into an hourly point, except the hour of a profile's latest tick (*History and deleting a profile*). A Companion of `0.3.0` and this server refuse each other (the Companion of `0.3.0` shows `server does not support contract version 1`), so replay with the Companion of the same release. Not yet tried: this update from the published image `0.3.0`.
- **Going back.** An older image refuses a database that a newer one wrote, so going back to an older image on the same volume is not supported.
- **A volume the user cannot write.** A `--user` that cannot write `/config` stops the start with exit code 1; see *Data directory and NAS hosts*.

Run the commands one at a time. If `docker pull` fails, stop there: nothing was removed. If `docker run` with the new tag fails after `docker rm`, run it with the old tag: the volume is untouched and the old server starts again. Tried with Linux Docker Engine and an image built from a checkout: stop, remove and run on one volume, with the same token and the opened database afterwards. Not yet tried: the pull of a newer published tag, an update from a published tag, and NAS hardware.

#### Network and TLS

Inside the image the server listens on all interfaces of the container, on plain HTTP, with no login on the start page and `/health`. The `-p` mapping decides who can reach it: `-p 8080:8080` publishes it on every interface of the host. To reach it from the host alone, bind the mapping to the loopback address:

```text
docker run -d --name censio -p 127.0.0.1:8080:8080 -v censio-config:/config networlddev/censio:0.4.0
```

On Linux a published port bypasses host firewalls such as ufw and firewalld, so restrict access with the mapping, not with the firewall. TLS is the job of a reverse proxy in front of the server; see [SECURITY.md](../SECURITY.md).

#### Ingest endpoint and token

The server of the release `0.3.0` and of later releases (not the image `0.2.0`) takes a Companion's data on the WebSocket endpoint `ws://<host>:8080/ingest`, where `<host>` is the machine that runs Docker and `8080` the published port; there is no TLS on it (*Network and TLS*). A Companion sends data when it replays a recording with `--server` (*Sending a recording to a server*) or, in forward mode, live (*Forward mode*). The server stores what it receives before it acknowledges it and restores the last state of each profile at start (*Data and logs*), but the pages show no data until a Companion sends it (*Web interface*). Tried with the server started outside Docker on Linux: the creation of the token file with mode `0600`, its reading at the next start, and the refusals below. Tried in a container (Linux Docker Engine, an image built from a checkout, an automated check): on a new volume the token file with mode `0600` owned by the container user, and the same token after a recreation of the container on that volume. Not yet tried: the other commands of this section in a container, NAS hardware, reading the file through a NAS share, and an update from a published tag.

- **The token.** It is required by default. At its first start the server generates a token of 43 characters and stores it in `/config/ingest-token`; the log shows `An ingest token was generated and stored in '/config/ingest-token'.` At every later start it reads the same file (`The ingest token is read from '/config/ingest-token'.`). The log never holds the token.
- **Reading it.** The file has mode `0600` and belongs to the container user (`1654`, or the `--user` of the NAS section above), so a NAS share or a file browser, which runs as another user, cannot read it. Read it in the container, or as root on the host in the folder you mounted as `/config`:

```text
docker exec censio cat /config/ingest-token
```

  The file has no line break at its end. Put the token in the file that `--token-file` of a replay names (*Sending a recording to a server*), and keep it private: never post it in an issue (*Reporting problems*). Where the server runs on Windows without Docker, the file takes the access rules of its folder instead of the mode `0600`.
- **Rotating it.** (Generated token.) Delete the file and start the server again; it generates a new token, and a Companion that still presents the old one is refused (`Companion refused: token refused.`). The server reads the file only at its start, so the file can be deleted while the container runs or after it was stopped (stop, delete, start): in the running container, and then restart it, or as root on the host in the mounted folder. Then read the new token and put it in the token file of a replay (`--token-file`). Not yet tried:

```text
docker exec censio rm /config/ingest-token
```

```text
docker restart censio
```

- **Your own token from a file.** Instead of the generated token you can give the server a file that holds your token, for example one that a secret store of yours delivers. The setting `Censio:Ingest:TokenFile` (`CENSIO__INGEST__TOKENFILE`) is unset by default; set to the absolute path of a file inside the container, it makes the server read the token from that file at its start and ignore `/config/ingest-token` (it neither reads, creates nor changes it). The file holds the token (32 to 1,024 visible ASCII characters; a line break at its end is accepted); generate one with `openssl rand -base64 32`. Make the file readable for the container user only, for example `sudo chown 1654:1654 <host file> && sudo chmod 0400 <host file>` (use the `--user` ID instead if you set one); do not make it readable for everyone. The `docker run` command mounts the host file read-only with `--mount`, which refuses to start when the host file is missing (`-v` creates a directory there), and uses the image built from a checkout (*Build from source*, hence `--pull never`):

```text
openssl rand -base64 32 | sudo tee /srv/censio/ingest-token > /dev/null
sudo chown 1654:1654 /srv/censio/ingest-token && sudo chmod 0400 /srv/censio/ingest-token
docker run -d --name censio --pull never -p 8080:8080 -v censio-config:/config --mount type=bind,source=/srv/censio/ingest-token,target=/run/secrets/censio-ingest-token,readonly -e CENSIO__INGEST__TOKENFILE=/run/secrets/censio-ingest-token censio
```

  The log then shows `The ingest token is read from the file named by Censio:Ingest:TokenFile.` and never the path or the token. To rotate the token, change the host file and restart the container (`docker restart censio`); the server reads the file at its start only. The setting cannot be combined with `CENSIO__INGEST__REQUIRETOKEN=false`. Tried on Docker Engine 29.9.2 on Linux with an image built from a checkout, the host file owned by `1654:1654` with mode `0400`: the container became healthy, the log showed the line above, `/config` held only `data-protection-keys` and no `ingest-token`, and `/health` answered `Healthy`. With the host file removed, `docker run` with `--mount` failed with `invalid mount config for type "bind": bind source path does not exist` (exit code 125) and created nothing on the host; with `-v` instead, Docker created a directory at that path and the container exited with code 1 and the line `The ingest token file named by Censio:Ingest:TokenFile cannot be read; the server stops.`
- **Switching it off.** The setting `Censio:Ingest:RequireToken` (`CENSIO__INGEST__REQUIRETOKEN`) is `true` by default. Starting with `-e CENSIO__INGEST__REQUIRETOKEN=false` switches the token off: the server then neither reads nor creates the file, logs the warning `The ingest token is switched off: anyone who reaches the server can send data.`, and accepts any Companion. Anyone who reaches the server can then send it data, and the first to connect keeps the Companion's place. Use it only on a network where every host is trusted. Any value other than `true` or `false` stops the start, and so does the combination with `CENSIO__INGEST__TOKENFILE`.
- **One Companion.** The server accepts one Companion at a time; a second one is refused (`Companion refused: another Companion is connected.`) until the first has closed its connection or the server has found it silent: it pings every 15 seconds and closes a connection that has not answered within 35 seconds, within 60 seconds of its last frame (measured worst case 56.2 seconds). A connection whose peer stops reading is ended 30 seconds after a reply cannot be sent; a connection slower than about 37 KB/s cannot take the largest reply (a catalog upload's acknowledgement, about 1.1 MB), so such an upload is aborted again and again.
- **Limits.** The server counts connections per client address: at most 4 at a time wait for their hello (a fifth gets `429`), and an address whose hellos fail 10 times within 60 seconds is refused (`429`) for 60 seconds; the server logs the start and the end of such a block without the address. The address is the one the connection comes from; `X-Forwarded-For` is ignored. Behind a reverse proxy all clients are one address, so one client's failures block the Companion behind the same proxy. Docker Engine on Linux with `-p 8080:8080` keeps the address of a client on another host, but a client on the Docker host itself (`127.0.0.1`, a container) arrives as the bridge gateway, one shared address; IPv6 on Docker was not measured, and Docker Desktop for Windows was not measured, where all clients may arrive as one address. Many addresses (or IPv6 addresses) can still keep the real Companion out and grow the log by up to 16 lines per address and minute; Docker's default log driver does not rotate it, so set a limit, for example `--log-opt max-size=10m --log-opt max-file=3`. A Companion with the token that keeps sending pings or `status` messages without reading keeps the one place until the token is rotated. Restrict who reaches the port with the `-p` mapping or a reverse proxy. A message of the Companion may be at most 24 MiB.

The server stops at start with exit code 1 and one `Critical` line in `docker logs censio` when `CENSIO__INGEST__TOKENFILE` is set and:

- it is combined with `CENSIO__INGEST__REQUIRETOKEN=false`: `The settings Censio:Ingest:TokenFile and Censio:Ingest:RequireToken false exclude each other; the server stops.`
- its value is not an absolute path (the empty string included; the value is not logged): `The setting Censio:Ingest:TokenFile must be an absolute path; the server stops.`
- the file cannot be read (missing, a directory, no permission for the container user; the line names no path): `The ingest token file named by Censio:Ingest:TokenFile cannot be read; the server stops.`
- the file holds no valid token (empty, shorter than 32 or longer than 1,024 characters, or a character outside the visible ASCII characters, for example a space inside): `The ingest token file named by Censio:Ingest:TokenFile holds no valid token (32 to 1,024 visible ASCII characters); the server stops.`

The server stops at start with exit code 1 and one `Critical` line in `docker logs censio` when the token is required, the setting is unset and:

- the file cannot be read: `The ingest token file '/config/ingest-token' cannot be read; the server stops.` Make it readable for the container user, or delete it for a new token.
- the file holds no valid token (empty, shorter than 32 or longer than 1,024 characters, or a character outside the visible ASCII characters, for example a space inside): `The ingest token file '/config/ingest-token' holds no valid token (32 to 1,024 visible ASCII characters); the server stops.` Delete it for a new token.
- the file cannot be created: `The ingest token file '/config/ingest-token' cannot be created; the server stops. Make the data directory writable for the user the server runs as.`

A value of `CENSIO__INGEST__REQUIRETOKEN` other than `true` or `false` (any case, also the empty string) stops it with `The setting Censio:Ingest:RequireToken must be true or false; the server stops.` Without a data directory (a server started outside the image without `Censio:DataDirectory`) and without `CENSIO__INGEST__TOKENFILE` the token cannot be stored: the server starts, logs `No ingest token without a data directory (Censio:DataDirectory); every Companion is refused.` and refuses every Companion. The rules in full are in [`docs/areas/ingest-token.md`](areas/ingest-token.md).

#### Limits

- Only linux/amd64; arm64 hosts (including ARM-based Synology models) and Windows containers are not supported.
- The image runs with invariant globalization and has no time zone data: `TZ` has no effect and log times are UTC.
- ASP.NET Core's data-protection keys lie unencrypted in `/config/data-protection-keys`; keep the directory and its backups private. ASP.NET Core logs the warning `No XML encryptor configured` when the server creates the first key.
- The server logs to the console; read it with `docker logs censio`.

### Companion

The Companion is the Windows program that reads the statistics of the running game. Download `Censio-<version>-win-x64.zip` from the release page `https://github.com/LarsLaskowski/Censio/releases` (under *Assets* of the release). It needs Windows 10 22H2 or Windows 11, 64-bit; it needs no installed .NET, no installer and no administrator rights. Windows other than these and arm64 are not supported. Local mode (*Local mode* below) is for Windows 11 only. Not yet tried: the ZIP of `v0.4.0` on a machine without .NET.

1. Extract the ZIP to a folder of your choice. It holds one file, `Censio.Companion.exe`.
2. Start `Censio.Companion.exe`. A tray icon appears; its menu shows the status, the last tick, the game installation (`Game: …`, see *Game installation* below), the game catalog (`Catalog: …`, see *Game catalog* below), `Open diagnostics`, `Start recording`, `Open recordings folder`, `Open log folder`, `Start with Windows`, `Version <version>` and `Exit`; in local mode also `Server: …` below the catalog line and `Open Censio` above `Open diagnostics` (*Local mode* below), in forward mode `Server: …` below the catalog line (*Forward mode* below).

The program is not signed, so Windows SmartScreen may show "Windows protected your PC" the first time. Choose "More info", then "Run anyway" (on a German Windows: "Weitere Informationen", then "Trotzdem ausführen"). Tip reported by the Product Manager from a German Windows, not tried against a real release download: open the properties of the extracted `Censio.Companion.exe` (or of the ZIP itself), tick *Zulassen* (on an English Windows probably *Unblock*; not yet tried) and apply; SmartScreen then does not ask.

#### Start with Windows

The Companion does not start with Windows unless you turn it on: choose `Start with Windows` in the tray menu. A check mark shows that it is on; choosing the entry again turns it off. Turning it on writes one value, `Censio Companion`, under `HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run`: it applies to your Windows account only, and the entry needs no administrator rights (the maintainer tried it on Windows 11: no administrator prompt appeared). The value is the full path of the running `Censio.Companion.exe` in quotes, without arguments, so the Companion starts the way a double click starts it (it neither records nor replays).

- Extract the ZIP to a folder in your own profile that stays where it is, for example `%LOCALAPPDATA%\Programs\Censio`. Do not use a shared folder or the root of a drive that other users can write to: whoever can replace the file there runs it at your next sign-in.
- A folder path that contains `%` or is longer than 200 characters cannot be used: the entry stays unchecked, nothing is written and the log says `Could not change the autostart setting`.
- If you move the exe, or start a new version from another folder, the old entry still points to the old file and the menu shows the entry unchecked. To remove such a leftover entry, start any copy of `Censio.Companion.exe`, choose `Start with Windows` (it replaces the leftover entry with the path of that copy), then choose it again to turn it off; or delete the value `Censio Companion` in the Registry Editor at the key above. Turn the entry off before you delete the folder. Switching the old program off in the Windows startup apps list does not delete the value.
- A value with another path or with arguments counts as off; choosing the entry then replaces it.
- If you switch the Companion off in the Windows startup apps list (Settings, Apps, Startup), the menu does not show it and still shows the check mark; switch it on again in that list. A policy of your organization that blocks startup programs is not visible to the Companion either.
- The maintainer tried this on Windows 11: the Companion started with Windows after a restart with the entry on and did not start with it off; no administrator prompt appeared (under a standard account); folders with spaces, `&` or `,` in the path worked; a second Windows account was unaffected; and turning the entry off removed it. Not tried: whether SmartScreen asks at the first automatic start, which name the startup apps list shows, and a folder path with `%`.

#### Connecting to the game

The game creates its statistics pipe only when it is started with the launch argument `/pipe`. Without it the Companion cannot connect, and it looks the same as a game that is not running: the tooltip stays at `Censio Companion: Waiting for game` although the game runs. Start the Companion before or after the game; it needs no restart when the game is quit and started again. It only reads from the pipe and never writes to it.

**Adding `/pipe`.** The argument takes effect at the next start of the game: if the game runs, quit it, add the argument and start it again.

- *Ubisoft Connect (every copy of the game, also one bought on Steam, which starts Ubisoft Connect too):* open Ubisoft Connect, choose *Library*, click the three dots on Anno 117 to open its pop-up menu, choose *Manage*, then *Properties*, type `/pipe` into the field *Add launch arguments* and choose *Close*.
- *Steam (alternative for a Steam copy):* in the *Library* right-click Anno 117, choose *Properties...* in the context menu, then under *General* type `/pipe` into the field *Launch Options*. If the tooltip stays at `Waiting for game` with this option set, the argument may not reach the game through Ubisoft Connect: add `/pipe` in Ubisoft Connect as above.

The Ubisoft Connect path was tried by the Product Manager on Windows 11 (26H2) with Ubisoft Connect in German: *Bibliothek*, the three dots on the game (pop-up menu), *Verwalten*, *Eigenschaften*, field *Startargumente hinzufügen*, `/pipe` entered, *Schließen*. The Product Manager also confirmed the English labels of this path in an English Ubisoft Connect: *Library*, the three dots, *Manage*, *Properties*, field *Add launch arguments*, *Close*. The Product Manager confirmed the labels of the Steam path up to the field as well, in German (*Bibliothek*, right-click on the game, *Eigenschaften*, *Allgemein*, field *Startoptionen*) and in English (*Library*, right-click on the game, *Properties...*, *General*, field *Launch Options*). Not yet tried: whether the argument reached the game after saving, and whether `/pipe` set in Steam reaches the game through Ubisoft Connect.

Hover over the tray icon: the tooltip reads `Censio Companion: <state>`. As soon as the game has sent a complete tick, a second line shows `Last tick: <time>, <n> islands` (the time when it arrived, as `HH:mm:ss` of today, otherwise with the date). The icon shows the state too: a grey ring while waiting (`Waiting for game`, `Connected`, `Pipe busy`), a green circle while `Receiving`, a red triangle for `Protocol mismatch`, `Error` and an invalid command line. Right-click the icon for the menu, which shows the same status and last tick.

The menu entry `Open diagnostics` opens a window with the last tick: a header with `Status:`, `Last tick:` and `Game time:`, and a table with one row per good of each island (region, island, area, session ID, name, good, generation, consumption, delta, perfect generation, perfect consumption, buildings, maintenance, income, profit and the two productivity values). Once the catalog is ready (*Game catalog* below) the `Region` and `Good` cells show `<English name> / <German name> (<GUID>)`, or the one name there is followed by the GUID; where the catalog has no name, and before it is ready, they show the raw number (GUID) the game sent, as the islands and all other values always do; the same cells show the game's icon in front of the text where the game's files give one (a small image, *Game catalog* below); numbers use the decimal point on every Windows. The window follows each new tick, also in a replay, and keeps the last tick when the connection ends. Closing it (close button or Alt+F4) leaves the Companion running; `Open diagnostics` opens it again with the last tick, and while it is open it brings the same window to the front. While it is open it has a taskbar button.

| Tooltip | Meaning | What to do |
| ------- | ------- | ---------- |
| `Waiting for game` | The pipe does not exist: the game is not running or was not started with `/pipe`. The Companion keeps looking (pauses grow from 1 to 10 seconds) | Start the game. If the game runs, check first that `/pipe` is saved in the launcher's field for launch arguments (*Adding `/pipe`*) and restart the game: the argument takes effect only at the next start. If it stays at `Waiting for game` with Steam's launch option set, add `/pipe` in Ubisoft Connect |
| `Connected` | The pipe is open; the game has not yet sent its first message. The game sends it at once, so you will hardly ever see this state | Nothing |
| `Receiving` | The game is sending data | Nothing |
| `Pipe busy` | The pipe exists but another program holds it (for example another pipe tool); the game serves one client at a time, so close other pipe readers. The Companion keeps retrying (pauses grow from 1 to 10 seconds) and shows `Receiving` at the next attempt after the pipe is free. It can also stay at `Pipe busy` after you restart the Companion while the game is in the main menu, until you load a game | Close the other pipe tool, or load a save if you restarted the Companion in the game's main menu |
| `Protocol mismatch` | The pipe speaks another protocol version than 2 or 3 (for example after a game update); the Companion stays connected and continues when version 2 or 3 arrives | Wait for version 2 or 3; if it does not go away, report it (*Reporting problems*) with the version from the tray menu and the log of the day, without the recording |
| `Error` | Connecting failed or the connection broke off. When you quit the game, `Error` can show briefly before `Waiting for game`; that is normal | If it does not go away, report it as for `Protocol mismatch` |
| ` (recording)` after the state | A recording is on (the entry reads `Stop recording`) | Nothing; choose `Stop recording` when you are done |
| ` (recording failed)` after the state | Writing the recording failed (for example the disk is full or too slow); recording stopped, the Companion keeps working | Free disk space, then choose `Start recording`: it tries again with a new file |

When the game quits, the Companion returns to `Waiting for game` and connects again by itself when the game is back; loading another save and a return to the main menu keep the connection. `Exit` in the tray menu works in every state and ends the program within 2 seconds (within 5 seconds in local mode, which stops its server).

#### Game installation

The Companion looks for your Anno 117 installation once at every start, in the background; the tray menu and `Exit` work while it runs. The result is the greyed-out menu line `Game: …` directly below `Last tick:`, for example `Game: build 26.29905.4.51797 (Ubisoft Connect)`. The Companion only reads: it writes nothing to the game, the registry or your settings file. The line is not shown in the diagnostics window.

**Search order.**

1. The folder named in the settings file (below). If it is set it is used, and nothing else is searched.
2. Ubisoft Connect's records of installed games (the registry key `HKEY_LOCAL_MACHINE\SOFTWARE\WOW6432Node\Ubisoft\Launcher\Installs`, read only): the first valid record by number is used, and a record that points at a folder without the game is skipped. A record that points at a network (UNC) or device path is never followed; a mapped drive letter or a folder link still is.
3. Ubisoft Connect's default games folder, `C:\Program Files (x86)\Ubisoft\Ubisoft Game Launcher\games` (below the 32-bit Program Files folder).

An installation is a folder that holds `maindata\config.rda` and `bin\win64\anno117.exe`. Steam is not searched: with a Steam copy, or a game in another folder, use the settings file. A change counts after the next start of the Companion.

**The build** is the file version of `bin\win64\anno117.exe` as four numbers, for example `26.29905.4.51797`. It is not the version the game's main menu shows (`3.0.1733841` on the same installation), and Ubisoft Connect shows none. Not yet verified: that the build changes with every game update.

**The settings file.** Create `%LOCALAPPDATA%\Censio\settings.json` (type that path into the Explorer address bar; the folder `Censio` exists once the Companion has run) with your game folder, for example:

```json
{
  "gameFolder": "C:\\Games\\Anno 117"
}
```

- Write a full path and double every backslash, or use forward slashes (`"C:/Games/Anno 117"`). The folder is the one that holds `maindata` and `bin`, not `maindata` itself. Variables such as `%USERPROFILE%` and a bare drive letter (`"C:"`) are not full paths. A network path (`\\\\server\\share\\Anno 117`) you write here is used as written, and Windows then contacts that server.
- The key `gameFolder` is read ignoring case (`GameFolder` works); any other spelling, such as `game_folder`, is an unknown key, which is ignored: the automatic search runs and the menu then shows `(Ubisoft Connect)` or `Game: not found`, not `(settings file)`. Other keys are ignored. A blank `gameFolder` counts as not set.
- The file is UTF-8 (Notepad's byte order mark is fine), comments (`//`, `/* */`) and trailing commas are accepted, and it may be up to 1 MiB. Edit it with the Companion closed and start it again.
- A wrong folder in the file is never replaced by a searched one, so that you see the mistake.

**Menu texts.**

| Text | What to do |
| ---- | ---------- |
| `Game: searching` | Wait; it ends by itself. A slow or sleeping drive can take a while. |
| `Game: build <build> (Ubisoft Connect)` | Nothing; found through Ubisoft Connect. |
| `Game: build <build> (settings file)` | Nothing; the folder of your settings file is used. |
| `Game: build unknown (…)` | The installation is used, but its program file has no readable version. Nothing to do. |
| `Game: not found` | Neither Ubisoft Connect's records nor its default folder hold the game (for example a Steam copy). Name the folder in the settings file. |
| `Game: folder in settings not found` | The folder in `gameFolder` does not exist. Correct the path (a variable inside a path is not expanded, so it is not found either). |
| `Game: folder in settings is not a full path` | Write the full path, starting with the drive letter, for example `C:\\Games\\Anno 117`. |
| `Game: folder in settings is not an Anno 117 installation` | The folder lacks `maindata\config.rda` or `bin\win64\anno117.exe`. Name the folder that holds `maindata` and `bin`. |
| `Game: settings file invalid` | The file is not valid JSON or not an object, `gameFolder` is not a text, the key occurs twice, the file is larger than 1 MiB or it cannot be read. The log names the reason. |

The log (`Open log folder`) names the cause of every problem and, when the game is found, the source, the build and the folder.

#### Game catalog

After the game search, the Companion loads the names of regions, goods, workforce and buildings in English and German from its cache or, when there is none that fits, reads them from your own game installation (the file `maindata\config.rda`), in the background, at every start; the tray menu, the connection and `Exit` do not wait for it. It only reads the game's files: nothing is written into the installation, and the names stay on your computer, except that a Companion with live sending uploads them to your own server (*Forward mode*; they are not written to the log and not part of any release). The only copy is the cache file described below. The greyed-out menu line `Catalog: …` directly below `Game: …` shows the state:

| Menu line | What to do |
| --------- | ---------- |
| `Catalog: reading` | Wait; it ends by itself. It also shows while the game search runs. |
| `Catalog: checking` | Wait; the Companion compares the game with the cache. |
| `Catalog: extracting names` | Wait; the names are read from the game files. The names shown before stay until the new ones are ready. |
| `Catalog: extracting icons, <n> entries` | Wait; the names are ready and shown, the icons follow. |
| `Catalog: <n> entries` | Nothing; the diagnostics window now shows names and icons. |
| `Catalog: <n> entries, icons failed` | The names work; the icons could not be read (see the icon paragraph below). Nothing is cached, so the next start reads the files again. |
| `Catalog: <n> entries, not cached` | Names and icons work, but the cache could not be written (disk full, no access to `%LOCALAPPDATA%\Censio\Cache`); the log line `Catalog cache not written` says why. The next start reads the game files again. |
| `Catalog: no game` | No installation was found (see *Game installation*); GUIDs stay numbers. |
| `Catalog: failed` | A game file could not be read or has an unexpected structure, for example after a game update. GUIDs stay numbers; the log line `Catalog failed: <kind>` names the kind (`ArchiveUnreadable`, `FileMissing`, `FileUnreadable` or `MalformedFile`); report it with the game build (*Reporting problems*). |

A GUID the catalog cannot name stays a number in the diagnostics window. For every such GUID of a tick the log holds, once for each catalog (so again after an extraction because of a game update), one line `Catalog cannot name <Region|Good|Workforce|Building> <GUID>: <Unknown|Incomplete|Nameless|Ambiguous>` (unknown: not in the game files; incomplete: only one language has a name; nameless: no name; ambiguous: the files define it more than once), never a name. The log also says how many entries were built, and names an archive that holds a second copy of one of the catalog's files (`Catalog: <archive> also lists <path>; the copy in config.rda is used`). If the game folder in the settings file is on a network drive written as `\\server\share`, the Companion lists the game archives over the network at every start and at every check, and reads them over it when it extracts.

Cache: after a complete extraction (names and icons) the Companion saves them in the file `%LOCALAPPDATA%\Censio\Cache\catalog.bin`, one file for the installation extracted last. The next start loads it in a moment without reading the game's archives, if the game folder, the game build and the name, size and modification time of every `.rda` file below `maindata` are the same, and the Companion itself was not updated; otherwise the cache is not used, the log line `Catalog cache not used: missing`, `game changed` or `Companion changed` says why, and the Companion extracts again and replaces the cache. A damaged or foreign file is never used in part: the warning `Catalog cache not used: invalid` is logged and the Companion extracts again. When the game is updated while the Companion runs, start it with the launch argument `/pipe` as usual: at each new connection the Companion checks the game, and if it changed, `Catalog: extracting names` shows again while the old names stay, and the cache is replaced; an unchanged game does nothing. Measured on the maintainer's installation (1,040 entries; your computer will differ): about 7 s to extract (names 2.5 s, icons 4.5 s) and about 2.4 s to load from the cache. The log lines `Catalog extracted in <t> s (names <a> s, icons <b> s)` and `Catalog loaded from cache in <t> s: …` give the times of your computer. The cache holds your game's names and icons, so it is private like a recording: the file itself is never sent (live sending uploads the catalog and the icons from memory to your own server, *Forward mode*), not written to the log and not part of any release, you should not share it, and it stays on the computer when you remove the Companion, so delete the folder `%LOCALAPPDATA%\Censio\Cache` by hand then. If a game update went unnoticed (an archive rewritten with the same name, size and time), close the Companion, delete that folder and start again. A game started without `/pipe`, a replay and an invalid command line are only checked at the start.

Icons: once the names are shown, the Companion also reads the icons of goods and regions from the game's picture archives (`maindata\ui.rda` and the `zz_patchfiles_<n>.rda` files next to it, the highest number first), converts them in memory and shows each one at 20 by 20 pixels in front of the name in the `Region` and `Good` cells; region icons are shown on a dark round backdrop, because the game draws them as light glyphs. Where the game's files give no icon, or one that cannot be read, the cell shows the text alone, without backdrop; the names never wait for or depend on the icons. The icons are saved only in the cache file above: they go to your own server only through live sending (*Forward mode*), are not written to the log and are not part of any release. The log has one line per extraction, `Catalog icons: <g> goods and <r> regions with an icon; without one: <a> not named, <m> missing, <u> unreadable` (counts of entries), or the warning `Catalog icons failed: <kind> (<archive>)` with one of the kinds `ArchiveMissing`, `ArchiveUnreadable`, `DuplicateArchiveNumber` or `IconSetTooLarge`; then no icon is shown, and the names are unaffected. After a game update the counts show whether icons went missing; report such a line with the game build (*Reporting problems*). If the game folder is on a network drive, the picture archives are read over the network at every extraction as well.

#### Recording and replay

For testing and bug reports the Companion can keep what the game sends and play it back later. Both can be started with a switch on the command line (for example `Censio.Companion.exe --record` in a terminal or in a shortcut's target); a recording can also be started and stopped from the tray menu (`Start recording`, `Stop recording`), a replay only with its switch. Close a running Companion first (`Exit` in the tray menu): a second start ends at once without a message, and nothing replays.

- **Record:** `Censio.Companion.exe --record` starts with the recording on; without the switch choose `Start recording` in the tray menu at any time, also while the game is already sending. The Companion connects to the game as usual and writes every connection to its own file in `%LOCALAPPDATA%\Censio\Recordings` (the menu entry `Open recordings folder` opens it). A file `recording-<yyyyMMdd-HHmmss>Z.jsonl` (UTC time of the first data; a taken name gets `-2`, `-3`, … before `.jsonl`) is created when the game's first data arrives after the start. Until then the tooltip already ends with `(recording)`, but the folder may not exist and holds no file: that is no failure. When the game is quit and started again, the next connection writes a new file, and every new start writes a new file, so one session can span several files. While recording, the tooltip ends with `(recording)` and the menu entry reads `Stop recording`; `Stop recording` writes what is still waiting and closes the file. If writing fails (for example the disk is full or too slow), recording stops, the tooltip ends with `(recording failed)` and the Companion keeps working; `Start recording` tries again with a new file. `Exit` in the tray menu writes what is still waiting, for at most 1 second, and ends the program. If the Companion is killed or the computer loses power, the last lines of a file can be missing; whether Windows sign-out or shutdown writes them is not tried.
- **Replay:** `Censio.Companion.exe --replay <file> [--speed <factor>|max] [--server <address> [--token-file <file>]]` reads a recording from a local file instead of the game's pipe and plays it back as the game sent it. `--speed` is `max` (no pauses) or a number from `0.1` to `1000`, written with a decimal point also on a German Windows (`--speed 10` pauses a tenth as long); without it the replay runs at real speed. The Companion does not open the pipe while it replays, and the file is only read. The tooltip, the last tick, the icon and the window `Open diagnostics` show the progress, and the window shows the replayed ticks and keeps the last tick of the file (`Start recording` is greyed out during a replay): `Replay: Connected`, then `Replay: Receiving` (or `Replay: Protocol mismatch`), and after the last frame `Replay finished` until `Exit`. A problem with the file shows as `Replay error: <reason>` with `file not found`, `not a recording`, `unsupported version`, `invalid line <n>` or `read failed`. In local mode a replay without `--server` sends into the local server instead (*Local mode*).

  To check a finished recording, which needs no console:

  1. Choose `Exit` in the tray menu. A Companion that still runs makes the replay start end at once, without a message.
  2. In Explorer, copy the full path of `Censio.Companion.exe` and of the recording file, each with "Copy as path" (right-click; on Windows 10 Shift + right-click).
  3. Press the Windows key + R, and in the *Run* dialog enter the line `"<path of Censio.Companion.exe>" --replay "<path of the file>" --speed max`, pasting both quoted paths. The quotes stay, so paths with spaces and `%LOCALAPPDATA%` already expanded by Explorer work.
  4. The tooltip shows `Censio Companion: Replay: Receiving` and ends at `Censio Companion: Replay finished`. That means the file is readable.
  5. Choose `Exit`: it ends the replay. Start `Censio.Companion.exe` as usual to get the Companion back; `Start with Windows` starts it only at the next sign-in.

  Tried by the Product Manager on Windows 11 (26H2) with a Companion built from source with the documented publish command: this procedure with `Exit` first and the *Run* dialog, which works. Not reported separately: the exact quoting and path details of the line, and a replay started while the tray Companion still runs.
- **Invalid command line:** an unknown argument, `--speed` without `--replay`, a speed outside the range, `--replay` without a file, `--record` together with `--replay`, `--server` or `--token-file` in a combination *Sending a recording to a server* does not allow show `Censio Companion: Invalid command line`; the Companion then neither records nor replays, and `Exit` works.

**A recording is private.** It holds the name of the player figure (which can be your real name), island names, the names of your trade routes and their folders, and economic data exactly as the game sent them. It stays in the folder on your computer, the Companion sends it only when you replay it into a server with `--server` (*Sending a recording to a server*) and never deletes it. Do not attach or post a raw recording publicly (not in an issue either); only anonymised fixtures are meant to be shared (*Anonymising a recording (contributors)*). Keep a recording until a maintainer asks how to hand it in (*Reporting problems*). Delete the files yourself when you no longer need them.

##### Anonymising a recording (contributors)

A contributor who wants to commit a recording as a test fixture anonymises it first. The tool is a console program of the repository, not part of the release or of the Companion ZIP, so it needs a checkout of the repository and the .NET SDK (as in *Build from source*). Testers who are not contributors do not need it: they keep their raw recordings and hand them in privately when a maintainer asks.

1. Stop the recording (`Stop recording` or `Exit`). A file the Companion still writes cannot be opened and gives `file not found`.
2. In the root directory of the repository run `dotnet run --project src/Censio.Anonymiser -c Release -- <recording> <output>` with the recording file and a new output file name. The output must not exist; it is never overwritten.
3. On success the tool prints `Anonymised <n> frames to <output>` and exits with code 0. The original is not changed.

What changes: every island and figure name becomes `Island <n>` or `Player <n>` (one original name always the same invented one), the amounts of every entry change (generation, consumption, income and productivity by 1 % to 20 %; maintenance and workforce amounts by 1 % to 20 % and at least 1, below 5 by exactly 1, with 1 becoming 2; delta, profit and average productivity follow), and every time moves earlier by a random offset of 30 to 365 days. Route names become `Route <n>` and route folders `Folder <n>`, and the problem, ship, lost-ship and goods amounts of trade routes change like the other amounts, except that a negative goods amount is kept; item offers (frames of the newer protocol version 3) keep their traders and items. What stays: the frame types and order, the game times, the pauses, the island and product GUIDs, the building counts, the workforce and building GUIDs, and the IDs, islands, flags and GUIDs of trade routes and item offers. A replay of the output shows the same ticks as the original.

Errors are one line on standard error, `Error: <reason>`, with exit code 1: `file not found`, `not a recording`, `unsupported version`, `invalid line <n>`, `read failed`, `frame cannot be anonymised in line <n>` (a frame the tool does not decode, a malformed trade-route or item-offer frame, a frame whose anonymised form would be longer than 1 MiB, or any frame but `Version` before a `Version 2` or `3` frame or after another version), `output file exists`, `output is the input`, `write failed` (for example a folder that does not exist) and `cancelled` (Ctrl+C). Without exactly two arguments the tool prints `Usage: Censio.Anonymiser <recording> <output>` and exits with code 2. After an error no output file is left.

Check the output before you commit it: a name or a number you know from the game must not appear in it. Do not commit or post the original recording.

#### Sending a recording to a server

To try the server without the game, the Companion sends a recording to it, through the same WebSocket and contract a live Companion uses (*Forward mode*). It needs a server of the same release as the Companion (not the image `0.2.0`, which has no ingest); a Companion and a server of different contract versions refuse each other (*Errors* below). The recording becomes a new profile `Replay <yyyy-MM-dd HH:mm:ss>` (the local time the Companion started the replay) with the regions, islands and goods of the file and, when the game of the recording sent them (pipe protocol 3), its trade routes; each run adds one more, and they stay until you delete them (*History and deleting a profile*). Tried by the Product Manager on Windows at `--speed 10` with the fixture `long-session.jsonl`: a server in Docker (image built from this state of the repository with the documented `docker build` command) and a server from source (`ws://localhost:5000/ingest`) both filled the pages (regions and islands), and a token file written by Windows PowerShell 5.1 with `>` was accepted; the steps needed no change. Not yet tried: `docker cp` for the token file, a token file saved by Notepad as UTF-16 BE, `wss://` on Windows, the Windows certificate store, a configured system proxy and a Docker server on another host.

1. **A server.** Any of three places; the address is the one you give `--server`:
   - Docker Desktop on the same PC (*Run*): `ws://localhost:8080/ingest`.
   - Docker on another host in your network, for example a NAS: `ws://<host>:8080/ingest`.
   - From source on the PC (*Build from source*), in the root folder of the checkout: `dotnet run --project src/Censio.Server -c Release --no-launch-profile -- --Censio:DataDirectory=<full path of an empty folder>`; the server is at `ws://localhost:5000/ingest`. Without the data directory the server has no token and refuses every Companion. Keep the data folder outside the checkout.
2. **A recording.** Use your own (*Recording and replay*, replayed only into your own server: a raw recording holds the figure name, island names, trade route names and your economy; a replay sends no catalog, so names and icons need a live connection of a Companion with the game installed, *The catalog and the icons*) or the fixture `long-session.jsonl`, an anonymised recording of about 30 minutes: open `https://raw.githubusercontent.com/LarsLaskowski/Censio/main/tests/Censio.Pipe.Tests/Fixtures/long-session.jsonl` in the browser and save the page as a file (`Ctrl+S`; check that the file name ends in `.jsonl`, not `.txt`). It has a pause of about 18 minutes; at `--speed 10` that is about 108 seconds and the connection stays open.
3. **The token file.** With the token required, the file holds the server's token and nothing else (a line break at its end is fine); with `Censio:Ingest:RequireToken` `false` leave `--token-file` out. Keep the file outside the source checkout, for example `C:\Users\<you>\censio-token.txt`, readable for you only, and never post it (*Reporting problems*). Make it in one of these ways:
   - Docker: copy it byte for byte with `docker cp censio:/config/ingest-token "C:\Users\<you>\censio-token.txt"` (in `cmd` or PowerShell, on the host that runs Docker; for a NAS copy it on the NAS and bring it to the PC).
   - From source: the file is `<data directory>\ingest-token` once the server has started; name it as `--token-file` or copy it.
   - By hand: read the token (`docker exec censio cat /config/ingest-token`), paste it into Notepad and save the file. Notepad's UTF-8, UTF-8 with BOM, UTF-16 LE and UTF-16 BE all work, and so does the file Windows PowerShell 5.1 writes when you redirect with `>` (UTF-16 with a byte order mark). The token must be 32 to 1,024 visible ASCII characters; surrounding white space is ignored.
4. **The command.** Close a running Companion first (`Exit`). Press the Windows key + R and enter one line with full paths (Explorer and shortcuts set the working folder, so relative paths break):

```text
"C:\Users\<you>\Censio\Censio.Companion.exe" --replay "C:\Users\<you>\long-session.jsonl" --server ws://localhost:8080/ingest --token-file "C:\Users\<you>\censio-token.txt" --speed 10
```

   `--server` takes a `ws://` or `wss://` address with a host and no user name, password or `#`; `--token-file` needs `--server`, and both need `--replay`; every other combination is an invalid command line (`Censio Companion: Invalid command line`) and nothing is sent. The token is never on the command line.
5. **What you see.** The tooltip reads `Censio Companion: Replay: Connecting to server`, then `Replay: Connected`, `Replay: Receiving` as in a replay without a server, and at the end `Censio Companion: Replay finished: <n> ticks sent, <r> refused` (`1 tick sent` for one; a refused message does not stop the replay; `<n>` counts ticks only, and a refused trade-routes message counts in `<r>`). In a browser the server's pages fill with each tick; the Companion banner shows the Companion as connected while the replay runs and not connected after it. The fixture's times lie 30 to 365 days back, so a profile with newer data stays the one the pages show: pick `Replay <time>` in the profile switch (*Web interface*). The server logs `Companion connected.` and `Companion disconnected; <a> messages accepted, <r> refused.`; the Companion's log has four lines about the replay, without token, address or name (*Data and logs*).
6. **Errors.** Each ends the replay with `Replay error: <reason>` and the problem icon until `Exit`; nothing is retried, and what the server acknowledged stays stored.

   | Reason | Meaning |
   | ------ | ------- |
   | `token file cannot be read` | The file is missing, a folder or not accessible |
   | `token file holds no valid token` | Over 64 KiB, an invalid encoding, or not 32 to 1,024 visible ASCII characters |
   | `server unreachable` | Nothing answers as a WebSocket at the address: wrong host or port, an HTTP page (the image `0.2.0`), a redirect, a TLS certificate your Windows does not trust, or no upgrade within 30 seconds |
   | `token refused` | The server's token differs or the file holds none while the server needs one |
   | `another Companion is connected` | The server has one Companion connected; close it and run again |
   | `server does not support contract version 2` | The server is of another contract version, for example a server of the release `0.3.0`, which reads version 1: use a server and a Companion of the same release |
   | `server does not answer` | No reply, or a message the server does not take, within 30 seconds |
   | `server connection lost` | The server stopped, the network failed or the server closed the connection |
   | `invalid server reply` | The server sent something a server must not send |

   A recording that cannot be opened or has an invalid header ends with its reason (*Recording and replay*) before the server is contacted, so no profile is created; an invalid or unreadable line later ends the replay after the ticks before it were sent.
7. **Warnings.** Over `ws://` the token and the data cross the network unencrypted: use `wss://` (a reverse proxy with TLS in front of the server, *Network and TLS*) wherever the path is not your own network; the Companion checks the certificate with Windows and has no way to skip it, and it never uses a configured proxy. Replay a raw recording only into your own server. Each run creates a profile that stays until you delete it (*History and deleting a profile*). Delete the token file when the testing ends and rotate the server's token if it was exposed (`SECURITY.md`).

#### Local mode

Local mode lets the Companion host the server in its own process, so the pages and the history need neither Docker nor a NAS. It is off by default. It is in `main` and in a release after `v0.4.0`, not in `v0.4.0`, and it is for **Windows 11, 64-bit** only: on Windows 10 22H2 the Companion runs as described above, but local mode is neither supported nor tried nor refused there. It needs no installed .NET, no installer, no administrator rights and no firewall permission (the server listens on the loopback addresses only). The Companion's exe is much larger than before (about 232 MB in a measured build), because it holds the server and its pages' scripts and styles; the ZIP is still one file.

**Steps.**

1. Close a running Companion (`Exit` in the tray menu).
2. Create the file `%LOCALAPPDATA%\Censio\settings.json`, or add the keys to the one you already have. It needs `"mode": "local"`, and `"localPort"` if you want another port than 5000:

```json
{
  "mode": "local",
  "localPort": 5117
}
```

3. Start `Censio.Companion.exe`. Below `Catalog: …` the menu shows the greyed line `Server: starting`, then `Server: running at http://localhost:5117/` (`5000` without `localPort`). `Open Censio`, directly above `Open diagnostics`, is greyed until then and enabled while the server runs. The tray icon does not wait for the server.
4. Choose `Open Censio`. The default browser opens `http://localhost:<port>/`; the start page shows the Companion's version. The pages show `No data yet. The pages fill once the Companion sends data.` until the game sends: the Companion sends its live data to its own server as in *Forward mode*, under the profile `Live`, and you can fill the pages from a replay as well (step 6).
5. Choose `Exit`. A running Companion ends a second start silently, so close it first. The icon disappears at once and the server stops; the process ends within 5 seconds.
6. Start `Censio.Companion.exe` with a replay and without `--server`: press the Windows key + R and enter, with full paths, `"C:\Users\<you>\Censio\Censio.Companion.exe" --replay "C:\Users\<you>\long-session.jsonl" --speed 10` (a recording: *Sending a recording to a server*, step 2). The Companion hosts the server as in step 3 and the tooltip reads `Replay: Connecting to server` until the server runs and has answered; it then sends the recording to its own server with the server's token, taken inside the process, so you need no token file and no address, and ends at `Replay finished: <n> ticks sent, <r> refused`. With `--server` the replay goes to that address as described there.
7. Choose `Open Censio` and pick the profile `Replay <time>` in the profile switch (*Web interface*): the regions, islands and goods of the recording are there. The server keeps running after the replay until `Exit`.
8. Choose `Exit` and start `Censio.Companion.exe` again: the pages show the same profiles and history, which the server keeps in its database.

**The settings.** The Companion reads the file once at start, never writes it, and a change counts after a restart. The keys are matched ignoring case, and so is the value `local`.

| Key | Value |
| --- | ----- |
| `mode` | `"local"` switches local mode on (`"forward"` switches forward mode on, *Forward mode*). A blank text counts as no `mode`. Any other text, a value that is not a text, or the key twice (also in different case) is invalid |
| `localPort` | Read only with `mode` `local`: an integer from 1 to 65535 written as digits (`5117`). `5117.0`, `5.117e3`, `"5117"`, `null`, a negative number, `0` and `65536` are invalid, and so is the key twice. Default 5000 |

**The menu line.** `Server: <state>` shows what the server does; the Companion keeps running in every state, and the game search, the pipe, the recording and the replay work as without local mode.

| Line | Meaning | What to do |
| ---- | ------- | ---------- |
| `Server: starting` | The server is starting in the background | Wait |
| `Server: running at http://localhost:<port>/` | It runs; `Open Censio` is enabled | Nothing |
| `Server: port <port> in use` | The port is taken on `127.0.0.1` or on `[::1]`: by another program, a standalone `Censio.Server` or the Companion of another signed-in Windows user. `Open Censio` stays greyed | Close the other program, or set another `localPort` and restart the Companion |
| `Server: failed` | Any other start failure, or the server stopped while the Companion ran: the data folder cannot be created or written, the database was written by a newer Censio, is not a Censio database or cannot be updated, the key ring or the token file cannot be written or read back. A port that Windows reserves for itself is expected to end here as well. Nothing in the folder is repaired or deleted, and the Companion does not restart the server | Choose `Open log folder` and read the log of the day: it names the reason (*Data and logs*). Try another `localPort`. A restart of the Companion tries again |
| `Server: settings invalid` | A value of `mode` or `localPort` is wrong (table above), or, with `"mode": "forward"`, of `serverAddress` or `serverToken`, or of `bufferHours` or `bufferMegabytes` with `forward` or `local` (*Forward mode*); the log names it. No server starts; the game folder in the same file still counts | Correct the file and restart |

A settings file that is invalid as a whole (too large, not JSON, unreadable) shows `Game: settings file invalid` as before, and no `Server:` line. With an invalid command line the server is not hosted and neither line nor entry is shown; with `--record` or `--replay` it is hosted. A replay without `--server` whose server does not start ends with `Replay error: local server not running`; nothing is retried. If `Open Censio` cannot start a browser, the log gets the warning `Could not open the browser` and nothing else changes.

**The server.** It listens on `127.0.0.1` and on `[::1]` (on `127.0.0.1` alone if IPv6 is switched off on the PC), plain HTTP, and answers only requests whose host name is `localhost`, `127.0.0.1` or `[::1]` (any port); every other host name, and a request without one, is answered `400`, so a page of another site cannot read your pages through your browser. It takes no environment variable and no configuration file. The ingest token is required, as on the Docker image; the pages need no login, and retention and the deletion of a profile's history work as there (`localhost` is a trusted host, *History and deleting a profile*). Its warnings and errors go to the Companion's log (*Data and logs*), never the token.

**The data folder** is `%LOCALAPPDATA%\Censio\Server`, fixed and private to your Windows account like the other Companion folders. The server creates it at the first start with its database `censio.db`, its data-protection key ring and its ingest token file `ingest-token`, and opens them again at every later start; the database is never kept in memory. The Companion keeps the folder when you remove it, so delete it by hand to remove your stored data or to start empty (a new token and a new database are made at the next start). Keep the folder and its copies private (*Data and logs*).

**Accepted risk.** The pages need no login (*Web interface*), and the server listens on your PC's loopback port: every program and every other signed-in Windows user of the same PC can reach the port, read every profile and delete history. Without the ingest token, which lies in your private folder `%LOCALAPPDATA%\Censio\Server`, none of them can send data. No other device of your network reaches the server. Use local mode only on a PC whose users and programs you trust.

Tried by the Product Manager on a Windows 11 x64 machine without .NET: the release ZIP with the steps above, that a loopback bind raises no firewall prompt, and a port taken by a standalone `Censio.Server` that listens on all interfaces. Not yet tried: a port that Windows reserves.

#### Forward mode

Forward mode lets the Companion send what the game reports, live, to a server that runs elsewhere, typically the Docker image on a NAS or a home server, and connect again on its own after a server restart or a network loss. It is off by default. It is in `main` and in a release after `v0.4.0`, not in `v0.4.0`, and it needs a server of the same release as the Companion (the image `0.2.0` has no ingest, and a server and a Companion of different contract versions refuse each other, *Errors* under *Sending a recording to a server*). It works wherever the Companion does, on Windows 10 22H2 and Windows 11, 64-bit.

**Steps.**

1. Close a running Companion (`Exit` in the tray menu).
2. Get the server's ingest token. For the Docker image of *Run* it is printed by `docker exec censio cat /config/ingest-token`. If the server reads its token from a file (`Censio:Ingest:TokenFile`), use the token in that file instead. If the server has the token switched off (`Censio:Ingest:RequireToken` `false`), you need none and leave `serverToken` out (*Ingest endpoint and token*).
3. Create the file `%LOCALAPPDATA%\Censio\settings.json`, or add the keys to the one you already have:

```json
{
  "mode": "forward",
  "serverAddress": "ws://nas:8080/ingest",
  "serverToken": "<the server's ingest token>"
}
```

   `serverAddress` is the address of the ingest endpoint: `ws://<host>:8080/ingest`, where `<host>` is the machine that runs Docker (a name or an IP address) and `8080` the published port, or a `wss://` address when a reverse proxy terminates TLS in front of the server (*Network and TLS*). The generated token needs no escaping in JSON; a token from `Censio:Ingest:TokenFile` may hold a `"` or a `\`, which you write as `\"` and `\\`.
4. Start `Censio.Companion.exe`. Below `Catalog: …` the menu shows the greyed line `Server: connecting`, then `Server: connected`, also while the game is not running, and below it the greyed line `Buffer: <n> waiting`. The server shows the Companion as connected with the pipe state it reports (*Web interface*).
5. Start the game with the launch argument `/pipe` and load a save (*First recording, step by step*, steps 1 and 2). Ticks, trade routes and session events now reach the server in the order the Companion reads them, and the pages show them live under the profile `Live`. With the game installed the Companion also sends its catalog first (*The catalog and the icons*), so that region and good names and good icons appear on the pages.
6. Choose `Exit` when you are done. The Companion stops at once; what still waited is in the buffer and is sent at the next start (*What is sent and what is lost*).

**The settings.** The Companion reads the file once at start, never writes it, and a change counts after a restart. The keys are matched ignoring case, and so is the value `forward`; `serverAddress` and `serverToken` are read only with `mode` `forward`, `bufferHours` and `bufferMegabytes` with `forward` and with `local`, and `localPort` is ignored in forward mode.

| Key | Value |
| --- | ----- |
| `mode` | `"forward"` switches forward mode on (`"local"` is local mode; any other text, a value that is not a text, or the key twice is invalid; a blank text counts as no `mode`) |
| `serverAddress` | Required. An absolute `ws://` or `wss://` address with a host and its path, a query allowed, without user name, password, fragment, `#`, white space or control characters. Missing, not a text or twice is invalid |
| `serverToken` | Optional. 32 to 1,024 visible ASCII characters (`!` to `~`); space, tab and line breaks around it are cut off. Not a text, too short or too long, another character or the key twice is invalid. Without it the Companion presents no token, which only a server with the token switched off accepts |
| `bufferHours` | Optional. How long unsent messages are kept: a whole number written as digits only, from 1 to 168; default 24. `24.0`, `2.4e1`, `"24"`, `null`, 0, a negative number, a larger number or the key twice is invalid |
| `bufferMegabytes` | Optional. How much unsent messages may take, counted as their written JSON with 1 MB = 1,048,576 bytes: a whole number written as digits only, from 1 to 10240; default 100. Anything else or the key twice is invalid |

A wrong value shows `Server: settings invalid` instead of the lines below, sends nothing, and the log names the problem (`Server settings invalid: <problem>`, never the value); the game folder in the same file still counts. As with an invalid local-mode setting, `Open Censio` then appears greyed, and a replay without `--server` ends with `Replay error: local server not running`.

**The menu line.** `Server: <state>` shows the connection, below `Catalog: …`. The Companion keeps trying in every state except `Server: token refused`, `Server: does not support contract version 2` and `Server: settings invalid`, with 1, 2, 4, 8 and 16 seconds between attempts and then every 30 seconds, and starts again at 1 second after a connection that stayed up for a minute. The tooltip and the icon keep showing the pipe connection.

| Line | Meaning | What to do |
| ---- | ------- | ---------- |
| `Server: connecting` | The first attempt is running | Wait |
| `Server: connected` | The server accepted the Companion | Nothing |
| `Server: unreachable, retrying` | No WebSocket at the address: a wrong host, port or path, a server that is down, a network that is not up yet (the Companion started at sign-in), or an untrusted `wss://` certificate | Nothing if the server or the network comes back; otherwise check the address and the server |
| `Server: not answering, retrying` | The server did not answer within 30 seconds | Check the server |
| `Server: connection lost, retrying` | The connection ended: a server restart, a network loss. A connection that delivers nothing is found within 60 seconds | Nothing; the Companion connects again and sends what waited |
| `Server: invalid reply, retrying` | The server sent something the Companion cannot read, or a reply larger than 65,536 bytes (only the acknowledgement of a catalog upload may be larger) | Check that the server is a Censio server of the same release |
| `Server: another Companion is connected, retrying` | The server still holds the earlier connection of this Companion, up to about a minute, or another Companion uses it (a server takes one) | Wait; close the other Companion if it stays |
| `Server: token refused` | The server does not accept `serverToken`. Not retried | Correct the token in the file and restart the Companion |
| `Server: does not support contract version 2` | The server is too old. Not retried | Run a server of the Companion's release and restart the Companion |
| `Server: settings invalid` | A value of the file is wrong (table above) | Correct the file and restart |

Any other state shows `Server: not connected`. In local mode (*Local mode*) the line keeps its own texts, and the Companion sends to its hosted server as soon as that runs.

**What is sent and what is lost.** After the server accepts the Companion it sends every tick that has at least one island, every trade-routes item, every session start and the first session end, in the order read and one message at a time, and its pipe state (also while the game is not running). It also uploads the game catalog and its icons (*The catalog and the icons*) and sends no figure name; island names, the economy, trade routes, the catalog and the icons go to the server. `--record` sends as well; a replay (`--replay`) and an invalid command line open no connection, and a replay in forward mode stays offline unless it names `--server`. While the server cannot be reached the messages wait in the buffer, one file per message in `%LOCALAPPDATA%\Censio\Buffer`, and are sent oldest first after the reconnect, before newer ones; the message that was in flight is sent again first, also after `Exit` or a restart of the PC (the log then says `Live buffer holds <n> messages from an earlier run`). The buffer holds the messages of the last `bufferHours` hours (24) and at most `bufferMegabytes` megabytes (100) of them, the newest message and the one in flight excepted. Beyond a limit the oldest are dropped and counted: the menu line reads `Buffer: <n> waiting, <d> dropped`, the log says `Live messages dropped: <d>`, and the history shows a gap, never zeros. The age is the time the Companion took the message by your PC's clock. A file that cannot be read (damaged, changed or from another version) is deleted, counted as dropped and logged as `Live buffer entries unreadable: <n>; discarded`; files of other names in the folder are left alone. If the folder cannot be written the menu line ends in `, not saved to disk` and `Live buffer cannot be written; waiting messages are kept in memory until Exit` is logged once: the messages then wait in memory, at most 64 or 16 MiB, and are lost at `Exit`. A message that still waits for its file at `Exit` is lost; a message in flight at `Exit` stays in the buffer and is sent again, and a server that already stored it acknowledges it without storing it twice. The buffer goes to the server of the start that sends it: after you change `serverAddress` the waiting messages go to the new server; delete the folder `%LOCALAPPDATA%\Censio\Buffer` first if that server should not get them. The folder stays when you remove the Companion, so delete it by hand. A message the server refuses is not sent again and the log names its kind (`Server refused a live message: <kind>`).

**The catalog and the icons.** Once the catalog is ready (the menu line `Catalog: <n> entries`, also `…, not cached` or `…, icons failed`; no game found or `Catalog: failed` means none), the Companion sends it to the server in forward mode and in local mode, so that the pages show region and good names and good icons instead of `Region <number>` and `Good <number>`. Right after the server accepts the Companion, before the waiting messages, it compares the catalog's identity (a SHA-256 of its document) with the one the server names. If the server holds no catalog, an incomplete one or another one (for example from another installation), the Companion sends the catalog and then, one at a time, the icons the server says it lacks, in the order the server lists them, and the log says `Catalog sent to the server: <i> icons sent, <r> refused` (`<i>` counts the icons the server accepted, `<r>` those it or the Companion refused). If the server already holds the same catalog (a restart, a reconnect, a new start with an unchanged game), nothing is sent and the log says `Catalog already on the server`. A catalog that becomes ready while the Companion is connected (the first extraction of a start, or one after a game update) is sent after the message in flight, unless the server holds it. A catalog whose icons could not be read is sent without icons, so the pages show names only. A fresh Docker server with an empty `/config` shows the names and icons after the first such connection of a Companion with the game installed; the open pages update without a reload. A **replay sends no catalog**: names and icons reach a server only from a live connection of a Companion with the game installed, and a replay into a server shows them only when such a connection stored them there before. The catalog and the icons never wait in the buffer (they are not counted in `Buffer: <n> waiting`), and the menu shows no text for the upload. If the server refuses the catalog the log says `Server refused the catalog: <kind>` and the Companion does not send that catalog again until the next start; `Catalog not sent: the contract writer refused it` says the Companion could not write it. If the connection fails while the catalog or an icon is on its way (no answer within 30 seconds, a lost connection), the Companion sends the waiting messages first at the next connection and then the catalog again, and after the third such failure it gives that catalog up for this run with `Catalog not sent: the connection failed 3 times during its upload`; restart the Companion or fix the server to try again. A link that cannot take the catalog within 30 seconds costs up to three reconnects this way. The catalog and the icons go over the same connection as everything else: unencrypted with `ws://`, under TLS with `wss://`.

**Trying the buffer.** (1) Outage: stop the server, play for a few minutes and watch `Buffer: <n> waiting` grow; start the server and watch it fall to `Buffer: 0 waiting` while the pages catch up. (2) Restart: during an outage choose `Exit`, start the Companion again and look for `Live buffer holds <n> messages from an earlier run` in the log; the messages are sent after `Server: connected`. (3) Age limit: set `"bufferHours": 1`, restart, stop the server for more than an hour and start it again: the older messages are dropped (`Buffer: … dropped`, `Live messages dropped: <n>`) and the charts break there. Set `"bufferMegabytes": 1` to see the size limit in a few hours of play.

**The profile `Live`.** Until a later version lets you choose a profile, everything the Companion sends goes to one profile with the name `Live`, the same after every restart and update, so its history continues. **Warning:** if you load another savegame or start another playthrough, its ticks go to `Live` as well. Islands with the same key continue and rename each other's history, and the islands of the other savegame stay listed without new values; the Companion shows no warning. Use one playthrough per server, or delete `Live`'s history between playthroughs (*History and deleting a profile*).

**The file holds a credential.** `settings.json` now holds the server's ingest token in plain text. Keep it in your private folder and do not share it, attach it to an issue or post its content; the Companion never logs the token, the address or a server name.

**Accepted risk.** Over `ws://` the Companion sends the ingest token unencrypted at every start and every retry, unattended, to whatever host answers `serverAddress`; a name without a domain (such as `nas`) may be answered by any device of the network the PC is on, so use `wss://`, or an address on a network you trust, when the PC leaves your home network. The data crosses the network unencrypted as well (*Network and TLS*).

Tried so far with the real game and a Docker server on Windows: connecting and the live pages, a server restart (`docker restart`), a start before the server is up, a wrong token, `Exit` (under 2 seconds) and local mode's live data. Not tried with the real game: the buffer on Windows. Covered by automated tests only: losing the network, the buffer and its limits, the refusals other than the token and the finding of a silent connection (measured once at 48.75 seconds against a local test endpoint).

### Build from source

To run a state of the repository that has not been released, build it from a checkout of this repository, with the commands run in its root directory. No edge builds are offered. In the other `docker run` commands of this guide, add `--pull never` and use the local name `censio` instead of `networlddev/censio:0.4.0`.

#### Build the server image

This builds the current state of the repository into a local image. It needs Docker 23 or later with BuildKit and access to `mcr.microsoft.com`. Run it in the root folder of the checkout (see [Getting Censio](../README.md#getting-censio)):

```text
docker build -f src/Censio.Server/Dockerfile -t censio .
```

The build stamps the version `0.0.0`; pass another one as a semantic version (`MAJOR.MINOR.PATCH`, optionally with pre-release and build parts), anything else fails the build with `VERSION is not a semantic version`:

```text
docker build -f src/Censio.Server/Dockerfile --build-arg VERSION=1.2.3 -t censio .
```

Start the local image. `--pull never` makes Docker refuse to start when the build failed and no local image `censio` exists, instead of pulling a foreign image of that name:

```text
docker run -d --name censio --pull never -p 8080:8080 -v censio-config:/config censio
```

Then check `http://localhost:8080/health` (`Healthy`) and `http://localhost:8080/` as above; the start page shows `Version 0.0.0`. The maintainer built and ran the image with these steps and `/health` answered `Healthy`. Not yet tried: the refusal of `--pull never` after a failed build.

#### Build the Companion

Building needs the .NET 11 SDK (version 11.0.100 or a later patch or feature band), access to `nuget.org` and the source (see [Getting Censio](../README.md#getting-censio)), on any operating system the SDK supports; only running the program needs Windows 10 22H2 or Windows 11, x64. Run the command in the root folder of the checkout. It uses the flags of the release build, except the version, and writes to the folder `publish`:

```text
dotnet publish src/Censio.Companion/Censio.Companion.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -p:DebugType=embedded -p:PublishDocumentationFile=false -p:PublishReferencesDocumentationFiles=false -o publish
```

The folder `publish` then holds only `Censio.Companion.exe`. Start it on Windows (`publish\Censio.Companion.exe`); the tray menu shows `Version 0.0.0`. The command is written to run in PowerShell 7 and Windows PowerShell 5.1. The maintainer published the Companion with this command, started it, and its tray menu showed `Version 0.0.0`; which PowerShell was used was not recorded. Not yet tried: Windows PowerShell 5.1.

## First recording, step by step

This path leads from the download to a recording file and its replay, on Windows 10 22H2 or Windows 11 (64-bit) with Anno 117 installed. Each step ends with what you see next.

1. Download `Censio-<version>-win-x64.zip` from the release page `https://github.com/LarsLaskowski/Censio/releases` (under *Assets* of the release). If the page lists no release yet, there is no ZIP: build the Companion from source (*Build the Companion*), then continue at step 3 with `publish\Censio.Companion.exe`. You see the ZIP in your downloads folder.
2. Extract the ZIP to a folder first (right-click, *Extract All…*), best one in your own profile that stays where it is, for example `%LOCALAPPDATA%\Programs\Censio`. Do not start the exe from inside the ZIP: it then runs from a temporary folder, and `Start with Windows` would register a path Windows later removes. You see the file `Censio.Companion.exe`.
3. Start `Censio.Companion.exe`. If Windows SmartScreen shows "Windows protected your PC", choose "More info", then "Run anyway". No window opens; a tray icon appears.
4. Find the icon in the notification area at the right of the taskbar. Windows may hide a new icon behind the arrow `^` next to the clock; click the arrow and drag the icon out to keep it visible. Hover over it: the tooltip reads `Censio Companion: Waiting for game`. A second start of `Censio.Companion.exe` ends at once without a message and leaves the first running.
5. Add `/pipe` to the launch arguments of the game with the Ubisoft Connect steps of *Adding `/pipe`* (every copy, also a Steam copy; for a Steam copy there is the alternative described there). Quit the game first if it runs: the argument takes effect at the next game start.
6. Start the game from the launcher and load a save. The tooltip changes from `Censio Companion: Waiting for game` to `Censio Companion: Receiving`. If it stays at `Waiting for game`, see the table of states under *Connecting to the game*.
7. Right-click the tray icon and choose `Start recording`. The tooltip ends with `(recording)` at once; no folder or file exists until the game's first data.
8. Play for a while. When a tick has closed, the tooltip gets a second line `Last tick: <time>, <n> islands`.
9. Choose `Stop recording`. The tooltip loses `(recording)`.
10. Choose `Open recordings folder`. Explorer shows `%LOCALAPPDATA%\Censio\Recordings` with a file `recording-<yyyyMMdd-HHmmss>Z.jsonl`. If you quit and restarted the game during the recording, the session spans several files (*Recording and replay*). The file is private: do not post or attach it.
11. Choose `Exit`. The icon disappears.
12. Replay the file from the Windows *Run* dialog as described under *Recording and replay* (copy both paths with "Copy as path", then `"<path of Censio.Companion.exe>" --replay "<path of the file>" --speed max`).
13. The tooltip ends at `Censio Companion: Replay finished`: the file is readable. Choose `Exit`, then start `Censio.Companion.exe` as in step 3 for normal use.

Tried by the Product Manager on Windows 11 (26H2) with Ubisoft Connect in German and a Companion built from source with the documented publish command, with the real game: step 5 (entering `/pipe` and choosing *Close*), recording and its file, the tray icon in the overflow area, the tooltips and tray states, and the replay with `Exit` and the *Run* dialog (steps 7 to 13 in general). Not yet tried: the download from the release `v0.4.0` (steps 1 and 2 as written), the SmartScreen dialog of step 3, whether `/pipe` set in Steam reaches the game through Ubisoft Connect (the labels of the Steam path and the English labels of the Ubisoft Connect path, *Close* included, were confirmed by the Product Manager), and the SmartScreen tip under *Companion*.

## First start

Server: open `http://localhost:8080/`; the start page shows the heading `Censio` and the line `Version <version>`. `curl http://localhost:8080/health` answers `Healthy`, and after a few seconds `docker ps` shows the container as `(healthy)`. The first start creates the first data-protection key, and ASP.NET Core logs the warning `No XML encryptor configured` once (see *Limits*). The server of the release `0.3.0` and later also creates the ingest token and logs `An ingest token was generated and stored in '/config/ingest-token'.` (see *Ingest endpoint and token*), and it creates its database and logs `The database '/config/censio.db' was created.` (see *Data and logs*); a later start on the same `/config` logs `The database '/config/censio.db' was opened.`

Companion: the program opens no window until you choose `Open diagnostics`, and shows a taskbar button only while that window is open. One icon appears in the notification area with the tooltip `Censio Companion: <state>` (the states are listed under *Connecting to the game* above); its menu holds the greyed-out status, last tick, game installation (`Game: …`, see *Game installation* above) and game catalog (`Catalog: …`, see *Game catalog* above), `Open diagnostics`, `Start recording` (or `Stop recording`), `Open recordings folder`, `Open log folder`, `Start with Windows` (checked while it is on), `Version <version>` (greyed out) and `Exit`, which removes the icon and ends the program within 2 seconds (in local mode within 5 seconds, and with the greyed line `Server: …` and the entry `Open Censio`, *Local mode*). The icon is a grey ring, a green circle or a red triangle by state. A second start in the same Windows session does nothing: it ends at once without a message and writes no log line, and the first keeps running. Windows SmartScreen asks once at the first start (see *Companion* above).

## Web interface

The web pages of the server of the release `0.3.0` and later (not the image `0.2.0`) sit in a frame: an app bar with the navigation button, the name `Censio`, the profile switch, the language switch and the theme switch, and a navigation on the left that lists the start page and the regions. The navigation button closes and opens the navigation; the page then takes the freed width.

- Theme: the page starts light. The theme button switches to the dark theme and back at once, without a reload.
- Language: the page shows German when your browser's language list ranks a German variant (`de`, `de-AT`, …) above English, otherwise English. The language button (a translation symbol) offers `English` and `Deutsch` and changes every text at once.
- The choices are kept in your browser in four cookies for a year: `censio-theme` (`light`, `dark`), `censio-language` (`en`, `de`), `censio-chart-range` (`hour`, `day`, `week`, `all`) and `censio-chart-axis` (`real`, `game`); they hold no personal data, and a stored language overrides the browser's list. A cookie value the server does not know is ignored and the default applies. Without cookies (blocked, a private window, cleared) the defaults apply on every visit; a switch still changes the open page.
- Pages: the navigation lists `Regions` (`/regions`) and `Trade routes` (`/trade-routes`). The region overview shows the regions of the profile with the newest data (islands, buildings, produced goods, goods in deficit); a region opens its island list, an island its goods table with production, consumption, delta (`+` or `-`, red for a deficit and green for a surplus), a trend (below), buildings and productivity, and an island's icons when the Companion has sent them. The names come from the game's catalog in your language; without a catalog a region is `Region <number>` and a good `Good <number>`. The server gets the catalog from a Companion's live connection (*The catalog and the icons*), never from a replay. Every page shows `As of <time>` (the time of its data in your browser's time zone; the line stays empty until the browser has answered, and the time is in UTC, marked `UTC`, only when the browser cannot give its time zone) and a banner while the Companion is not connected (`The Companion is not connected.`), the game is not running (`The game is not running.`) or the Companion cannot read the game's statistics. The pages update without a reload.
- Trade routes: the page `Trade routes` (`/trade-routes`, which follows the profile with the newest data, or `/profiles/<profile>/trade-routes` for the profile shown) lists the trade routes of the profile in a table with the columns `Route`, `Folder`, `Ships`, `Lost ships`, `Major problems`, `Minor problems` and `Stations` (the islands of the route's stations in order, joined by `→`). A line above it reads `<n> trade routes, <p> with problems or lost ships.`, and the routes with major problems, minor problems or lost ships come first, each such count in red (the number carries the meaning without the colour). The game sends the whole set about every two minutes; the page shows the latest set under its own `As of` time (the time that set was received, not the time of the latest tick), replaces it when a newer one arrives without a reload, keeps no history and has no `Delete history` button. A route without a name is `Unnamed route`, an empty folder `–`, a route without stations `–`, and a station whose island the profile does not name `Island <session>/<island>/<area>`. A profile that never received trade routes (a game of pipe protocol 2, or a replay of such a recording) shows `No trade routes received yet.`, an empty latest set `No trade routes in the latest data.`. The counts are shown as the game sends them. Tried by the Product Manager with the real game: a route that the game shows with a problem or a lost ship shows a count above 0 in the matching column after a replay of its recording.
- Latest data only: every figure and goods table comes from the latest tick of the profile, the one received last (its time is the one `As of` shows), except the trade routes above; no older tick is used (the charts and the trend column, below, are the only places that show the history). An island the latest tick lacks or has no values for shows `–` in every figure column of its island list (a region none of whose islands has values shows `–` in the region overview too), and its goods table is replaced by `No values for this island in the latest tick.`; nothing is shown as zero. After a savegame is loaded the game first sends a tick without values, so a recording that ends after a load, replayed with `--server`, ends with every island at `–`; the window `Open diagnostics` then keeps the same last tick, with `(no data yet)` after the game time. The figures return with the next tick that has values.
- Trend column: the goods table of an island (after `Delta`) and the island list of a region (after `Buildings`) have a column `Trend` with a small line and an arrow for each row: for a good its delta on the island, for an island its buildings, over the last 4 hours up to the latest tick (the tooltip of the column heading says so, `Last 4 hours up to the latest tick`). The window ignores the period and the time axis of the charts, and every tick is a point; only hours older than 7 days, which the server keeps as hourly means, are one point an hour (a profile not played for a week). Like the charts' lines, the line is interrupted, never drawn to zero, where a value is missing or more than 15 minutes pass between two points. The arrow compares the newest value of the line with its oldest one, each rounded as the table rounds it (the delta to two decimals, buildings to a whole number): `↑` (`Rising`), `↓` (`Falling`) or `→` (`Stable`); the arrow's name is its tooltip and what a screen reader reads, the line itself is decoration. A row with fewer than two values in the window shows `–` (a good that is new, an island the history lacks), and so does the second row of a good that an island carries twice (the first row gets the line). The cells stay empty until the trends are read, which starts after the figures show, so the figures never wait for them; a new tick updates the lines without a reload, and a change of the period or the time axis, which changes nothing here, does not read them again. When the trends cannot be read, every cell shows `–` and the line `The trends cannot be read right now. Reload the page to try again.` stands under the table. Limits: a line holds the newest 240 points at most, so a replay faster than about one tick per 75 seconds shows less than the 4 hours the heading names (the arrow then compares the oldest and newest of those 240 points); opening the island list of a region of 256 islands can take about 13 seconds to fill in its trend column, up to about 20 seconds when the server has not read that history lately, and the charts of other pages wait while it is read (the island list itself shows at once).
- Charts: a good's name in the goods table of an island opens the good's page (`/profiles/<profile>/islands/<session>/<island>/<area>/goods/<good>`) with the controls (below) and two charts, `This island` and `All islands of the region` (the sum over the region's islands that have a value), each with the lines `Production`, `Consumption` and `Delta`. The island's page shows above its goods table the chart `Overview` with the lines `Buildings`, `Produced goods` and `Goods in deficit`, counted as the island list counts them for the latest tick, and the controls under its heading. **The controls** are two groups of buttons above the charts and a line of text under them: the period `Last hour`, `Last 24 hours` (the default), `Last 7 days` and `All`, and the time axis `Real time` (the default) and `Game time`; the line names the period, for example `Last 24 hours up to the latest tick` (`All history up to the latest tick` for `All`). One choice applies to every chart of the page, is applied without a reload (each chart shows `Loading…` until its points are there, and a quick second choice replaces the first), and is kept in your browser, so the next chart page, a reload and the next day open with it; without a stored choice, in a browser without cookies and for a stored value the server does not know, the charts open on `Last 24 hours` and `Real time`. A chart shows the points from the start of the UTC hour that holds the time 1 hour, 24 hours or 7 days before the profile's latest tick up to that tick (`All`: every point of the profile), at most the newest 2,880 (a line under the chart then says `Showing the newest 2,880 of <n> points.`), and shows `No values in this period.` without any value. Hovering a point shows its time (in your browser's time zone, in UTC, marked `UTC`, when the browser cannot give it) and the values of the lines, `–` for none. A line is interrupted, never drawn to zero, where a value is missing and where more than 15 minutes pass between the end of one point and the start of the next (a pause of the game, an outage); a game that keeps sending shows no gap. The charts take the colours of the shown theme, are revealed from left to right when they are drawn (not when a browser asks for reduced motion) and again when a new tick arrives, and follow a language or theme switch at once. `Last 7 days` and `All` show one point per hour that holds a tick, the mean over that hour's ticks (the tooltip says `Hourly average`); a new tick changes only the newest hour. A week of a large region (hundreds of islands) can take about two minutes to read when the server has not read it lately, while `Loading…` shows and the other charts wait. Times follow your browser's time zone at the latest tick, so on `Last 7 days` and `All` a daylight-saving change inside the period puts the hours before it one hour off, and a zone that is no whole hour (+5:30) puts the hourly points between the labels. The labels are `HH:mm`, with the date (`MM-dd HH:mm`) when the points span more than a day, and their spacing grows with the span (10 minutes up to 365 days, at most 8 intervals). **`Game time`** places every point at its game time, so a pause of the game leaves no gap: the time axis has no labels and no vertical guide lines (only the horizontal grid lines of the value axis), and the tooltip shows the point's real time and then `Game time <h>:<mm>` (hours not limited to a day; for an hourly mean its largest); a line is interrupted only where a value is missing or more than 15 minutes of game time pass; the tick the game sends after loading a save (no island holds an entry) is left out. The game time is read as milliseconds, which a run at 1x speed confirmed; an hour of a folded week whose smallest game time is such a load tick's may join the hour before it without a break. Ticks older than 7 days are kept as hourly means: such a point is one per hour, and a pause inside an hour no longer shows on `Real time` (on `Last hour` and `Last 24 hours` too, once the hour is folded). So a recording older than 7 days that you replay with `--server` shows every pause until the server's next retention run (it runs once at start and then every hour) has folded it, then as hourly means, joined to each other and to the ticks of the latest hour (*History and deleting a profile*).
- Profile switch: it is disabled until a profile exists; then it lists up to 100 profiles by name (equal names get the start of their identity) and opens that profile's region overview; a page's address carries its profile, so a reload or a copied address shows the same profile.
- No login: anyone who reaches the server reads every stored profile, including their names (those of islands, trade routes and their folders too), and the icons under `/icons/`; restrict who reaches the port (*Network and TLS*); the same holds for deleting a profile's history (*History and deleting a profile*). Until a Companion sends data (live in forward mode, *Forward mode*, or in local mode; a replay with `--server`, or a replay into the local server, *Local mode*) every page shows `No data yet. The pages fill once the Companion sends data.`; an address that names nothing shows `Not found.`
- Not yet tried: the pages with real data from a Companion, an update reaching an open page within 2 seconds, and how a browser shows an icon that the server answers with `404`; the charts with a replayed recording of a real, not anonymised session. Tried by the Product Manager on a build of this state of the repository, with the fixture `long-session.jsonl` replayed after the server's first retention run: the charts in the light and the dark theme (their look, the reveal, the gap at the pause and the tooltip). Tried on a build of this state of the repository with the fixture `long-session.jsonl` replayed at `--speed 10` through the Companion's replay code on Linux into a server started from source (not the Windows Companion), in headless Chromium, in both themes and both languages: the period picker and the time-axis switch (each item, a click on an already selected item included, every choice shown as selected and its line of text right, no error), the `Last 7 days` and `All` views, and the tooltip on `Game time` (the real time, `Hourly average` and `Game time <h>:<mm>`, for example `Game time 486:28`). The fixture was older than 7 days, so every point was an hourly mean and the charts held three points. Tried by the Product Manager with the real game on Windows (a recording of 17:47 to 18:49 at 3x speed with a pause from 18:20 to 18:40, replayed with `--server` into a server of this state): the period picker, the time-axis switch and the stored choice (kept across a theme change, a language change and a reload), and the pause, which leaves a gap on `Real time` and none on `Game time`. The tooltip's game time (the total play time of the savegame in hours and minutes) went from 492:27 at 17:47 to 493:51 at 18:46, 1:24 over one real hour with a 20-minute pause, where the Product Manager counted one hour of game time; a unit other than milliseconds would be off by a factor of 60 or more, so milliseconds is likely, but the 24 minutes of difference were not explained (the speed was probably not steady), and a second run settled the unit: at 1x speed without a pause the tooltip's game time went from 494:12 at 19:25 to 494:32 at 19:45, 20:00 minutes over 20:00 minutes of real time, so game time is milliseconds. It is not the play time the game shows for a savegame (299:51:18 at 19:24 and 301:12:42 at 19:46, about 3.7 times as fast), which is another counter. A replay younger than 7 days, in a server that had not folded it yet, showed single ticks whose tooltip had the time, `Game time <h>:<mm>` (for example `Game time 494:20`) and the values and no `Hourly average`, on `Real time` as well as on `Game time` (the game-time line only on `Game time`).
- The pages load everything from the server itself, no fonts or scripts from other sites. Desktop browsers only; the layout for phones comes later.
- Not yet tried: the keyboard focus rings and the contrast in a real browser, and the choice after a browser restart; the look of the trend column's lines and arrows in a real browser, in both themes and both languages.

## History and deleting a profile

The server of the release `0.4.0` and of later releases keeps the history of every profile in its database and can delete it.

- Retention: a tick is kept as the server received it for 7 days. Once a whole UTC hour lies 7 days or more in the past, the server folds the ticks of that hour, one tick at a time, into one hourly point of the profile (per island and good the sums and counts of its values, so that means can be shown later) and removes them; the hourly points are kept without limit. The hour of a profile's latest tick is never folded, so a profile you have not played for a week still shows its latest tick. A replay keeps the times of the recording, so the ticks of an old recording are folded at the next run, except those of its last hour; the charts then show them as hourly means (*Web interface*). The job starts after the server listens, runs once at start and then every hour, and works while the server serves: a Companion's data is still stored at once (it waits for at most one step, at most about 4 seconds even for the largest tick the contract allows). A run that folded writes `History reduced to hourly averages: <h> hours from <t> ticks.` to the log; a failed step changes nothing and writes `The history could not be reduced; the next run tries again.`
- Size: the database file never shrinks, the space that folding and deleting free is reused by new data. A folded hour of the repository's fixture recording (about 680 goods) takes about 5 % of the space of its ticks, 137 KB, which is about 1.2 GB a year of continuous play; the server also keeps the identity of every folded tick without end, about 108 bytes a tick (about 28 MB a year at one tick every two minutes) ([`docs/areas/history.md`](areas/history.md), *Measurements*).
- Deleting: the region overview of a profile (`/profiles/<profile>/regions`, reached from the profile switch) has the button `Delete history`. It opens the dialog `Delete history?` with the text `All data of the profile <name> is removed from the server: its regions, islands, goods, trade routes and history. This cannot be undone.`; `Cancel` closes it, `Delete` removes the profile with everything the server holds of it, without a backup. The catalog, the icons and the other profiles stay. Afterwards the page goes to `/regions`, the profile leaves the profile switch, and a page that shows it shows `Not found.`. If the deletion fails the dialog stays open and says `The history could not be deleted.`; nothing was changed. `/regions`, which follows the newest profile, has no button. A Companion that still sends under the deleted profile creates it again, without a name until its next hello.
- Who may delete: there is no login, so the button works only on a page you opened by IP address (for example `http://192.168.1.10:8080/`), as `localhost` or by a host name that the setting `AllowedHosts` lists (environment variable `ALLOWEDHOSTS`, names separated by `;`, `*.example.com` for a domain; for example `-e ALLOWEDHOSTS="nas;censio.example.com;127.0.0.1"`). On any other page the button is disabled and says `Deleting needs this page opened by IP address or as localhost, or by a host name the setting AllowedHosts lists.` This keeps a page of another site (DNS rebinding) from deleting. Anyone who reaches the server by its address can still delete every profile's history, so restrict who reaches the port (*Network and TLS*). Listing names in `AllowedHosts` also turns on ASP.NET Core's host filtering for every request: a request for another host answers `400`, so list every name and address the server is reached by (`127.0.0.1` for the image's health check, the name in the Companion's `--server`), `[::1]` for IPv6 loopback. Unset, `AllowedHosts` is `*` and filters nothing.
- Behind a reverse proxy the server sees the host the proxy sends. nginx sends its own address (`$proxy_host`) unless told otherwise, which makes every page it serves trusted, the pages of another site included. So pass the client's host (`proxy_set_header Host $host;`) and let the proxy answer only its own names, which you list in `AllowedHosts`.
- Clean-up: after the profile is gone the server removes its rows step by step and then clears them from the database file (SQLite overwrites what it deletes, and the write-ahead log is truncated). It logs `The history of a profile was deleted.` when the profile is gone and `The deleted history was cleared from the database file.` when no name that only that profile held is left in `censio.db` or the files beside it; a failed deletion logs `The history of a profile could not be deleted.` (nothing was changed). A read that holds the log can delay the clean-up: the server then logs `The deleted history could not yet be cleared from the database file; the next retention run tries again.` and tries again within the hour. No line names a profile.
- Older copies of names: a server of the release `0.3.0` did not overwrite deleted data, so copies of names it changed may remain in the free space of a file it filled, and the clean-up does not reach them. To remove them stop the server (`docker stop censio`), keep a copy of the file, run `sqlite3 censio.db "VACUUM;"` on it (it needs as much free space again as the file and rewrites the whole file) and start the server.
- Not yet tried: the button on real hardware with a reverse proxy and `AllowedHosts`, and the clean-up and `VACUUM` on a database that an earlier server filled.

## Data and logs

Server: the data directory is `/config` in the Docker image. It holds the data-protection key ring in `/config/data-protection-keys` and, while `CENSIO__INGEST__TOKENFILE` is unset, the ingest token in `/config/ingest-token`; the keys and the token are unencrypted, so keep the directory and its backups private. The server logs no token. The server of the release `0.3.0` and later also keeps its SQLite database there, `/config/censio.db` (the setting `CENSIO__DATABASE__FILE` names another absolute path; without it and without a data directory the database is kept in memory and lost when the server stops). It holds profile, island, trade route and folder names, which are private: the server creates the file, the files SQLite keeps beside it while it runs (`censio.db-wal`, `censio.db-shm`) and a folder it creates readable by its owner only (mode `0600` and `0700` on Linux), and logs the path of the file and never a name or a value. The server stores every profile, tick, trade-routes message, catalog and icon it receives before it acknowledges it, and the file grows with every tick (about 77 KB for a real tick, about 55 MB a day at one tick every two minutes) until the server folds ticks that are 7 days old into hourly values (*History and deleting a profile*). At start, before it listens, it restores the last state of each profile from the file and logs `Profiles restored from the database: <n>.` (`<n>` is the number of stored profiles, `0` for the in-memory database); if the state cannot be read it stops with exit code 1 and the line `The current state cannot be read from the database '<file>'; the server stops.` A message it cannot store is not acknowledged: the server closes the connection and logs `A message could not be stored; the connection is closed.` with the exception, and the Companion reconnects and sends the message again; `The current state of a profile cannot be read from the database.` and `A follower of the current state failed.` are the other lines it writes about the state, and none of them names a profile or an island. The data pages show it (*Web interface*). A backup is a copy of `censio.db` taken while the server is stopped (`docker stop censio`, then copy from the volume or the mounted folder); a restored copy must be readable by the server's user only (`chmod 600 censio.db` on Linux, as the files SQLite keeps beside it take its mode) and the file belongs on a local disk. A newer server brings an older database to its schema at start and keeps its data, and an older server refuses a newer database (`The database '<file>' was written by a newer Censio version; the server stops. Start that version or a newer one.`); the other start failures are `The database '<file>' cannot be opened or written; the server stops. Make its folder writable for the user the server runs as.`, `The file '<file>' is not a readable Censio database; the server stops.` and `The database '<file>' cannot be updated to the current schema; the server stops.`, each with exit code 1 before the server listens and with the file left unchanged. Tried on Docker Engine on Linux with an image built from a checkout: the created line on the first start, the opened line on a second container on the same volume, and mode `600` for the file and for `-wal` and `-shm` while the server ran. Not yet tried: NAS hardware, a restored backup, and the other start failures in a container. The server writes its log to the console; read it with `docker logs censio`. Log times are UTC. The settings are listed in the [README](../README.md#configuration).

Companion: it stores game data in the catalog cache `%LOCALAPPDATA%\Censio\Cache\catalog.bin` (the names and icons of your game, saved after a complete extraction, the file never sent, and kept when you remove the Companion, so delete the folder by hand; it holds temporary files only for the moment of a save, and the Companion deletes leftovers older than a day) and, only in local mode, in the local server's data folder `%LOCALAPPDATA%\Censio\Server` (the database `censio.db` with the profiles, island and trade route names it received, the key ring and the ingest token, private to your Windows account and kept when you remove the Companion, so delete the folder by hand; *Local mode*), and, only where live data is sent, the live buffer in `%LOCALAPPDATA%\Censio\Buffer` (the messages waiting for the server, as sent: island names, the economy and trade routes, never the token; private to your Windows account and kept when you remove the Companion, so delete the folder by hand; *Forward mode*), and the diagnostics window stores nothing (it shows the last tick on screen only and writes nothing to disk or to the log). It writes recording files to `%LOCALAPPDATA%\Censio\Recordings` only while a recording runs (`--record` or `Start recording`); they hold the data of your game as it was sent, stay on your computer and are never deleted by the program, so delete them by hand (*Recording and replay*). It also writes a log to `%LOCALAPPDATA%\Censio\Logs`: one file per day, `companion-<yyyyMMdd>.log` (a file that grows past 10 MiB continues in `companion-<yyyyMMdd>-2.log` and so on). The Companion keeps the 10 newest of these files and deletes older ones; it deletes no other file in the folder. The menu entries `Open recordings folder` and `Open log folder` open both folders in Explorer. Only when you turn `Start with Windows` on does it write one value `Censio Companion` under `HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run` (your account only), and it deletes that value when you turn it off; the log then holds `Autostart enabled` or `Autostart disabled`, and a warning if the setting could not be read or changed (no file path). A line holds the local time, the level and the message: the start, every change of the connection state, recording started and stopped, the names of recording files, replay start and end, the result of the game installation search (the source, the build and the game folder, or the reason it failed; see *Game installation*), the result of the catalog (entry count, or the failure kind), whether the cache was used, loaded or written, the durations of an extraction or a cache load, the counts of its icons and the GUIDs it cannot name (see *Game catalog*), and problems. The log holds no game data, no game name and no icon, but the game folder at every start and an error text can contain a file path, and so your Windows user name; check a log before you share it. In local mode the log also holds the lines `Local server running on port <port>`, `Local server port <port> in use`, `Local server failed` and `Local server stopped unexpectedly`, `Could not open the browser`, and the warnings and errors of the hosted server (not its other lines and never the token). In local mode and in forward mode a wrong setting is logged as `Server settings invalid: <problem>`, and live sending writes `Live sending connected to the server` at each accepted connection, `Live sending failed: <reason>; retrying` when the reason of a failure changes, `Live sending refused by the server: <reason>; not retried` for a refused token or contract version, `Server refused a live message: <kind>`, `Live message not sent: the contract writer refused it` and `Live messages dropped: <n>`, `Live buffer holds <n> messages from an earlier run`, `Live buffer cannot be written; waiting messages are kept in memory until Exit` and `Live buffer entries unreadable: <n>; discarded`, and for the catalog `Catalog sent to the server: <i> icons sent, <r> refused`, `Catalog already on the server`, `Server refused the catalog: <kind>`, `Catalog not sent: the contract writer refused it` and `Catalog not sent: the connection failed 3 times during its upload`, never the token, the address, a name, a path, a message's content or an exception text (*Forward mode*). The Companion also reads, but never writes, the optional settings file `%LOCALAPPDATA%\Censio\settings.json` (the game folder, in local mode `mode` and `localPort`, in forward mode `mode`, `serverAddress` and `serverToken`, and `bufferHours` and `bufferMegabytes` in both, so the file may hold your ingest token: do not share it) and Ubisoft Connect's install records in the registry.

## Reporting problems

Open a GitHub issue with the [Bug report](../.github/ISSUE_TEMPLATE/bug_report.md) template on `https://github.com/LarsLaskowski/Censio/issues/new/choose`. Include:

- the version: the start page (`Version <version>`) or the Companion's tray menu;
- how you run it: your `docker run` command (without secrets and private paths) or how you started the Companion, and your host operating system;
- the log: an excerpt of `docker logs censio` (redact tokens and other secrets); for the Companion, the log file of the day in `%LOCALAPPDATA%\Censio\Logs` (the tray menu entry `Open log folder` opens the folder). **Check the log for your Windows user name before you share it:** an error text can contain a file path such as `C:\Users\<your name>\...`, so replace the name or cut the line out. Never attach a raw recording (`--record`) to an issue or post it publicly, it holds private names and game data; describe the problem and the tooltip instead, and keep the file until a maintainer asks how to hand it in. A screenshot of the diagnostics window shows the island names of your savegame as well: hide them, or describe the problem instead, before you attach it. Never attach the catalog cache (`%LOCALAPPDATA%\Censio\Cache\catalog.bin`), it holds the names and icons of your game.

Report a security vulnerability privately as [SECURITY.md](../SECURITY.md) describes, never in a public issue.

# Censio-Benutzerhandbuch

Censio liest die Statistik eines laufenden Anno-117-Spiels unter Windows und zeigt sie live und im Verlauf in einer Webanwendung: Ein Windows-Companion extrahiert die Daten, eine Blazor-Server-Anwendung speichert und zeigt sie an. Status und Schnellstart stehen in der [README](../README.md#censio-deutsch).

English version: [Censio user guide](#censio-user-guide)

## Installation

### Server (Docker)

Der Censio-Server läuft als Docker-Image `networlddev/censio` (linux/amd64) auf Docker Hub. Jedes Release veröffentlicht den Tag `<version>` (zum Beispiel `0.4.0`) und setzt den Tag `latest` auf das neueste Release. Die Versionen stehen auf der Release-Seite `https://github.com/LarsLaskowski/Censio/releases`, die Tags auf `https://hub.docker.com/r/networlddev/censio/tags`. Voraussetzung ist Docker 23 oder neuer (Docker Engine unter Linux oder Docker Desktop für Windows mit WSL-2-Backend und Linux-Containern). Die Befehle unten verwenden die Version `0.4.0`; sie durch die gewünschte Version oder durch `latest` ersetzen. Die Befehle werden einzeln ausgeführt: Schlägt ein Befehl fehl, schlägt auch der nächste fehl. Noch nicht ausprobiert: das Laden und Starten des veröffentlichten Images `0.3.0`.

#### Image laden

```text
docker pull networlddev/censio:0.4.0
```

`docker run` lädt ein fehlendes Image selbst, dieser Schritt holt es nur vorab. Ein fehlgeschlagener Pull hinterlässt nichts Halbfertiges.

#### Starten

Den Container mit einem benannten Volume für das Datenverzeichnis `/config` starten:

```text
docker run -d --name censio -p 8080:8080 -v censio-config:/config networlddev/censio:0.4.0
```

Prüfen, ob er antwortet (die Antwort lautet `Healthy`; noch nicht ausprobiert: in Windows PowerShell 5.1 ist `curl` ein Alias für `Invoke-WebRequest`, das `StatusCode` `200` und `Content` `Healthy` anzeigen sollte und vorher eine Bestätigung verlangen kann), und sein Log lesen:

```text
curl http://localhost:8080/health
```

```text
docker logs censio
```

Die Startseite liegt unter `http://localhost:8080/`. Nach wenigen Sekunden zeigt `docker ps` den Container als `(healthy)`: Das Image fragt `/health` selbst alle 10 Sekunden ab. Ist ein Start fehlgeschlagen, den Container vor einem neuen Start entfernen, weil sein Name belegt ist:

```text
docker rm -f censio
```

#### Port

Im Container lauscht der Server auf Port 8080. Ist Port 8080 auf dem Host belegt, meldet Docker „port is already allocated“; dann einen anderen Host-Port abbilden:

```text
docker run -d --name censio -p 9000:8080 -v censio-config:/config networlddev/censio:0.4.0
```

Den Port, auf dem der Server selbst lauscht, ändert `ASPNETCORE_HTTP_PORTS` (der Health-Check folgt dem ersten Eintrag der Liste; `ASPNETCORE_URLS` unterstützt das Image nicht):

```text
docker run -d --name censio -e ASPNETCORE_HTTP_PORTS=9090 -p 9090:9090 -v censio-config:/config networlddev/censio:0.4.0
```

#### Datenverzeichnis und NAS-Hosts

`/config` ist das Verzeichnis für die Daten des Servers; es enthält den Data-Protection-Schlüsselring in `/config/data-protection-keys` und, solange `CENSIO__INGEST__TOKENFILE` nicht gesetzt ist, das Ingest-Token in `/config/ingest-token` (*Ingest-Endpunkt und Token*); außerdem enthält es die Datenbank `/config/censio.db` (*Daten und Logs*). Das Image setzt `CENSIO__DATADIRECTORY=/config`; mit `-e CENSIO__DATADIRECTORY=<Pfad>` lässt es sich auf einen anderen absoluten Pfad setzen. Im Image abschalten lässt es sich nicht: `docker run -e` kann es nicht entfernen, und ein leerer Wert stoppt den Start. Das Image deklariert kein `VOLUME`, deshalb geben alle Befehle oben `-v` an. Ein benanntes Volume (`censio-config`) ist der Standard und unter Docker Desktop für Windows die einzige Form. Der Container startet nie als root: Er läuft als Benutzer `1654`.

Auf einem NAS, dessen Freigaben einem anderen Benutzer gehören (Unraid `nobody:users` ist `99:100`, ein Synology-Benutzer etwa `1026:100`), den Container mit diesem Benutzer und dieser Gruppe starten; den Pfad durch die eigene Freigabe ersetzen:

```text
docker run -d --name censio --user 99:100 -p 8080:8080 -v /mnt/user/appdata/censio:/config networlddev/censio:0.4.0
```

Oder das Verzeichnis dem Benutzer des Images übergeben und ohne `--user` starten:

```text
chown -R 1654:1654 /mnt/user/appdata/censio
```

```text
docker run -d --name censio -p 8080:8080 -v /mnt/user/appdata/censio:/config networlddev/censio:0.4.0
```

Die Datenbankdatei liegt auf dem Datenträger, auf den SQLite sie schreibt, und das Dateisperren von SQLite ist auf Netzwerkdateisystemen unzuverlässig: auf einem NAS `/config` auf einem lokalen Datenträger halten (ein Volume oder eine Freigabe des NAS selbst, die Docker lokal einhängt), nicht auf einer Freigabe, die das NAS von einem anderen Rechner einhängt. Ein Verzeichnis, das der Container-Benutzer nicht beschreiben kann, stoppt den Container beim Start mit Exit-Code 1; `docker logs censio` zeigt dann `The data-protection key ring cannot be stored in '/config/data-protection-keys'; the server stops. Make the data directory writable for the user the server runs as.` Ein Wert von `CENSIO__DATADIRECTORY`, der kein absoluter Pfad ist, stoppt ihn ebenfalls mit Exit-Code 1; `docker logs censio` zeigt dann `The data directory (Censio:DataDirectory) must be an absolute path, not '<value>'; the server stops.` Das Image auf dem NAS selbst laden; `docker run` tut das, wenn das Image fehlt:

```text
docker pull networlddev/censio:0.4.0
```

Das Bauen des Images aus dem Quellcode und sein Start mit den Befehlen dieser Anleitung wurde unter Docker Desktop für Windows in PowerShell 7 ausprobiert. Eine automatische Prüfung unter Docker Engine für Linux führt den Befehl mit `--user 99:100` und einem Bind-Mount aus, der `99:100` gehört; Windows PowerShell 5.1, die übrigen Befehle dieses Abschnitts (die `chown`-Abhilfe, das Laden auf dem NAS), der Stopp beim Start für ein nicht beschreibbares Verzeichnis auf NAS-Hardware sowie Unraid- oder Synology-Hardware wurden noch nicht ausprobiert.

#### Neu erstellen und aktualisieren

Den Container neu erstellen, um eine Einstellung zu ändern oder auf ein neueres Image zu wechseln: Die Daten liegen im Volume, nicht im Container. Auf eine neuere Version wird aktualisiert, indem zuerst ihr Tag geladen wird (`0.2.1` steht hier für die gewünschte Version); `docker run` verwendet ein Image desselben Tags, das schon auf dem Host liegt, deshalb lädt bei `latest` erst der Pull das neuere Image:

```text
docker pull networlddev/censio:0.2.1
```

```text
docker stop censio
```

```text
docker rm censio
```

Danach den Container mit demselben Befehl wie unter *Starten* starten, mit dem neuen Tag (und mit jedem `-e`, `-p`, `--user` und `--mount`, das vorher verwendet wurde):

```text
docker run -d --name censio -p 8080:8080 -v censio-config:/config networlddev/censio:0.2.1
```

- **Was das Volume behält.** Den Schlüsselring, das Ingest-Token und die Datenbank in `/config`. Der neue Container schreibt `The ingest token is read from '/config/ingest-token'.` und `The database '/config/censio.db' was opened.` ins Log (oder `The database '/config/censio.db' was updated to the current schema.`, wenn die neue Version das Schema geändert hat), und das Token des Companions gilt weiter.
- **Eine eigene Token-Datei.** Wurde mit `CENSIO__INGEST__TOKENFILE` gestartet, dasselbe `-e` und dasselbe `--mount` erneut angeben (*Ingest-Endpunkt und Token*); ohne sie erzeugt der Server ein neues Token in `/config`, und der Companion wird abgelehnt.
- **Ohne `-v`.** Der Server schreibt dann in den Container, und das Entfernen des Containers löscht Schlüsselring, Token und Datenbank.
- **Ein gelöschtes Volume.** Der nächste Start ist ein erster Start: Der Server erzeugt ein neues Token, das Sie lesen und erneut in die Token-Datei eines Abspielens (`--token-file`) schreiben.
- **Aktualisieren von `0.2.0`.** Dieses Image hat kein Ingest-Token und keine Datenbank, deshalb behält das Volume nur den Schlüsselring: Der neue Container schreibt die Zeilen des ersten Starts ins Log (`An ingest token was generated and stored in '/config/ingest-token'.` und `The database '/config/censio.db' was created.`). Das neue Token lesen und in die Token-Datei eines Abspielens (`--token-file`) schreiben.
- **Aktualisieren von `0.3.0`.** Das Volume behält den Schlüsselring, das Token und die Datenbank; der neue Container schreibt `The database '/config/censio.db' was updated to the current schema.` ins Log, und die Profile und Ticks, die `0.3.0` gespeichert hat, bleiben erhalten. Sie werden der Anfang des Verlaufs: Der erste Aufbewahrungslauf nach dem Start fasst jede ganze Stunde, die vor 7 Tagen oder früher geendet hat, zu einem Stundenpunkt zusammen, außer der Stunde des letzten Ticks eines Profils (*Verlauf und Löschen eines Profils*). Ein Companion von `0.3.0` und dieser Server lehnen sich ab (der Companion von `0.3.0` zeigt `server does not support contract version 1`), deshalb mit dem Companion desselben Releases abspielen. Noch nicht ausprobiert: dieses Update vom veröffentlichten Image `0.3.0`.
- **Zurückgehen.** Ein älteres Image verweigert eine Datenbank, die ein neueres geschrieben hat; das Zurückgehen auf ein älteres Image mit demselben Volume wird deshalb nicht unterstützt.
- **Ein Volume, das der Benutzer nicht beschreiben kann.** Ein `--user`, der `/config` nicht beschreiben kann, beendet den Start mit Exit-Code 1; siehe *Datenverzeichnis und NAS-Hosts*.

Die Befehle werden einzeln ausgeführt. Schlägt `docker pull` fehl, hier aufhören: Es wurde nichts entfernt. Schlägt `docker run` mit dem neuen Tag nach `docker rm` fehl, ihn mit dem alten Tag ausführen: Das Volume ist unberührt, und der alte Server startet wieder. Ausprobiert mit Docker Engine unter Linux und einem aus einem Checkout gebauten Image: Stoppen, Entfernen und Starten auf einem Volume, danach mit demselben Token und der geöffneten Datenbank. Noch nicht ausprobiert: das Laden eines neueren veröffentlichten Tags, ein Update von einem veröffentlichten Tag und NAS-Hardware.

#### Netzwerk und TLS

Im Image lauscht der Server auf allen Schnittstellen des Containers, über reines HTTP und ohne Login für Startseite und `/health`. Die `-p`-Abbildung entscheidet, wer ihn erreicht: `-p 8080:8080` veröffentlicht ihn auf jeder Schnittstelle des Hosts. Um ihn nur vom Host aus erreichbar zu machen, die Abbildung an die Loopback-Adresse binden:

```text
docker run -d --name censio -p 127.0.0.1:8080:8080 -v censio-config:/config networlddev/censio:0.4.0
```

Unter Linux umgeht ein veröffentlichter Port Host-Firewalls wie ufw und firewalld; den Zugriff deshalb über die Abbildung beschränken, nicht über die Firewall. TLS ist Aufgabe eines Reverse Proxys vor dem Server; siehe [SECURITY.md](../SECURITY.md).

#### Ingest-Endpunkt und Token

Der Server des Releases `0.3.0` und späterer Releases (nicht das Image `0.2.0`) nimmt die Daten eines Companions auf dem WebSocket-Endpunkt `ws://<Host>:8080/ingest` entgegen; `<Host>` ist der Rechner, auf dem Docker läuft, und `8080` der veröffentlichte Port; TLS gibt es dort nicht (*Netzwerk und TLS*). Ein Companion sendet Daten, wenn er eine Aufzeichnung mit `--server` abspielt (*Eine Aufzeichnung an einen Server senden*); im Weiterleitungsmodus sendet er auch live (*Weiterleitungsmodus*). Der Server speichert, was er empfängt, bevor er es bestätigt, und stellt beim Start den letzten Stand jedes Profils wieder her (*Daten und Logs*), aber die Seiten zeigen erst Daten, wenn ein Companion sie sendet (*Weboberfläche*). Ausprobiert mit dem Server, der außerhalb von Docker unter Linux gestartet wurde: das Anlegen der Token-Datei mit Modus `0600`, ihr Lesen beim nächsten Start und die Ablehnungen unten. Im Container ausprobiert (Docker Engine unter Linux, ein aus einem Checkout gebautes Image, eine automatische Prüfung): auf einem neuen Volume die Token-Datei mit Modus `0600` und dem Container-Benutzer als Eigentümer sowie dasselbe Token nach dem Neuerstellen des Containers auf diesem Volume. Noch nicht ausprobiert: die anderen Befehle dieses Abschnitts in einem Container, NAS-Hardware, das Lesen der Datei über eine NAS-Freigabe und ein Update von einem veröffentlichten Tag.

- **Das Token.** Es wird standardmäßig verlangt. Beim ersten Start erzeugt der Server ein Token aus 43 Zeichen und speichert es in `/config/ingest-token`; das Log zeigt `An ingest token was generated and stored in '/config/ingest-token'.` Bei jedem späteren Start liest er dieselbe Datei (`The ingest token is read from '/config/ingest-token'.`). Das Log enthält das Token nie.
- **Lesen.** Die Datei hat den Modus `0600` und gehört dem Container-Benutzer (`1654` oder dem `--user` des NAS-Abschnitts oben); eine NAS-Freigabe oder ein Dateibrowser, die als ein anderer Benutzer laufen, können sie deshalb nicht lesen. Im Container lesen oder als root auf dem Host in dem Ordner, den Sie als `/config` eingebunden haben:

```text
docker exec censio cat /config/ingest-token
```

  Die Datei hat am Ende keinen Zeilenumbruch. Das Token in die Datei schreiben, die `--token-file` eines Abspielens nennt (*Eine Aufzeichnung an einen Server senden*), und privat halten: nie in einem Issue posten (*Probleme melden*). Läuft der Server unter Windows ohne Docker, übernimmt die Datei die Zugriffsregeln ihres Ordners statt des Modus `0600`.
- **Erneuern.** (Erzeugtes Token.) Die Datei löschen und den Server neu starten; er erzeugt ein neues Token, und ein Companion, der noch das alte vorlegt, wird abgelehnt (`Companion refused: token refused.`). Der Server liest die Datei nur beim Start, deshalb kann sie gelöscht werden, während der Container läuft oder nachdem er gestoppt wurde (stoppen, löschen, starten): im laufenden Container, und ihn danach neu starten, oder als root auf dem Host im eingebundenen Ordner. Danach das neue Token lesen und in die Token-Datei eines Abspielens (`--token-file`) schreiben. Noch nicht ausprobiert:

```text
docker exec censio rm /config/ingest-token
```

```text
docker restart censio
```

- **Ein eigenes Token aus einer Datei.** Statt des erzeugten Tokens können Sie dem Server eine Datei mit Ihrem Token geben, zum Beispiel eine, die ein eigener Secret-Speicher liefert. Die Einstellung `Censio:Ingest:TokenFile` (`CENSIO__INGEST__TOKENFILE`) ist standardmäßig nicht gesetzt; auf den absoluten Pfad einer Datei im Container gesetzt, liest der Server das Token beim Start aus dieser Datei und ignoriert `/config/ingest-token` (er liest, erzeugt und ändert es nicht). Die Datei enthält das Token (32 bis 1.024 sichtbare ASCII-Zeichen; ein Zeilenumbruch am Ende wird akzeptiert); eines erzeugt `openssl rand -base64 32`. Die Datei nur für den Container-Benutzer lesbar machen, zum Beispiel mit `sudo chown 1654:1654 <Host-Datei> && sudo chmod 0400 <Host-Datei>` (stattdessen die ID des `--user` verwenden, falls Sie einen gesetzt haben); nicht für alle lesbar machen. Der `docker run`-Befehl verwendet das aus einem Checkout gebaute Image (*Aus dem Quellcode bauen*, deshalb `--pull never`) und bindet die Host-Datei mit `--mount` schreibgeschützt ein; `--mount` verweigert den Start, wenn die Host-Datei fehlt (`-v` legt dort ein Verzeichnis an):

```text
openssl rand -base64 32 | sudo tee /srv/censio/ingest-token > /dev/null
sudo chown 1654:1654 /srv/censio/ingest-token && sudo chmod 0400 /srv/censio/ingest-token
docker run -d --name censio --pull never -p 8080:8080 -v censio-config:/config --mount type=bind,source=/srv/censio/ingest-token,target=/run/secrets/censio-ingest-token,readonly -e CENSIO__INGEST__TOKENFILE=/run/secrets/censio-ingest-token censio
```

  Das Log zeigt dann `The ingest token is read from the file named by Censio:Ingest:TokenFile.` und nie den Pfad oder das Token. Zum Erneuern die Host-Datei ändern und den Container neu starten (`docker restart censio`); der Server liest die Datei nur beim Start. Die Einstellung lässt sich nicht mit `CENSIO__INGEST__REQUIRETOKEN=false` kombinieren. Ausprobiert mit Docker Engine 29.9.2 unter Linux und einem aus einem Checkout gebauten Image, die Host-Datei mit Eigentümer `1654:1654` und Modus `0400`: Der Container wurde `healthy`, das Log zeigte die Zeile oben, `/config` enthielt nur `data-protection-keys` und kein `ingest-token`, und `/health` antwortete mit `Healthy`. Bei entfernter Host-Datei scheiterte `docker run` mit `--mount` mit `invalid mount config for type "bind": bind source path does not exist` (Exit-Code 125) und legte auf dem Host nichts an; mit `-v` legte Docker stattdessen ein Verzeichnis an diesem Pfad an, und der Container beendete sich mit Exit-Code 1 und der Zeile `The ingest token file named by Censio:Ingest:TokenFile cannot be read; the server stops.`
- **Abschalten.** Die Einstellung `Censio:Ingest:RequireToken` (`CENSIO__INGEST__REQUIRETOKEN`) ist standardmäßig `true`. Ein Start mit `-e CENSIO__INGEST__REQUIRETOKEN=false` schaltet das Token ab: Der Server liest und erzeugt die Datei dann nicht, schreibt die Warnung `The ingest token is switched off: anyone who reaches the server can send data.` ins Log und nimmt jeden Companion an. Jeder, der den Server erreicht, kann ihm dann Daten senden, und wer sich als Erster verbindet, belegt den Platz des Companions. Nur in einem Netz verwenden, in dem jedem Host vertraut wird. Jeder andere Wert als `true` oder `false` stoppt den Start, ebenso die Kombination mit `CENSIO__INGEST__TOKENFILE`.
- **Ein Companion.** Der Server nimmt einen Companion zur Zeit an; ein zweiter wird abgelehnt (`Companion refused: another Companion is connected.`), bis der erste seine Verbindung geschlossen hat oder der Server ihn als stumm erkannt hat: Er sendet alle 15 Sekunden einen Ping und schließt eine Verbindung, die innerhalb von 35 Sekunden nicht geantwortet hat, innerhalb von 60 Sekunden nach ihrem letzten Frame (gemessener schlechtester Fall 56,2 Sekunden). Eine Verbindung, deren Gegenstelle nicht mehr liest, endet 30 Sekunden, nachdem eine Antwort nicht gesendet werden kann; eine Verbindung unter etwa 37 KB/s kann die größte Antwort (die Bestätigung eines Katalog-Uploads, etwa 1,1 MB) nicht aufnehmen, ein solcher Upload wird dann immer wieder abgebrochen.
- **Einschränkungen.** Der Server zählt Verbindungen pro Client-Adresse: höchstens 4 warten gleichzeitig auf ihr Hello (eine fünfte erhält `429`), und eine Adresse, deren Hellos innerhalb von 60 Sekunden 10-mal scheitern, wird 60 Sekunden lang abgewiesen (`429`); der Server loggt Beginn und Ende einer solchen Sperre ohne die Adresse. Maßgeblich ist die Adresse, von der die Verbindung kommt; `X-Forwarded-For` wird ignoriert. Hinter einem Reverse Proxy sind alle Clients eine Adresse, ein Fehlschlag eines Clients sperrt also auch den Companion hinter demselben Proxy. Docker Engine unter Linux mit `-p 8080:8080` behält die Adresse eines Clients auf einem anderen Host, aber ein Client auf dem Docker-Host selbst (`127.0.0.1`, ein Container) erscheint als Bridge-Gateway, also als eine gemeinsame Adresse; IPv6 unter Docker wurde nicht gemessen, und Docker Desktop für Windows wurde nicht gemessen, dort können alle Clients als eine Adresse ankommen. Viele Adressen (oder IPv6-Adressen) können den echten Companion weiterhin aussperren und das Log um bis zu 16 Zeilen pro Adresse und Minute wachsen lassen; Dockers Standard-Logtreiber rotiert es nicht, deshalb ein Limit setzen, zum Beispiel `--log-opt max-size=10m --log-opt max-file=3`. Ein Companion mit dem Token, der ständig Pings oder `status`-Nachrichten sendet ohne zu lesen, behält den einen Platz, bis das Token erneuert wird. Wer den Port erreicht, mit der `-p`-Abbildung oder einem Reverse Proxy beschränken. Eine Nachricht des Companions darf höchstens 24 MiB groß sein.

Der Server stoppt beim Start mit Exit-Code 1 und einer `Critical`-Zeile in `docker logs censio`, wenn `CENSIO__INGEST__TOKENFILE` gesetzt ist und:

- es mit `CENSIO__INGEST__REQUIRETOKEN=false` kombiniert ist: `The settings Censio:Ingest:TokenFile and Censio:Ingest:RequireToken false exclude each other; the server stops.`
- sein Wert kein absoluter Pfad ist (auch die leere Zeichenkette; der Wert wird nicht protokolliert): `The setting Censio:Ingest:TokenFile must be an absolute path; the server stops.`
- die Datei nicht gelesen werden kann (fehlt, ein Verzeichnis, keine Berechtigung für den Container-Benutzer; die Zeile nennt keinen Pfad): `The ingest token file named by Censio:Ingest:TokenFile cannot be read; the server stops.`
- die Datei kein gültiges Token enthält (leer, kürzer als 32 oder länger als 1.024 Zeichen oder ein Zeichen außerhalb der sichtbaren ASCII-Zeichen, zum Beispiel ein Leerzeichen mittendrin): `The ingest token file named by Censio:Ingest:TokenFile holds no valid token (32 to 1,024 visible ASCII characters); the server stops.`

Der Server stoppt beim Start mit Exit-Code 1 und einer `Critical`-Zeile in `docker logs censio`, wenn das Token verlangt wird, die Einstellung nicht gesetzt ist und:

- die Datei nicht gelesen werden kann: `The ingest token file '/config/ingest-token' cannot be read; the server stops.` Sie für den Container-Benutzer lesbar machen oder für ein neues Token löschen.
- die Datei kein gültiges Token enthält (leer, kürzer als 32 oder länger als 1.024 Zeichen oder ein Zeichen außerhalb der sichtbaren ASCII-Zeichen, zum Beispiel ein Leerzeichen mittendrin): `The ingest token file '/config/ingest-token' holds no valid token (32 to 1,024 visible ASCII characters); the server stops.` Sie für ein neues Token löschen.
- die Datei nicht angelegt werden kann: `The ingest token file '/config/ingest-token' cannot be created; the server stops. Make the data directory writable for the user the server runs as.`

Ein Wert von `CENSIO__INGEST__REQUIRETOKEN` außer `true` oder `false` (in beliebiger Schreibweise, auch die leere Zeichenkette) stoppt ihn mit `The setting Censio:Ingest:RequireToken must be true or false; the server stops.` Ohne Datenverzeichnis (ein außerhalb des Images ohne `Censio:DataDirectory` gestarteter Server) und ohne `CENSIO__INGEST__TOKENFILE` kann das Token nicht gespeichert werden: Der Server startet, schreibt `No ingest token without a data directory (Censio:DataDirectory); every Companion is refused.` ins Log und lehnt jeden Companion ab. Die Regeln im Einzelnen stehen in [`docs/areas/ingest-token.md`](areas/ingest-token.md) (auf Englisch).

#### Einschränkungen

- Nur linux/amd64; arm64-Hosts (auch ARM-basierte Synology-Modelle) und Windows-Container werden nicht unterstützt.
- Das Image läuft mit invarianter Globalisierung und ohne Zeitzonendaten: `TZ` hat keine Wirkung, Logzeiten sind UTC.
- Die Data-Protection-Schlüssel von ASP.NET Core liegen unverschlüsselt in `/config/data-protection-keys`; das Verzeichnis und seine Sicherungen privat halten. ASP.NET Core meldet die Warnung `No XML encryptor configured`, wenn der Server den ersten Schlüssel anlegt.
- Der Server schreibt sein Log auf die Konsole; Lesen mit `docker logs censio`.

### Companion

Der Companion ist das Windows-Programm, das die Statistik des laufenden Spiels liest. `Censio-<version>-win-x64.zip` von der Release-Seite `https://github.com/LarsLaskowski/Censio/releases` herunterladen (beim Release unter *Assets*). Er braucht Windows 10 22H2 oder Windows 11, 64 Bit; er braucht kein installiertes .NET, keinen Installer und keine Administratorrechte. Anderes Windows und arm64 werden nicht unterstützt. Der lokale Modus (*Lokaler Modus* unten) ist nur für Windows 11. Noch nicht ausprobiert: das ZIP von `v0.4.0` auf einem Rechner ohne .NET.

1. Das ZIP in einen beliebigen Ordner entpacken. Es enthält eine Datei, `Censio.Companion.exe`.
2. `Censio.Companion.exe` starten. Ein Tray-Symbol erscheint; sein Menü zeigt den Status, den letzten Tick, die Spielinstallation (`Game: …`, siehe *Spielinstallation* unten), den Spielkatalog (`Catalog: …`, siehe *Spielkatalog* unten), `Open diagnostics`, `Start recording`, `Open recordings folder`, `Open log folder`, `Start with Windows`, `Version <version>` und `Exit`; im lokalen Modus zusätzlich `Server: …` unter der Katalogzeile und `Open Censio` über `Open diagnostics` (*Lokaler Modus* unten), im Weiterleitungsmodus `Server: …` unter der Katalogzeile (*Weiterleitungsmodus* unten).

#### Start mit Windows

Der Companion startet nur dann mit Windows, wenn Sie es einschalten: im Tray-Menü `Start with Windows` wählen. Ein Häkchen zeigt, dass es eingeschaltet ist; den Eintrag erneut zu wählen schaltet es aus. Das Einschalten schreibt einen Wert, `Censio Companion`, unter `HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run`: Er gilt nur für Ihr Windows-Konto, und der Eintrag braucht keine Administratorrechte (der Maintainer hat es unter Windows 11 ausprobiert: keine Administrator-Abfrage erschien). Der Wert ist der vollständige Pfad der laufenden `Censio.Companion.exe` in Anführungszeichen, ohne Argumente; der Companion startet also wie bei einem Doppelklick (er zeichnet weder auf noch spielt er ab).

- Das ZIP in einen Ordner im eigenen Profil entpacken, der an seinem Platz bleibt, zum Beispiel `%LOCALAPPDATA%\Programs\Censio`. Keinen gemeinsamen Ordner und nicht das Stammverzeichnis eines Laufwerks verwenden, in das andere Benutzer schreiben können: Wer die Datei dort ersetzen kann, führt sie bei Ihrer nächsten Anmeldung aus.
- Ein Ordnerpfad mit `%` oder mit mehr als 200 Zeichen kann nicht verwendet werden: Der Eintrag bleibt ohne Häkchen, es wird nichts geschrieben, und das Log meldet `Could not change the autostart setting`.
- Wenn Sie die Exe verschieben oder eine neue Version aus einem anderen Ordner starten, zeigt der alte Eintrag noch auf die alte Datei, und das Menü zeigt den Eintrag ohne Häkchen. Um einen solchen übrig gebliebenen Eintrag zu entfernen, starten Sie eine beliebige Kopie von `Censio.Companion.exe`, wählen `Start with Windows` (der Eintrag wird durch den Pfad dieser Kopie ersetzt) und wählen es dann erneut, um es auszuschalten; oder löschen Sie den Wert `Censio Companion` im Registrierungs-Editor am oben genannten Schlüssel. Schalten Sie den Eintrag aus, bevor Sie den Ordner löschen. Das Ausschalten des alten Programms in der Windows-Liste der Autostart-Apps löscht den Wert nicht.
- Ein Wert mit anderem Pfad oder mit Argumenten gilt als ausgeschaltet; die Wahl des Eintrags ersetzt ihn dann.
- Wenn Sie den Companion in der Windows-Liste der Autostart-Apps ausschalten (Einstellungen, Apps, Autostart), zeigt das Menü das nicht und zeigt weiter das Häkchen; schalten Sie ihn in dieser Liste wieder ein. Eine Richtlinie Ihrer Organisation, die Startprogramme sperrt, sieht der Companion ebenfalls nicht.
- Der Maintainer hat dies unter Windows 11 ausprobiert: Der Companion startete nach einem Neustart mit Windows, wenn der Eintrag eingeschaltet war, und startete nicht, wenn er ausgeschaltet war; keine Administrator-Abfrage erschien (unter einem Standardkonto); Ordner mit Leerzeichen, `&` oder `,` im Pfad funktionierten; ein zweites Windows-Konto blieb unberührt; und das Ausschalten des Eintrags entfernte ihn. Nicht ausprobiert: ob SmartScreen beim ersten automatischen Start fragt, welchen Namen die Autostart-Liste zeigt, und ein Ordnerpfad mit `%`.

#### Verbindung zum Spiel

Das Spiel legt seine Statistik-Pipe nur an, wenn es mit dem Startargument `/pipe` gestartet wird. Ohne dieses Argument kann der Companion sich nicht verbinden; das sieht genauso aus wie ein Spiel, das nicht läuft: Der Tooltip bleibt bei `Censio Companion: Waiting for game`, obwohl das Spiel läuft. Den Companion vor oder nach dem Spiel starten; er braucht keinen Neustart, wenn das Spiel beendet und erneut gestartet wird. Er liest nur aus der Pipe und schreibt nie hinein.

**`/pipe` hinzufügen.** Das Argument wirkt beim nächsten Start des Spiels: Läuft das Spiel, beenden Sie es, fügen das Argument hinzu und starten es neu.

- *Ubisoft Connect (jede Kopie des Spiels, auch eine bei Steam gekaufte, die Ubisoft Connect mitstartet):* Ubisoft Connect öffnen, *Bibliothek* wählen, bei Anno 117 auf die drei Punkte klicken (Popupmenü), *Verwalten* wählen, dann *Eigenschaften*, `/pipe` in das Feld *Startargumente hinzufügen* eintragen und *Schließen* wählen.
- *Steam (Alternative für eine Steam-Kopie):* in der *Bibliothek* mit der rechten Maustaste auf Anno 117 klicken, im Kontextmenü *Eigenschaften* wählen, dann unter *Allgemein* `/pipe` in das Feld *Startoptionen* eintragen. Bleibt der Tooltip mit dieser Option bei `Waiting for game`, erreicht das Argument das Spiel über Ubisoft Connect vielleicht nicht: `/pipe` dann wie oben in Ubisoft Connect eintragen.

Der Weg in Ubisoft Connect wurde vom Product Manager unter Windows 11 (26H2) mit deutschem Ubisoft Connect ausprobiert: *Bibliothek*, die drei Punkte beim Spiel (Popupmenü), *Verwalten*, *Eigenschaften*, Feld *Startargumente hinzufügen*, `/pipe` eingetragen, *Schließen*. Der Product Manager hat außerdem die englischen Bezeichnungen dieses Wegs in einem englischen Ubisoft Connect bestätigt: *Library*, die drei Punkte, *Manage*, *Properties*, Feld *Add launch arguments*, *Close*. Ebenso hat er die Bezeichnungen des Steam-Wegs bis zum Feld bestätigt, auf Deutsch (*Bibliothek*, Rechtsklick auf das Spiel, *Eigenschaften*, *Allgemein*, Feld *Startoptionen*) und auf Englisch (*Library*, Rechtsklick auf das Spiel, *Properties...*, *General*, Feld *Launch Options*). Noch nicht ausprobiert: ob das Argument nach dem Speichern im Spiel ankam und ob ein in Steam gesetztes `/pipe` das Spiel über Ubisoft Connect erreicht.

Mit der Maus über das Tray-Symbol fahren: Der Tooltip lautet `Censio Companion: <Zustand>`. Sobald das Spiel einen vollständigen Tick gesendet hat, zeigt eine zweite Zeile `Last tick: <Zeit>, <n> islands` (die Ankunftszeit als `HH:mm:ss`, wenn sie heute war, sonst mit Datum). Auch das Symbol zeigt den Zustand: ein grauer Ring beim Warten (`Waiting for game`, `Connected`, `Pipe busy`), ein grüner Kreis bei `Receiving`, ein rotes Dreieck bei `Protocol mismatch`, `Error` und einer ungültigen Kommandozeile. Ein Rechtsklick auf das Symbol öffnet das Menü, das denselben Status und letzten Tick zeigt.

Der Menüeintrag `Open diagnostics` öffnet ein Fenster mit dem letzten Tick: einen Kopf mit `Status:`, `Last tick:` und `Game time:` und eine Tabelle mit einer Zeile je Ware jeder Insel (Region, Insel, Gebiet, Sitzungs-ID, Name, Ware, Erzeugung, Verbrauch, Delta, perfekte Erzeugung, perfekter Verbrauch, Gebäude, Unterhalt, Einkommen, Gewinn und die beiden Produktivitätswerte). Sobald der Katalog bereit ist (*Spielkatalog* unten), zeigen die Zellen `Region` und `Good` `<englischer Name> / <deutscher Name> (<GUID>)` oder den einen vorhandenen Namen mit der GUID dahinter; wo der Katalog keinen Namen hat und bevor er bereit ist, zeigen sie die rohe Zahl (GUID), die das Spiel gesendet hat, wie es Inseln und alle anderen Werte immer tun; dieselben Zellen zeigen vor dem Text das Symbol des Spiels, wo die Spieldateien eines liefern (ein kleines Bild, *Spielkatalog* unten); Zahlen haben unter jedem Windows den Dezimalpunkt. Das Fenster folgt jedem neuen Tick, auch beim Abspielen, und behält den letzten Tick, wenn die Verbindung endet. Schließen (Schließen-Schaltfläche oder Alt+F4) lässt den Companion weiterlaufen; `Open diagnostics` öffnet es wieder mit dem letzten Tick und holt ein offenes Fenster in den Vordergrund. Solange es offen ist, hat es eine Schaltfläche in der Taskleiste.

| Tooltip | Bedeutung | Was tun |
| ------- | --------- | ------- |
| `Waiting for game` | Die Pipe existiert nicht: Das Spiel läuft nicht oder wurde nicht mit `/pipe` gestartet. Der Companion sucht weiter (die Pausen wachsen von 1 auf 10 Sekunden) | Das Spiel starten. Läuft das Spiel, zuerst prüfen, dass `/pipe` im Feld für Startargumente des Launchers gespeichert ist (*`/pipe` hinzufügen*), und das Spiel neu starten: Das Argument wirkt erst beim nächsten Start. Bleibt es bei `Waiting for game`, obwohl die Startoption von Steam gesetzt ist, `/pipe` in Ubisoft Connect eintragen |
| `Connected` | Die Pipe ist geöffnet; das Spiel hat noch keine erste Nachricht gesendet. Das Spiel sendet sie sofort, dieser Zustand ist daher kaum zu sehen | Nichts |
| `Receiving` | Das Spiel sendet Daten | Nichts |
| `Pipe busy` | Die Pipe existiert, wird aber von einem anderen Programm gehalten (zum Beispiel einem anderen Pipe-Werkzeug); das Spiel bedient nur einen Client gleichzeitig, andere Pipe-Leser also schließen. Der Companion versucht es weiter (die Pausen wachsen von 1 auf 10 Sekunden) und zeigt beim nächsten Versuch nach dem Freiwerden der Pipe `Receiving`. Er kann auch nach einem Neustart des Companions bei `Pipe busy` bleiben, solange das Spiel im Hauptmenü ist, bis ein Spiel geladen wird | Das andere Pipe-Werkzeug schließen, oder einen Spielstand laden, wenn der Companion im Hauptmenü des Spiels neu gestartet wurde |
| `Protocol mismatch` | Die Pipe spricht eine andere Protokollversion als 2 oder 3 (zum Beispiel nach einem Spiel-Update); der Companion bleibt verbunden und macht weiter, sobald Version 2 oder 3 eintrifft | Auf Version 2 oder 3 warten; verschwindet es nicht, melden (*Probleme melden*), mit der Version aus dem Tray-Menü und dem Log des Tages, ohne die Aufzeichnung |
| `Error` | Das Verbinden ist fehlgeschlagen oder die Verbindung ist abgebrochen. Beim Beenden des Spiels kann `Error` kurz vor `Waiting for game` erscheinen; das ist normal | Verschwindet es nicht, melden wie bei `Protocol mismatch` |
| ` (recording)` nach dem Zustand | Eine Aufzeichnung läuft (der Eintrag lautet `Stop recording`) | Nichts; am Ende `Stop recording` wählen |
| ` (recording failed)` nach dem Zustand | Das Schreiben der Aufzeichnung ist fehlgeschlagen (zum Beispiel weil die Platte voll oder zu langsam ist); die Aufzeichnung endete, der Companion arbeitet weiter | Speicherplatz schaffen, dann `Start recording` wählen: Es versucht es mit einer neuen Datei erneut |

Beendet man das Spiel, kehrt der Companion zu `Waiting for game` zurück und verbindet sich von selbst wieder, sobald das Spiel zurück ist; das Laden eines anderen Spielstands und der Wechsel ins Hauptmenü behalten die Verbindung. `Exit` im Tray-Menü funktioniert in jedem Zustand und beendet das Programm innerhalb von 2 Sekunden (im lokalen Modus innerhalb von 5 Sekunden, weil es seinen Server stoppt).

#### Spielinstallation

Der Companion sucht Ihre Anno-117-Installation bei jedem Start einmal im Hintergrund; das Tray-Menü und `Exit` funktionieren währenddessen. Das Ergebnis ist die ausgegraute Menüzeile `Game: …` direkt unter `Last tick:`, zum Beispiel `Game: build 26.29905.4.51797 (Ubisoft Connect)`. Der Companion liest nur: Er schreibt nichts ins Spiel, in die Registry oder in Ihre Einstellungsdatei. Das Diagnosefenster zeigt die Zeile nicht.

**Suchreihenfolge.**

1. Der in der Einstellungsdatei (unten) genannte Ordner. Ist er gesetzt, wird er verwendet, und sonst wird nichts gesucht.
2. Die Einträge von Ubisoft Connect zu installierten Spielen (der Registry-Schlüssel `HKEY_LOCAL_MACHINE\SOFTWARE\WOW6432Node\Ubisoft\Launcher\Installs`, nur lesend): Der erste gültige Eintrag nach Nummer wird verwendet; ein Eintrag, der auf einen Ordner ohne das Spiel zeigt, wird übersprungen. Ein Eintrag, der auf einen Netzwerkpfad (UNC) oder Gerätepfad zeigt, wird nie verfolgt; ein zugeordneter Laufwerksbuchstabe oder eine Ordnerverknüpfung dagegen schon.
3. Der Standard-Spieleordner von Ubisoft Connect, `C:\Program Files (x86)\Ubisoft\Ubisoft Game Launcher\games` (unter dem 32-Bit-Programmordner).

Eine Installation ist ein Ordner, der `maindata\config.rda` und `bin\win64\anno117.exe` enthält. Steam wird nicht durchsucht: Bei einer Steam-Kopie oder einem Spiel in einem anderen Ordner die Einstellungsdatei verwenden. Eine Änderung gilt nach dem nächsten Start des Companions.

**Der Build** ist die Dateiversion von `bin\win64\anno117.exe` als vier Zahlen, zum Beispiel `26.29905.4.51797`. Er ist nicht die Version, die das Hauptmenü des Spiels zeigt (`3.0.1733841` bei derselben Installation), und Ubisoft Connect zeigt keine. Noch nicht überprüft: dass sich der Build mit jedem Spiel-Update ändert.

**Die Einstellungsdatei.** `%LOCALAPPDATA%\Censio\settings.json` anlegen (den Pfad in die Adresszeile des Explorers eingeben; der Ordner `Censio` existiert, sobald der Companion einmal lief) mit Ihrem Spieleordner, zum Beispiel:

```json
{
  "gameFolder": "C:\\Games\\Anno 117"
}
```

- Einen vollständigen Pfad schreiben und jeden Backslash verdoppeln, oder Schrägstriche verwenden (`"C:/Games/Anno 117"`). Der Ordner ist der, der `maindata` und `bin` enthält, nicht `maindata` selbst. Variablen wie `%USERPROFILE%` und ein bloßer Laufwerksbuchstabe (`"C:"`) sind keine vollständigen Pfade. Einen Netzwerkpfad (`\\\\server\\share\\Anno 117`), den Sie hier schreiben, verwendet der Companion wie geschrieben, und Windows kontaktiert dann diesen Server.
- Der Schlüssel `gameFolder` wird ohne Beachtung der Groß- und Kleinschreibung gelesen (`GameFolder` funktioniert); jede andere Schreibweise, etwa `game_folder`, ist ein unbekannter Schlüssel und wird ignoriert: Die automatische Suche läuft, und das Menü zeigt dann `(Ubisoft Connect)` oder `Game: not found`, nicht `(settings file)`. Andere Schlüssel werden ignoriert. Ein leeres `gameFolder` gilt als nicht gesetzt.
- Die Datei ist UTF-8 (die Byte-Reihenfolge-Marke von Notepad ist in Ordnung), Kommentare (`//`, `/* */`) und nachgestellte Kommas sind erlaubt, und sie darf bis zu 1 MiB groß sein. Bearbeiten Sie sie bei geschlossenem Companion und starten Sie ihn danach neu.
- Ein falscher Ordner in der Datei wird nie durch einen gesuchten ersetzt, damit Sie den Fehler sehen.

**Menütexte.**

| Text | Was zu tun ist |
| ---- | -------------- |
| `Game: searching` | Warten; es endet von selbst. Ein langsames oder schlafendes Laufwerk kann dauern. |
| `Game: build <build> (Ubisoft Connect)` | Nichts; über Ubisoft Connect gefunden. |
| `Game: build <build> (settings file)` | Nichts; der Ordner Ihrer Einstellungsdatei wird verwendet. |
| `Game: build unknown (…)` | Die Installation wird verwendet, aber ihre Programmdatei hat keine lesbare Version. Nichts zu tun. |
| `Game: not found` | Weder die Einträge von Ubisoft Connect noch dessen Standardordner enthalten das Spiel (zum Beispiel eine Steam-Kopie). Den Ordner in der Einstellungsdatei nennen. |
| `Game: folder in settings not found` | Der Ordner in `gameFolder` existiert nicht. Den Pfad korrigieren (eine Variable in einem Pfad wird nicht aufgelöst und wird deshalb ebenfalls nicht gefunden). |
| `Game: folder in settings is not a full path` | Den vollständigen Pfad mit Laufwerksbuchstaben schreiben, zum Beispiel `C:\\Games\\Anno 117`. |
| `Game: folder in settings is not an Anno 117 installation` | Dem Ordner fehlt `maindata\config.rda` oder `bin\win64\anno117.exe`. Den Ordner nennen, der `maindata` und `bin` enthält. |
| `Game: settings file invalid` | Die Datei ist kein gültiges JSON oder kein Objekt, `gameFolder` ist kein Text, der Schlüssel kommt doppelt vor, die Datei ist größer als 1 MiB oder sie ist nicht lesbar. Das Log nennt den Grund. |

Das Log (`Open log folder`) nennt die Ursache jedes Problems und, wenn das Spiel gefunden wird, die Quelle, den Build und den Ordner.

#### Spielkatalog

Nach der Spielsuche lädt der Companion im Hintergrund bei jedem Start die Namen von Regionen, Waren, Arbeitskräften und Gebäuden auf Englisch und Deutsch aus seinem Cache oder, wenn keiner passt, liest sie aus Ihrer eigenen Spielinstallation (die Datei `maindata\config.rda`); das Tray-Menü, die Verbindung und `Exit` warten nicht darauf. Er liest die Dateien des Spiels nur: In die Installation wird nichts geschrieben, und die Namen bleiben auf Ihrem Rechner, außer dass ein Companion mit Live-Senden sie auf Ihren eigenen Server hochlädt (*Weiterleitungsmodus*; sie werden nicht ins Log geschrieben und sind nicht Teil eines Release). Die einzige Kopie ist die unten beschriebene Cache-Datei. Die ausgegraute Menüzeile `Catalog: …` direkt unter `Game: …` zeigt den Zustand:

| Menüzeile | Was zu tun ist |
| --------- | -------------- |
| `Catalog: reading` | Warten; es endet von selbst. Sie erscheint auch, solange die Spielsuche läuft. |
| `Catalog: checking` | Warten; der Companion vergleicht das Spiel mit dem Cache. |
| `Catalog: extracting names` | Warten; die Namen werden aus den Spieldateien gelesen. Die bisher gezeigten Namen bleiben, bis die neuen bereit sind. |
| `Catalog: extracting icons, <n> entries` | Warten; die Namen sind bereit und werden gezeigt, die Symbole folgen. |
| `Catalog: <n> entries` | Nichts; das Diagnosefenster zeigt jetzt Namen und Symbole. |
| `Catalog: <n> entries, icons failed` | Die Namen funktionieren; die Symbole ließen sich nicht lesen (siehe den Absatz zu Symbolen unten). Es wird nichts im Cache gespeichert, der nächste Start liest die Dateien also erneut. |
| `Catalog: <n> entries, not cached` | Namen und Symbole funktionieren, aber der Cache ließ sich nicht schreiben (Platte voll, kein Zugriff auf `%LOCALAPPDATA%\Censio\Cache`); die Logzeile `Catalog cache not written` nennt den Grund. Der nächste Start liest die Spieldateien erneut. |
| `Catalog: no game` | Es wurde keine Installation gefunden (siehe *Spielinstallation*); GUIDs bleiben Zahlen. |
| `Catalog: failed` | Eine Spieldatei war nicht lesbar oder hat einen unerwarteten Aufbau, zum Beispiel nach einem Spielupdate. GUIDs bleiben Zahlen; die Logzeile `Catalog failed: <Art>` nennt die Art (`ArchiveUnreadable`, `FileMissing`, `FileUnreadable` oder `MalformedFile`); melden Sie sie mit dem Spiel-Build (*Probleme melden*). |

Eine GUID, die der Katalog nicht benennen kann, bleibt im Diagnosefenster eine Zahl. Für jede solche GUID eines Ticks steht im Log, einmal je Katalog (also nach einer Extraktion wegen eines Spielupdates erneut), eine Zeile `Catalog cannot name <Region|Good|Workforce|Building> <GUID>: <Unknown|Incomplete|Nameless|Ambiguous>` (unknown: nicht in den Spieldateien; incomplete: nur eine Sprache hat einen Namen; nameless: kein Name; ambiguous: die Dateien definieren sie mehrfach), nie ein Name. Das Log nennt außerdem, wie viele Einträge gebaut wurden, und benennt ein Archiv, das eine zweite Kopie einer Datei des Katalogs enthält (`Catalog: <Archiv> also lists <Pfad>; the copy in config.rda is used`). Liegt der Spieleordner der Einstellungsdatei auf einem Netzlaufwerk in der Schreibweise `\\Server\Freigabe`, listet der Companion die Spielarchive bei jedem Start und bei jeder Prüfung über das Netzwerk und liest sie darüber, wenn er extrahiert.

Cache: Nach einer vollständigen Extraktion (Namen und Symbole) speichert der Companion sie in der Datei `%LOCALAPPDATA%\Censio\Cache\catalog.bin`, einer Datei für die zuletzt extrahierte Installation. Der nächste Start lädt sie in einem Augenblick, ohne die Archive des Spiels zu lesen, wenn der Spieleordner, der Spiel-Build sowie Name, Größe und Änderungszeit jeder `.rda`-Datei unter `maindata` dieselben sind und der Companion selbst nicht aktualisiert wurde; sonst wird der Cache nicht benutzt, die Logzeile `Catalog cache not used: missing`, `game changed` oder `Companion changed` nennt den Grund, und der Companion extrahiert erneut und ersetzt den Cache. Eine beschädigte oder fremde Datei wird nie teilweise benutzt: Die Warnung `Catalog cache not used: invalid` wird geschrieben, und der Companion extrahiert erneut. Wird das Spiel aktualisiert, während der Companion läuft, starten Sie es wie üblich mit dem Startargument `/pipe`: Bei jeder neuen Verbindung prüft der Companion das Spiel, und hat es sich geändert, zeigt `Catalog: extracting names` wieder an, während die alten Namen bleiben, und der Cache wird ersetzt; ein unverändertes Spiel bewirkt nichts. Gemessen auf der Installation des Maintainers (1.040 Einträge; Ihr Rechner weicht ab): etwa 7 s zum Extrahieren (Namen 2,5 s, Symbole 4,5 s) und etwa 2,4 s zum Laden aus dem Cache. Die Logzeilen `Catalog extracted in <t> s (names <a> s, icons <b> s)` und `Catalog loaded from cache in <t> s: …` nennen die Zeiten Ihres Rechners. Der Cache enthält die Namen und Symbole Ihres Spiels und ist deshalb privat wie eine Aufzeichnung: Die Datei selbst wird nie gesendet (das Live-Senden lädt den Katalog und die Symbole aus dem Arbeitsspeicher auf Ihren eigenen Server hoch, *Weiterleitungsmodus*), nicht ins Log geschrieben und ist nicht Teil eines Release, Sie sollten ihn nicht weitergeben, und er bleibt auf dem Rechner, wenn Sie den Companion entfernen; löschen Sie dann den Ordner `%LOCALAPPDATA%\Censio\Cache` von Hand. Blieb ein Spielupdate unbemerkt (ein Archiv mit gleichem Namen, gleicher Größe und gleicher Zeit neu geschrieben), den Companion schließen, den Ordner löschen und neu starten. Ein Spiel, das ohne `/pipe` gestartet wurde, ein Abspielen und eine ungültige Befehlszeile werden nur beim Start geprüft.

Symbole: Sobald die Namen angezeigt werden, liest der Companion auch die Symbole der Waren und Regionen aus den Bildarchiven des Spiels (`maindata\ui.rda` und die danebenliegenden Dateien `zz_patchfiles_<n>.rda`, die höchste Nummer zuerst), wandelt sie im Speicher um und zeigt jedes mit 20 mal 20 Pixeln vor dem Namen in den Zellen `Region` und `Good`; Regionssymbole stehen auf einem dunklen runden Hintergrund, weil das Spiel sie als helle Zeichen zeichnet. Liefern die Spieldateien kein Symbol oder eines, das sich nicht lesen lässt, zeigt die Zelle nur den Text, ohne Hintergrund; die Namen warten nie auf die Symbole und hängen nicht von ihnen ab. Die Symbole werden nur in der Cache-Datei oben gespeichert: Sie gehen nur durch das Live-Senden auf Ihren eigenen Server (*Weiterleitungsmodus*), werden nicht ins Log geschrieben und sind nicht Teil eines Release. Das Log enthält je Extraktion eine Zeile, `Catalog icons: <g> goods and <r> regions with an icon; without one: <a> not named, <m> missing, <u> unreadable` (Anzahl der Einträge), oder die Warnung `Catalog icons failed: <Art> (<Archiv>)` mit einer der Arten `ArchiveMissing`, `ArchiveUnreadable`, `DuplicateArchiveNumber` oder `IconSetTooLarge`; dann wird kein Symbol gezeigt, und die Namen bleiben unberührt. Nach einem Spielupdate zeigen die Zahlen, ob Symbole fehlen; melden Sie eine solche Zeile mit dem Spiel-Build (*Probleme melden*). Liegt der Spieleordner auf einem Netzlaufwerk, werden auch die Bildarchive bei jeder Extraktion über das Netzwerk gelesen.

#### Aufzeichnen und Abspielen

Für Tests und Fehlermeldungen kann der Companion aufzeichnen, was das Spiel sendet, und es später wieder abspielen. Beides kann mit einem Schalter in der Kommandozeile gestartet werden (zum Beispiel `Censio.Companion.exe --record` in einem Terminal oder im Ziel einer Verknüpfung); eine Aufzeichnung lässt sich auch im Tray-Menü starten und beenden (`Start recording`, `Stop recording`), ein Abspielen nur mit seinem Schalter. Einen laufenden Companion vorher schließen (`Exit` im Tray-Menü): Ein zweiter Start endet sofort ohne Meldung, und es wird nichts abgespielt.

- **Aufzeichnen:** `Censio.Companion.exe --record` startet mit eingeschalteter Aufzeichnung; ohne den Schalter im Tray-Menü jederzeit `Start recording` wählen, auch wenn das Spiel schon sendet. Der Companion verbindet sich wie gewohnt mit dem Spiel und schreibt jede Verbindung in eine eigene Datei in `%LOCALAPPDATA%\Censio\Recordings` (der Menüeintrag `Open recordings folder` öffnet ihn). Eine Datei `recording-<yyyyMMdd-HHmmss>Z.jsonl` (UTC-Zeit der ersten Daten; ein vergebener Name bekommt `-2`, `-3`, … vor `.jsonl`) entsteht, sobald nach dem Start die ersten Daten des Spiels eintreffen. Bis dahin endet der Tooltip schon mit `(recording)`, aber der Ordner existiert unter Umständen nicht und enthält keine Datei: Das ist kein Fehler. Wird das Spiel beendet und neu gestartet, schreibt die nächste Verbindung eine neue Datei, und jeder neue Start schreibt eine neue Datei; eine Sitzung kann also aus mehreren Dateien bestehen. Während der Aufzeichnung endet der Tooltip mit `(recording)`, und der Menüeintrag lautet `Stop recording`; `Stop recording` schreibt noch Wartendes und schließt die Datei. Schlägt das Schreiben fehl (zum Beispiel weil die Platte voll oder zu langsam ist), endet die Aufzeichnung, der Tooltip endet mit `(recording failed)`, und der Companion arbeitet weiter; `Start recording` versucht es mit einer neuen Datei erneut. `Exit` im Tray-Menü schreibt noch Wartendes, höchstens 1 Sekunde lang, und beendet das Programm. Wird der Companion beendet („abgeschossen“) oder fällt der Strom aus, können die letzten Zeilen einer Datei fehlen; ob Windows beim Abmelden oder Herunterfahren sie schreibt, ist nicht ausprobiert.
- **Abspielen:** `Censio.Companion.exe --replay <Datei> [--speed <Faktor>|max] [--server <Adresse> [--token-file <Datei>]]` liest eine Aufzeichnung aus einer lokalen Datei statt aus der Pipe des Spiels und spielt sie so ab, wie das Spiel sie gesendet hat. `--speed` ist `max` (keine Pausen) oder eine Zahl von `0.1` bis `1000`, auch unter deutschem Windows mit Dezimalpunkt geschrieben (`--speed 10` macht die Pausen auf ein Zehntel kürzer); ohne Angabe läuft das Abspielen in Echtzeit. Der Companion öffnet beim Abspielen die Pipe nicht, und die Datei wird nur gelesen. Der Tooltip, der letzte Tick, das Symbol und das Fenster `Open diagnostics` zeigen den Fortschritt, und das Fenster zeigt die abgespielten Ticks und behält den letzten Tick der Datei (`Start recording` ist beim Abspielen ausgegraut): `Replay: Connected`, dann `Replay: Receiving` (oder `Replay: Protocol mismatch`) und nach dem letzten Frame `Replay finished` bis `Exit`. Ein Problem mit der Datei erscheint als `Replay error: <Grund>` mit `file not found`, `not a recording`, `unsupported version`, `invalid line <n>` oder `read failed`. Im lokalen Modus sendet ein Abspielen ohne `--server` stattdessen in den lokalen Server (*Lokaler Modus*).

  Eine fertige Aufzeichnung prüfen, ohne Konsole:

  1. Im Tray-Menü `Exit` wählen. Läuft noch ein Companion, endet der Start des Abspielens sofort und ohne Meldung.
  2. Im Explorer den vollständigen Pfad von `Censio.Companion.exe` und der Aufzeichnungsdatei jeweils mit „Als Pfad kopieren“ kopieren (Rechtsklick; unter Windows 10 Umschalt + Rechtsklick).
  3. Windows-Taste + R drücken und im Dialog *Ausführen* die Zeile `"<Pfad der Censio.Companion.exe>" --replay "<Pfad der Datei>" --speed max` eingeben, beide Pfade samt Anführungszeichen eingefügt. Die Anführungszeichen bleiben, damit gehen auch Pfade mit Leerzeichen und ein vom Explorer bereits aufgelöstes `%LOCALAPPDATA%`.
  4. Der Tooltip zeigt `Censio Companion: Replay: Receiving` und endet bei `Censio Companion: Replay finished`. Das heißt, die Datei ist lesbar.
  5. `Exit` wählen: Das beendet das Abspielen. `Censio.Companion.exe` wie gewohnt starten, um den Companion zurückzubekommen; `Start with Windows` startet ihn erst bei der nächsten Anmeldung.

  Vom Product Manager unter Windows 11 (26H2) mit einem Companion ausprobiert, aus dem Quellcode mit dem dokumentierten Publish-Befehl gebaut: dieses Verfahren mit `Exit` zuerst und dem Dialog *Ausführen*, es funktioniert. Nicht gesondert gemeldet: die Einzelheiten der Zeile zu Anführungszeichen und Pfaden und ein Abspielen, das gestartet wird, während der Tray-Companion noch läuft.
- **Ungültige Kommandozeile:** ein unbekanntes Argument, `--speed` ohne `--replay`, eine Geschwindigkeit außerhalb des Bereichs, `--replay` ohne Datei, `--record` zusammen mit `--replay`, `--server` oder `--token-file` in einer Kombination, die *Eine Aufzeichnung an einen Server senden* nicht erlaubt, zeigen `Censio Companion: Invalid command line`; der Companion zeichnet dann weder auf noch spielt er ab, und `Exit` funktioniert.

**Eine Aufzeichnung ist privat.** Sie enthält den Namen der Spielfigur (der Ihr echter Name sein kann), Inselnamen, die Namen Ihrer Handelsrouten und ihrer Ordner und Wirtschaftsdaten genau so, wie das Spiel sie gesendet hat. Sie bleibt im Ordner auf dem eigenen Rechner, der Companion sendet sie nur, wenn Sie sie mit `--server` in einen Server abspielen (*Eine Aufzeichnung an einen Server senden*), und löscht sie nie. Eine unbearbeitete Aufzeichnung nie öffentlich anhängen oder posten (auch nicht in einem Issue); geteilt werden sollen nur anonymisierte Testdaten (*Eine Aufzeichnung anonymisieren (für Mitwirkende)*). Eine Aufzeichnung aufheben, bis ein Maintainer fragt, wie sie übergeben werden soll (*Probleme melden*). Die Dateien selbst löschen, wenn sie nicht mehr gebraucht werden.

##### Eine Aufzeichnung anonymisieren (für Mitwirkende)

Wer eine Aufzeichnung als Testdatei einchecken möchte, anonymisiert sie vorher. Das Werkzeug ist ein Konsolenprogramm des Repositorys, nicht Teil des Releases oder des Companion-ZIPs; es braucht einen Checkout des Repositorys und das .NET SDK (wie in *Aus dem Quellcode bauen*). Tester, die nicht mitwirken, brauchen es nicht: Sie behalten ihre unbearbeiteten Aufzeichnungen und geben sie privat weiter, wenn ein Maintainer fragt.

1. Die Aufzeichnung beenden (`Stop recording` oder `Exit`). Eine Datei, die der Companion noch schreibt, lässt sich nicht öffnen und ergibt `file not found`.
2. Im Hauptverzeichnis des Repositorys `dotnet run --project src/Censio.Anonymiser -c Release -- <Aufzeichnung> <Ausgabe>` mit der Aufzeichnungsdatei und einem neuen Namen für die Ausgabedatei ausführen. Die Ausgabe darf nicht existieren; sie wird nie überschrieben.
3. Bei Erfolg gibt das Werkzeug `Anonymised <n> frames to <Ausgabe>` aus und endet mit Code 0. Das Original bleibt unverändert.

Was sich ändert: Jeder Insel- und Figurenname wird zu `Island <n>` oder `Player <n>` (derselbe Originalname immer derselbe erfundene), die Beträge jedes Eintrags ändern sich (Erzeugung, Verbrauch, Einkommen und Produktivität um 1 % bis 20 %; Unterhalt und Arbeitskräftemengen um 1 % bis 20 % und mindestens 1, unter 5 um genau 1, wobei 1 zu 2 wird; Delta, Gewinn und durchschnittliche Produktivität folgen), und jede Zeit wird um einen zufälligen Versatz von 30 bis 365 Tagen nach früher verschoben. Routennamen werden zu `Route <n>` und Routenordner zu `Folder <n>`, und die Problem-, Schiffs-, Schiffsverlust- und Warenmengen der Handelsrouten ändern sich wie die übrigen Beträge, nur eine negative Warenmenge bleibt erhalten; Angebote von Gegenständen (Frames der neueren Protokollversion 3) behalten ihre Händler und Gegenstände. Was bleibt: Frame-Typen und Reihenfolge, Spielzeiten, Pausen, die GUIDs von Inseln und Produkten, die Gebäudezahlen, die GUIDs der Arbeitskräfte und Gebäude sowie die IDs, Inseln, Flags und GUIDs von Handelsrouten und Angeboten. Ein Abspielen der Ausgabe zeigt dieselben Ticks wie das Original.

Fehler sind eine Zeile auf der Standardfehlerausgabe, `Error: <Grund>`, mit Code 1: `file not found`, `not a recording`, `unsupported version`, `invalid line <n>`, `read failed`, `frame cannot be anonymised in line <n>` (ein Frame, den das Werkzeug nicht dekodiert, ein fehlerhafter Handelsrouten- oder Angebots-Frame, ein Frame, dessen anonymisierte Form länger als 1 MiB wäre, oder jeder Frame außer `Version` vor einem `Version 2`- oder `3`-Frame oder nach einer anderen Version), `output file exists`, `output is the input`, `write failed` (zum Beispiel ein Ordner, der nicht existiert) und `cancelled` (Strg+C). Ohne genau zwei Argumente gibt das Werkzeug `Usage: Censio.Anonymiser <recording> <output>` aus und endet mit Code 2. Nach einem Fehler bleibt keine Ausgabedatei zurück.

Die Ausgabe vor dem Einchecken prüfen: Ein Name oder eine Zahl, die Sie aus dem Spiel kennen, darf darin nicht vorkommen. Die ursprüngliche Aufzeichnung nie einchecken oder posten.

#### Eine Aufzeichnung an einen Server senden

Um den Server ohne das Spiel auszuprobieren, sendet der Companion ihm eine Aufzeichnung, über denselben WebSocket und Vertrag, den ein Companion im laufenden Betrieb verwendet (*Weiterleitungsmodus*). Es braucht einen Server desselben Releases wie der Companion (nicht das Image `0.2.0`, das keinen Ingest hat); ein Companion und ein Server mit verschiedenen Vertragsversionen lehnen sich ab (*Fehler* unten). Die Aufzeichnung wird ein neues Profil `Replay <jjjj-MM-tt HH:mm:ss>` (die lokale Zeit, zu der der Companion das Abspielen gestartet hat) mit den Regionen, Inseln und Waren der Datei und, wenn das Spiel der Aufzeichnung sie gesendet hat (Pipe-Protokoll 3), ihren Handelsrouten; jeder Lauf fügt ein weiteres hinzu, und sie bleiben, bis Sie sie löschen (*Verlauf und Löschen eines Profils*). Vom Product Manager unter Windows mit `--speed 10` und der Testdatei `long-session.jsonl` ausprobiert: ein Server in Docker (Image mit dem dokumentierten Befehl `docker build` aus diesem Stand des Repositorys gebaut) und ein Server aus dem Quellcode (`ws://localhost:5000/ingest`) füllten beide die Seiten (Regionen und Inseln), und eine Token-Datei, die Windows PowerShell 5.1 mit `>` geschrieben hat, wurde akzeptiert; die Schritte brauchten keine Änderung. Noch nicht ausprobiert: `docker cp` für die Token-Datei, eine in Notepad als UTF-16 BE gespeicherte Token-Datei, `wss://` unter Windows, der Windows-Zertifikatspeicher, ein eingerichteter System-Proxy und ein Docker-Server auf einem anderen Host.

1. **Ein Server.** Einer von drei Orten; die Adresse ist die, die Sie `--server` geben:
   - Docker Desktop auf demselben PC (*Starten*): `ws://localhost:8080/ingest`.
   - Docker auf einem anderen Host im Netz, zum Beispiel einem NAS: `ws://<Host>:8080/ingest`.
   - Aus dem Quellcode auf dem PC (*Aus dem Quellcode bauen*), im Hauptordner des Checkouts: `dotnet run --project src/Censio.Server -c Release --no-launch-profile -- --Censio:DataDirectory=<vollständiger Pfad eines leeren Ordners>`; der Server ist unter `ws://localhost:5000/ingest` erreichbar. Ohne das Datenverzeichnis hat der Server kein Token und lehnt jeden Companion ab. Den Datenordner außerhalb des Checkouts anlegen.
2. **Eine Aufzeichnung.** Eine eigene verwenden (*Aufzeichnen und Abspielen*, nur in den eigenen Server abgespielt: Eine rohe Aufzeichnung enthält den Namen der Spielfigur, Inselnamen, Namen von Handelsrouten und Ihre Wirtschaft; ein Abspielen sendet keinen Katalog, Namen und Symbole brauchen also eine Live-Verbindung eines Companions mit installiertem Spiel, *Der Katalog und die Symbole*) oder die Testdatei `long-session.jsonl`, eine anonymisierte Aufzeichnung von etwa 30 Minuten: `https://raw.githubusercontent.com/LarsLaskowski/Censio/main/tests/Censio.Pipe.Tests/Fixtures/long-session.jsonl` im Browser öffnen und die Seite als Datei speichern (`Strg+S`; prüfen, dass der Dateiname auf `.jsonl` endet, nicht auf `.txt`). Sie hat eine Pause von etwa 18 Minuten; bei `--speed 10` sind das etwa 108 Sekunden, und die Verbindung bleibt offen.
3. **Die Token-Datei.** Bei verlangtem Token enthält die Datei das Token des Servers und sonst nichts (ein Zeilenumbruch am Ende ist in Ordnung); bei `Censio:Ingest:RequireToken` `false` `--token-file` weglassen. Die Datei außerhalb des Quellcode-Checkouts halten, zum Beispiel `C:\Users\<Sie>\censio-token.txt`, nur für Sie lesbar, und nie posten (*Probleme melden*). Sie entsteht auf einem dieser Wege:
   - Docker: Byte für Byte kopieren mit `docker cp censio:/config/ingest-token "C:\Users\<Sie>\censio-token.txt"` (in `cmd` oder PowerShell, auf dem Host, der Docker ausführt; bei einem NAS dort kopieren und auf den PC bringen).
   - Aus dem Quellcode: Die Datei ist `<Datenverzeichnis>\ingest-token`, sobald der Server gestartet ist; als `--token-file` nennen oder kopieren.
   - Von Hand: das Token lesen (`docker exec censio cat /config/ingest-token`), in Notepad einfügen und die Datei speichern. UTF-8, UTF-8 mit BOM, UTF-16 LE und UTF-16 BE von Notepad funktionieren, ebenso die Datei, die Windows PowerShell 5.1 mit der Umleitung `>` schreibt (UTF-16 mit Byte-Order-Mark). Das Token muss 32 bis 1.024 sichtbare ASCII-Zeichen haben; umgebende Leerraumzeichen werden ignoriert.
4. **Der Befehl.** Einen laufenden Companion vorher schließen (`Exit`). Windows-Taste + R drücken und eine Zeile mit vollständigen Pfaden eingeben (Explorer und Verknüpfungen setzen den Arbeitsordner, relative Pfade gehen deshalb schief):

```text
"C:\Users\<Sie>\Censio\Censio.Companion.exe" --replay "C:\Users\<Sie>\long-session.jsonl" --server ws://localhost:8080/ingest --token-file "C:\Users\<Sie>\censio-token.txt" --speed 10
```

   `--server` nimmt eine `ws://`- oder `wss://`-Adresse mit Host und ohne Benutzername, Passwort oder `#`; `--token-file` braucht `--server`, und beide brauchen `--replay`; jede andere Kombination ist eine ungültige Kommandozeile (`Censio Companion: Invalid command line`), und es wird nichts gesendet. Das Token steht nie in der Kommandozeile.
5. **Was Sie sehen.** Der Tooltip zeigt `Censio Companion: Replay: Connecting to server`, dann `Replay: Connected` und `Replay: Receiving` wie beim Abspielen ohne Server, und am Ende `Censio Companion: Replay finished: <n> ticks sent, <r> refused` (`1 tick sent` bei einem; eine abgelehnte Nachricht beendet das Abspielen nicht; `<n>` zählt nur Ticks, und eine abgelehnte Handelsrouten-Nachricht zählt in `<r>`). Im Browser füllen sich die Seiten des Servers mit jedem Tick; der Companion-Hinweis zeigt den Companion als verbunden, solange das Abspielen läuft, und danach als nicht verbunden. Die Zeiten der Testdatei liegen 30 bis 365 Tage zurück, deshalb bleibt ein Profil mit neueren Daten das, das die Seiten zeigen: im Profilschalter `Replay <Zeit>` wählen (*Weboberfläche*). Der Server schreibt `Companion connected.` und `Companion disconnected; <a> messages accepted, <r> refused.` ins Log; das Log des Companions hat vier Zeilen zum Abspielen, ohne Token, Adresse und Namen (*Daten und Logs*).
6. **Fehler.** Jeder beendet das Abspielen mit `Replay error: <Grund>` und dem Problem-Symbol bis `Exit`; nichts wird wiederholt, und was der Server bestätigt hat, bleibt gespeichert.

   | Grund | Bedeutung |
   | ----- | --------- |
   | `token file cannot be read` | Die Datei fehlt, ist ein Ordner oder nicht zugänglich |
   | `token file holds no valid token` | Über 64 KiB, eine ungültige Kodierung oder nicht 32 bis 1.024 sichtbare ASCII-Zeichen |
   | `server unreachable` | Unter der Adresse antwortet kein WebSocket: falscher Host oder Port, eine HTTP-Seite (das Image `0.2.0`), eine Umleitung, ein TLS-Zertifikat, dem Ihr Windows nicht vertraut, oder kein Upgrade innerhalb von 30 Sekunden |
   | `token refused` | Das Token des Servers weicht ab, oder die Datei enthält keines, obwohl der Server eines braucht |
   | `another Companion is connected` | Beim Server ist ein Companion verbunden; ihn schließen und erneut abspielen |
   | `server does not support contract version 2` | Der Server hat eine andere Vertragsversion, zum Beispiel ein Server des Releases `0.3.0`, der Version 1 liest: einen Server und einen Companion desselben Releases verwenden |
   | `server does not answer` | Keine Antwort und keine Annahme einer Nachricht durch den Server innerhalb von 30 Sekunden |
   | `server connection lost` | Der Server wurde gestoppt, das Netz fiel aus, oder der Server hat die Verbindung geschlossen |
   | `invalid server reply` | Der Server hat etwas gesendet, das ein Server nicht senden darf |

   Eine Aufzeichnung, die sich nicht öffnen lässt oder einen ungültigen Kopf hat, endet mit ihrem Grund (*Aufzeichnen und Abspielen*), bevor der Server kontaktiert wird, es entsteht also kein Profil; eine ungültige oder nicht lesbare Zeile später beendet das Abspielen, nachdem die Ticks davor gesendet wurden.
7. **Warnungen.** Über `ws://` laufen Token und Daten unverschlüsselt durchs Netz: überall, wo der Weg nicht Ihr eigenes Netz ist, `wss://` verwenden (ein Reverse-Proxy mit TLS vor dem Server, *Netzwerk und TLS*); der Companion prüft das Zertifikat mit Windows und kann es nicht überspringen, und er nutzt nie einen eingerichteten Proxy. Eine rohe Aufzeichnung nur in den eigenen Server abspielen. Jeder Lauf erzeugt ein Profil, das bleibt, bis Sie es löschen (*Verlauf und Löschen eines Profils*). Die Token-Datei löschen, wenn das Testen endet, und das Token des Servers erneuern, wenn es offengelegt wurde (`SECURITY.md`).

#### Lokaler Modus

Im lokalen Modus betreibt der Companion den Server im eigenen Prozess, sodass die Seiten und der Verlauf weder Docker noch ein NAS brauchen. Er ist standardmäßig aus. Er ist in `main` und in einem Release nach `v0.4.0`, nicht in `v0.4.0`, und er ist nur für **Windows 11, 64 Bit**: Unter Windows 10 22H2 läuft der Companion wie oben beschrieben, aber der lokale Modus wird dort weder unterstützt noch versucht noch abgelehnt. Er braucht kein installiertes .NET, keinen Installer, keine Administratorrechte und keine Firewall-Freigabe (der Server lauscht nur auf den Loopback-Adressen). Die Exe des Companions ist deutlich größer als zuvor (etwa 232 MB in einem gemessenen Build), weil sie den Server und die Skripte und Stile seiner Seiten enthält; das ZIP bleibt eine Datei.

**Schritte.**

1. Einen laufenden Companion beenden (`Exit` im Tray-Menü).
2. Die Datei `%LOCALAPPDATA%\Censio\settings.json` anlegen oder die Schlüssel in die vorhandene eintragen. Sie braucht `"mode": "local"` und `"localPort"`, wenn Sie einen anderen Port als 5000 möchten:

```json
{
  "mode": "local",
  "localPort": 5117
}
```

3. `Censio.Companion.exe` starten. Unter `Catalog: …` zeigt das Menü die ausgegraute Zeile `Server: starting`, dann `Server: running at http://localhost:5117/` (`5000` ohne `localPort`). `Open Censio`, direkt über `Open diagnostics`, ist bis dahin ausgegraut und aktiv, solange der Server läuft. Das Tray-Symbol wartet nicht auf den Server.
4. `Open Censio` wählen. Der Standardbrowser öffnet `http://localhost:<port>/`; die Startseite zeigt die Version des Companions. Die Seiten zeigen `Noch keine Daten. Die Seiten füllen sich, sobald der Companion Daten sendet.`, bis das Spiel sendet: Der Companion sendet seine Live-Daten wie im *Weiterleitungsmodus* an seinen eigenen Server, unter dem Profil `Live`, und Sie können die Seiten zusätzlich durch ein Abspielen füllen (Schritt 6).
5. `Exit` wählen. Ein laufender Companion beendet einen zweiten Start stillschweigend, also schließen Sie ihn zuerst. Das Symbol verschwindet sofort und der Server stoppt; der Prozess endet innerhalb von 5 Sekunden.
6. `Censio.Companion.exe` mit einem Abspielen und ohne `--server` starten: Windows-Taste + R drücken und mit vollständigen Pfaden `"C:\Users\<Sie>\Censio\Censio.Companion.exe" --replay "C:\Users\<Sie>\long-session.jsonl" --speed 10` eingeben (eine Aufzeichnung: *Eine Aufzeichnung an einen Server senden*, Schritt 2). Der Companion betreibt den Server wie in Schritt 3, und der Tooltip zeigt `Replay: Connecting to server`, bis der Server läuft und geantwortet hat; dann sendet er die Aufzeichnung mit dem Token des Servers, das er im Prozess übernimmt, an seinen eigenen Server, sodass Sie weder eine Token-Datei noch eine Adresse brauchen, und endet bei `Replay finished: <n> ticks sent, <r> refused`. Mit `--server` geht das Abspielen an diese Adresse wie dort beschrieben.
7. `Open Censio` wählen und in der Profilauswahl das Profil `Replay <Zeit>` wählen (*Weboberfläche*): Die Regionen, Inseln und Waren der Aufzeichnung sind da. Der Server läuft nach dem Abspielen weiter bis `Exit`.
8. `Exit` wählen und `Censio.Companion.exe` erneut starten: Die Seiten zeigen dieselben Profile und denselben Verlauf, die der Server in seiner Datenbank hält.

**Die Einstellungen.** Der Companion liest die Datei einmal beim Start, schreibt sie nie, und eine Änderung gilt nach einem Neustart. Die Schlüssel werden ohne Beachtung der Groß- und Kleinschreibung zugeordnet, ebenso der Wert `local`.

| Schlüssel | Wert |
| --------- | ---- |
| `mode` | `"local"` schaltet den lokalen Modus ein (`"forward"` den Weiterleitungsmodus, *Weiterleitungsmodus*). Ein leerer Text zählt als fehlendes `mode`. Jeder andere Text, ein Wert, der kein Text ist, oder der Schlüssel zweimal (auch in anderer Schreibweise) ist ungültig |
| `localPort` | Nur mit `mode` `local` gelesen: eine ganze Zahl von 1 bis 65535, als Ziffern geschrieben (`5117`). `5117.0`, `5.117e3`, `"5117"`, `null`, eine negative Zahl, `0` und `65536` sind ungültig, ebenso der Schlüssel zweimal. Standard 5000 |

**Die Menüzeile.** `Server: <Zustand>` zeigt, was der Server tut; der Companion läuft in jedem Zustand weiter, und Spielsuche, Pipe, Aufzeichnung und Abspielen funktionieren wie ohne lokalen Modus.

| Zeile | Bedeutung | Was zu tun ist |
| ----- | --------- | -------------- |
| `Server: starting` | Der Server startet im Hintergrund | Warten |
| `Server: running at http://localhost:<port>/` | Er läuft; `Open Censio` ist aktiv | Nichts |
| `Server: port <port> in use` | Der Port ist auf `127.0.0.1` oder auf `[::1]` belegt: von einem anderen Programm, einem eigenständigen `Censio.Server` oder dem Companion eines anderen angemeldeten Windows-Benutzers. `Open Censio` bleibt ausgegraut | Das andere Programm schließen oder einen anderen `localPort` setzen und den Companion neu starten |
| `Server: failed` | Jeder andere Startfehler oder ein Server, der beendet wurde, während der Companion lief: Der Datenordner kann nicht angelegt oder beschrieben werden, die Datenbank wurde von einem neueren Censio geschrieben, ist keine Censio-Datenbank oder kann nicht aktualisiert werden, der Schlüsselring oder die Token-Datei kann nicht geschrieben oder zurückgelesen werden. Ein Port, den Windows für sich reserviert, endet voraussichtlich ebenfalls hier. Im Ordner wird nichts repariert oder gelöscht, und der Companion startet den Server nicht neu | `Open log folder` wählen und das Log des Tages lesen: Es nennt den Grund (*Daten und Logs*). Einen anderen `localPort` versuchen. Ein Neustart des Companions versucht es erneut |
| `Server: settings invalid` | Ein Wert von `mode` oder `localPort` ist falsch (Tabelle oben) oder, mit `"mode": "forward"`, von `serverAddress` oder `serverToken` oder, mit `forward` oder `local`, von `bufferHours` oder `bufferMegabytes` (*Weiterleitungsmodus*); das Log nennt ihn. Kein Server startet; der Spielordner in derselben Datei zählt weiter | Die Datei korrigieren und neu starten |

Eine Einstellungsdatei, die als Ganzes ungültig ist (zu groß, kein JSON, nicht lesbar), zeigt wie bisher `Game: settings file invalid` und keine `Server:`-Zeile. Bei einer ungültigen Befehlszeile wird der Server nicht betrieben, und weder Zeile noch Eintrag erscheinen; mit `--record` oder `--replay` wird er betrieben. Ein Abspielen ohne `--server`, dessen Server nicht startet, endet mit `Replay error: local server not running`; nichts wird wiederholt. Kann `Open Censio` keinen Browser starten, steht im Log die Warnung `Could not open the browser`, und sonst ändert sich nichts.

**Der Server.** Er lauscht auf `127.0.0.1` und auf `[::1]` (nur auf `127.0.0.1`, wenn IPv6 auf dem PC ausgeschaltet ist), unverschlüsseltes HTTP, und beantwortet nur Anfragen, deren Hostname `localhost`, `127.0.0.1` oder `[::1]` ist (mit beliebigem Port); jeder andere Hostname und eine Anfrage ohne einen wird mit `400` beantwortet, sodass eine Seite einer anderen Website Ihre Seiten nicht über Ihren Browser lesen kann. Er nimmt keine Umgebungsvariable und keine Konfigurationsdatei an. Das Ingest-Token ist erforderlich wie im Docker-Image; die Seiten brauchen keine Anmeldung, und die Aufbewahrung und das Löschen des Verlaufs eines Profils funktionieren wie dort (`localhost` ist ein vertrauenswürdiger Host, *Verlauf und Löschen eines Profils*). Seine Warnungen und Fehler gehen ins Log des Companions (*Daten und Logs*), nie das Token.

**Der Datenordner** ist `%LOCALAPPDATA%\Censio\Server`, fest und wie die anderen Companion-Ordner privat für Ihr Windows-Konto. Der Server legt ihn beim ersten Start mit seiner Datenbank `censio.db`, seinem Data-Protection-Schlüsselring und seiner Token-Datei `ingest-token` an und öffnet sie bei jedem späteren Start wieder; die Datenbank liegt nie im Arbeitsspeicher. Der Companion behält den Ordner, wenn Sie ihn entfernen, also löschen Sie ihn von Hand, um Ihre gespeicherten Daten zu entfernen oder leer zu starten (beim nächsten Start entstehen ein neues Token und eine neue Datenbank). Den Ordner und seine Kopien privat halten (*Daten und Logs*).

**Akzeptiertes Risiko.** Die Seiten brauchen keine Anmeldung (*Weboberfläche*), und der Server lauscht auf dem Loopback-Port Ihres PCs: Jedes Programm und jeder andere angemeldete Windows-Benutzer desselben PCs kann den Port erreichen, jedes Profil lesen und den Verlauf löschen. Ohne das Ingest-Token, das in Ihrem privaten Ordner `%LOCALAPPDATA%\Censio\Server` liegt, kann keiner von ihnen Daten senden. Kein anderes Gerät Ihres Netzes erreicht den Server. Den lokalen Modus nur auf einem PC verwenden, dessen Benutzern und Programmen Sie vertrauen.

Vom Product Manager auf einem Windows-11-x64-Rechner ohne .NET ausprobiert: das Release-ZIP mit den Schritten oben, dass ein Loopback-Bind keine Firewall-Abfrage auslöst, und ein Port, den ein eigenständiger `Censio.Server` belegt, der auf allen Schnittstellen lauscht. Noch nicht ausprobiert: ein Port, den Windows reserviert.

#### Weiterleitungsmodus

Im Weiterleitungsmodus sendet der Companion, was das Spiel meldet, live an einen Server, der anderswo läuft, typischerweise das Docker-Image auf einem NAS oder einem Heimserver, und verbindet sich nach einem Neustart des Servers oder einem Netzausfall von selbst neu. Er ist standardmäßig aus. Er ist in `main` und in einem Release nach `v0.4.0`, nicht in `v0.4.0`, und er braucht einen Server desselben Releases wie der Companion (das Image `0.2.0` hat keinen Ingest, und ein Server und ein Companion mit verschiedenen Vertragsversionen lehnen sich ab, *Fehler* unter *Eine Aufzeichnung an einen Server senden*). Er läuft dort, wo der Companion läuft, unter Windows 10 22H2 und Windows 11, 64 Bit.

**Schritte.**

1. Einen laufenden Companion beenden (`Exit` im Tray-Menü).
2. Das Ingest-Token des Servers besorgen. Beim Docker-Image aus *Starten* gibt es `docker exec censio cat /config/ingest-token` aus. Liest der Server sein Token aus einer Datei (`Censio:Ingest:TokenFile`), das Token dieser Datei verwenden. Ist beim Server das Token abgeschaltet (`Censio:Ingest:RequireToken` `false`), brauchen Sie keines und lassen `serverToken` weg (*Ingest-Endpunkt und Token*).
3. Die Datei `%LOCALAPPDATA%\Censio\settings.json` anlegen oder die Schlüssel in die vorhandene eintragen:

```json
{
  "mode": "forward",
  "serverAddress": "ws://nas:8080/ingest",
  "serverToken": "<das Ingest-Token des Servers>"
}
```

   `serverAddress` ist die Adresse des Ingest-Endpunkts: `ws://<Host>:8080/ingest`, wobei `<Host>` der Rechner ist, auf dem Docker läuft (ein Name oder eine IP-Adresse), und `8080` der veröffentlichte Port, oder eine `wss://`-Adresse, wenn ein Reverse-Proxy vor dem Server TLS beendet (*Netzwerk und TLS*). Das erzeugte Token braucht in JSON keine Maskierung; ein Token aus `Censio:Ingest:TokenFile` kann ein `"` oder ein `\` enthalten, das Sie als `\"` und `\\` schreiben.
4. `Censio.Companion.exe` starten. Unter `Catalog: …` zeigt das Menü die ausgegraute Zeile `Server: connecting`, dann `Server: connected`, auch solange das Spiel nicht läuft, und darunter die ausgegraute Zeile `Buffer: <n> waiting`. Der Server zeigt den Companion als verbunden mit dem Pipe-Zustand, den er meldet (*Weboberfläche*).
5. Das Spiel mit dem Startargument `/pipe` starten und einen Spielstand laden (*Erste Aufzeichnung Schritt für Schritt*, Schritte 1 und 2). Ticks, Handelsrouten und Sitzungsereignisse erreichen den Server jetzt in der Reihenfolge, in der der Companion sie liest, und die Seiten zeigen sie live unter dem Profil `Live`. Mit installiertem Spiel sendet der Companion außerdem zuerst seinen Katalog (*Der Katalog und die Symbole*), sodass Namen von Regionen und Waren und Symbole der Waren auf den Seiten erscheinen.
6. `Exit` wählen, wenn Sie fertig sind. Der Companion stoppt sofort; was noch wartete, liegt im Puffer und wird beim nächsten Start gesendet (*Was gesendet wird und was verloren geht*).

**Die Einstellungen.** Der Companion liest die Datei einmal beim Start, schreibt sie nie, und eine Änderung gilt nach einem Neustart. Die Schlüssel werden ohne Beachtung der Groß- und Kleinschreibung zugeordnet, ebenso der Wert `forward`; `serverAddress` und `serverToken` werden nur mit `mode` `forward` gelesen, `bufferHours` und `bufferMegabytes` mit `forward` und mit `local`, und `localPort` wird im Weiterleitungsmodus ignoriert.

| Schlüssel | Wert |
| --------- | ---- |
| `mode` | `"forward"` schaltet den Weiterleitungsmodus ein (`"local"` ist der lokale Modus; jeder andere Text, ein Wert, der kein Text ist, oder der Schlüssel zweimal ist ungültig; ein leerer Text zählt als fehlendes `mode`) |
| `serverAddress` | Erforderlich. Eine absolute `ws://`- oder `wss://`-Adresse mit Host und ihrem Pfad, eine Query ist erlaubt, ohne Benutzername, Passwort, Fragment, `#`, Leerraum oder Steuerzeichen. Fehlend, kein Text oder zweimal ist ungültig |
| `serverToken` | Optional. 32 bis 1.024 sichtbare ASCII-Zeichen (`!` bis `~`); Leerzeichen, Tabulatoren und Zeilenumbrüche darum werden abgeschnitten. Kein Text, zu kurz oder zu lang, ein anderes Zeichen oder der Schlüssel zweimal ist ungültig. Ohne ihn legt der Companion kein Token vor, was nur ein Server akzeptiert, bei dem das Token abgeschaltet ist |
| `bufferHours` | Optional. Wie lange ungesendete Nachrichten behalten werden: eine ganze Zahl, nur aus Ziffern geschrieben, von 1 bis 168; Standard 24. `24.0`, `2.4e1`, `"24"`, `null`, 0, eine negative Zahl, eine größere Zahl oder der Schlüssel zweimal ist ungültig |
| `bufferMegabytes` | Optional. Wie viel Platz ungesendete Nachrichten belegen dürfen, gezählt als ihr geschriebenes JSON mit 1 MB = 1.048.576 Byte: eine ganze Zahl, nur aus Ziffern geschrieben, von 1 bis 10240; Standard 100. Alles andere oder der Schlüssel zweimal ist ungültig |

Ein falscher Wert zeigt `Server: settings invalid` statt der Zeilen unten, sendet nichts, und das Log nennt das Problem (`Server settings invalid: <Problem>`, nie den Wert); der Spielordner in derselben Datei zählt weiter. Wie bei einer ungültigen Einstellung des lokalen Modus erscheint dann `Open Censio` ausgegraut, und ein Abspielen ohne `--server` endet mit `Replay error: local server not running`.

**Die Menüzeile.** `Server: <Zustand>` zeigt die Verbindung, unter `Catalog: …`. Der Companion versucht es in jedem Zustand weiter außer bei `Server: token refused`, `Server: does not support contract version 2` und `Server: settings invalid`, mit 1, 2, 4, 8 und 16 Sekunden zwischen den Versuchen und danach alle 30 Sekunden, und beginnt nach einer Verbindung, die eine Minute stand, wieder bei 1 Sekunde. Der Tooltip und das Symbol zeigen weiter die Pipe-Verbindung.

| Zeile | Bedeutung | Was zu tun ist |
| ----- | --------- | -------------- |
| `Server: connecting` | Der erste Versuch läuft | Warten |
| `Server: connected` | Der Server hat den Companion angenommen | Nichts |
| `Server: unreachable, retrying` | Unter der Adresse ist kein WebSocket: ein falscher Host, Port oder Pfad, ein Server, der aus ist, ein Netz, das noch nicht steht (der Companion startete bei der Anmeldung), oder ein nicht vertrauenswürdiges `wss://`-Zertifikat | Nichts, wenn der Server oder das Netz zurückkommt; sonst die Adresse und den Server prüfen |
| `Server: not answering, retrying` | Der Server hat innerhalb von 30 Sekunden nicht geantwortet | Den Server prüfen |
| `Server: connection lost, retrying` | Die Verbindung endete: ein Neustart des Servers, ein Netzausfall. Eine Verbindung, über die nichts ankommt, wird innerhalb von 60 Sekunden erkannt | Nichts; der Companion verbindet sich neu und sendet, was wartete |
| `Server: invalid reply, retrying` | Der Server hat etwas gesendet, das der Companion nicht lesen kann, oder eine Antwort über 65.536 Byte (nur die Bestätigung eines Katalog-Uploads darf größer sein) | Prüfen, ob der Server ein Censio-Server desselben Releases ist |
| `Server: another Companion is connected, retrying` | Der Server hält noch die frühere Verbindung dieses Companions, bis zu etwa eine Minute, oder ein anderer Companion nutzt ihn (ein Server nimmt einen) | Warten; den anderen Companion schließen, wenn es bleibt |
| `Server: token refused` | Der Server nimmt `serverToken` nicht an. Wird nicht wiederholt | Das Token in der Datei korrigieren und den Companion neu starten |
| `Server: does not support contract version 2` | Der Server ist zu alt. Wird nicht wiederholt | Einen Server des Releases des Companions betreiben und den Companion neu starten |
| `Server: settings invalid` | Ein Wert der Datei ist falsch (Tabelle oben) | Die Datei korrigieren und neu starten |

Jeder andere Zustand zeigt `Server: not connected`. Im lokalen Modus (*Lokaler Modus*) behält die Zeile ihre eigenen Texte, und der Companion sendet an seinen betriebenen Server, sobald der läuft.

**Was gesendet wird und was verloren geht.** Nachdem der Server den Companion angenommen hat, sendet er jeden Tick mit mindestens einer Insel, jede Handelsrouten-Nachricht, jeden Sitzungsbeginn und das erste Sitzungsende, in der gelesenen Reihenfolge und eine Nachricht nach der anderen, dazu seinen Pipe-Zustand (auch solange das Spiel nicht läuft). Er lädt außerdem den Spielkatalog und seine Symbole hoch (*Der Katalog und die Symbole*) und sendet keinen Figurennamen; Inselnamen, die Wirtschaft, Handelsrouten, der Katalog und die Symbole gehen an den Server. `--record` sendet ebenfalls; ein Abspielen (`--replay`) und eine ungültige Befehlszeile öffnen keine Verbindung, und ein Abspielen im Weiterleitungsmodus bleibt offline, wenn es nicht `--server` nennt. Solange der Server nicht erreichbar ist, warten die Nachrichten im Puffer, eine Datei pro Nachricht in `%LOCALAPPDATA%\Censio\Buffer`, und werden nach dem erneuten Verbinden die älteste zuerst gesendet, vor neueren; die Nachricht, die unterwegs war, wird zuerst erneut gesendet, auch nach `Exit` oder einem Neustart des PCs (das Log sagt dann `Live buffer holds <n> messages from an earlier run`). Der Puffer hält die Nachrichten der letzten `bufferHours` Stunden (24) und höchstens `bufferMegabytes` Megabyte (100) davon, die neueste Nachricht und die unterwegs befindliche ausgenommen. Über eine Grenze hinaus werden die ältesten verworfen und gezählt: die Menüzeile lautet `Buffer: <n> waiting, <d> dropped`, das Log sagt `Live messages dropped: <d>`, und der Verlauf zeigt eine Lücke, nie Nullen. Das Alter ist die Zeit, zu der der Companion die Nachricht nahm, nach der Uhr Ihres PCs. Eine Datei, die nicht gelesen werden kann (beschädigt, geändert oder aus einer anderen Version), wird gelöscht, als verworfen gezählt und als `Live buffer entries unreadable: <n>; discarded` protokolliert; Dateien anderer Namen im Ordner bleiben unberührt. Kann der Ordner nicht beschrieben werden, endet die Menüzeile auf `, not saved to disk`, und `Live buffer cannot be written; waiting messages are kept in memory until Exit` wird einmal protokolliert: die Nachrichten warten dann im Arbeitsspeicher, höchstens 64 oder 16 MiB, und gehen bei `Exit` verloren. Eine Nachricht, die bei `Exit` noch auf ihre Datei wartet, geht verloren; eine Nachricht, die bei `Exit` unterwegs ist, bleibt im Puffer und wird erneut gesendet, und ein Server, der sie schon gespeichert hat, bestätigt sie, ohne sie doppelt zu speichern. Der Puffer geht an den Server des Starts, der ihn sendet: nach einer Änderung von `serverAddress` gehen die wartenden Nachrichten an den neuen Server; den Ordner `%LOCALAPPDATA%\Censio\Buffer` vorher löschen, wenn dieser Server sie nicht erhalten soll. Der Ordner bleibt beim Entfernen des Companions erhalten, also von Hand löschen. Eine Nachricht, die der Server ablehnt, wird nicht erneut gesendet, und das Log nennt ihre Art (`Server refused a live message: <Art>`).

**Der Katalog und die Symbole.** Sobald der Katalog bereit ist (die Menüzeile `Catalog: <n> entries`, auch `…, not cached` oder `…, icons failed`; kein gefundenes Spiel oder `Catalog: failed` bedeutet keinen), sendet der Companion ihn im Weiterleitungsmodus und im lokalen Modus an den Server, damit die Seiten Namen von Regionen und Waren und Symbole der Waren statt `Region <Nummer>` und `Ware <Nummer>` zeigen. Gleich nachdem der Server den Companion angenommen hat, vor den wartenden Nachrichten, vergleicht er die Identität des Katalogs (ein SHA-256 seines Dokuments) mit der, die der Server nennt. Hat der Server keinen Katalog, einen unvollständigen oder einen anderen (etwa von einer anderen Installation), sendet der Companion den Katalog und danach nacheinander die Symbole, die dem Server nach seiner Angabe fehlen, in der Reihenfolge, in der der Server sie auflistet, und das Log sagt `Catalog sent to the server: <i> icons sent, <r> refused` (`<i>` zählt die Symbole, die der Server angenommen hat, `<r>` die, die er oder der Companion abgelehnt hat). Hat der Server denselben Katalog schon (ein Neustart, ein erneutes Verbinden, ein neuer Start mit unverändertem Spiel), wird nichts gesendet, und das Log sagt `Catalog already on the server`. Ein Katalog, der bereitwird, während der Companion verbunden ist (die erste Extraktion eines Starts oder eine nach einem Spielupdate), wird nach der Nachricht, die unterwegs ist, gesendet, außer der Server hat ihn. Ein Katalog, dessen Symbole nicht gelesen werden konnten, wird ohne Symbole gesendet, die Seiten zeigen dann nur Namen. Ein frischer Docker-Server mit leerem `/config` zeigt die Namen und Symbole nach der ersten solchen Verbindung eines Companions mit installiertem Spiel; die offenen Seiten aktualisieren sich ohne Neuladen. Ein **Abspielen sendet keinen Katalog**: Namen und Symbole erreichen einen Server nur über eine Live-Verbindung eines Companions mit installiertem Spiel, und ein Abspielen in einen Server zeigt sie nur, wenn eine solche Verbindung sie vorher dort gespeichert hat. Der Katalog und die Symbole warten nie im Puffer (sie zählen nicht in `Buffer: <n> waiting`), und das Menü zeigt keinen Text für das Hochladen. Lehnt der Server den Katalog ab, sagt das Log `Server refused the catalog: <Art>`, und der Companion sendet diesen Katalog bis zum nächsten Start nicht erneut; `Catalog not sent: the contract writer refused it` sagt, dass der Companion ihn nicht schreiben konnte. Scheitert die Verbindung, während der Katalog oder ein Symbol unterwegs ist (keine Antwort innerhalb von 30 Sekunden, eine verlorene Verbindung), sendet der Companion bei der nächsten Verbindung zuerst die wartenden Nachrichten und dann den Katalog erneut, und nach dem dritten solchen Scheitern gibt er diesen Katalog für diesen Lauf mit `Catalog not sent: the connection failed 3 times during its upload` auf; den Companion neu starten oder den Server in Ordnung bringen, um es erneut zu versuchen. Eine Verbindung, die den Katalog nicht innerhalb von 30 Sekunden aufnehmen kann, kostet so bis zu drei erneute Verbindungen. Der Katalog und die Symbole gehen über dieselbe Verbindung wie alles andere: unverschlüsselt mit `ws://`, unter TLS mit `wss://`.

**Den Puffer ausprobieren.** (1) Ausfall: den Server stoppen, einige Minuten spielen und beobachten, wie `Buffer: <n> waiting` wächst; den Server starten und beobachten, wie es auf `Buffer: 0 waiting` fällt, während die Seiten aufholen. (2) Neustart: während eines Ausfalls `Exit` wählen, den Companion neu starten und im Log nach `Live buffer holds <n> messages from an earlier run` suchen; die Nachrichten werden nach `Server: connected` gesendet. (3) Altersgrenze: `"bufferHours": 1` setzen, neu starten, den Server länger als eine Stunde stoppen und wieder starten: die älteren Nachrichten werden verworfen (`Buffer: … dropped`, `Live messages dropped: <n>`), und die Diagramme brechen dort ab. Mit `"bufferMegabytes": 1` sieht man die Größengrenze nach wenigen Stunden Spiel.

**Das Profil `Live`.** Bis eine spätere Version Sie ein Profil wählen lässt, geht alles, was der Companion sendet, in ein Profil mit dem Namen `Live`, nach jedem Neustart und jeder Aktualisierung dasselbe, sodass sein Verlauf weitergeht. **Warnung:** Wenn Sie einen anderen Spielstand laden oder eine andere Spielrunde beginnen, gehen deren Ticks ebenfalls nach `Live`. Inseln mit demselben Schlüssel setzen sich fort und benennen den Verlauf der anderen um, und die Inseln des anderen Spielstands bleiben ohne neue Werte gelistet; der Companion zeigt keine Warnung. Pro Server eine Spielrunde verwenden oder den Verlauf von `Live` zwischen den Spielrunden löschen (*Verlauf und Löschen eines Profils*).

**Die Datei enthält eine Zugangsinformation.** `settings.json` enthält jetzt das Ingest-Token des Servers im Klartext. Halten Sie sie in Ihrem privaten Ordner und geben Sie sie nicht weiter, hängen Sie sie nicht an ein Issue an und posten Sie ihren Inhalt nicht; der Companion protokolliert nie das Token, die Adresse oder einen Servernamen.

**Akzeptiertes Risiko.** Über `ws://` sendet der Companion das Ingest-Token unverschlüsselt bei jedem Start und jedem erneuten Versuch, unbeaufsichtigt, an jeden Host, der `serverAddress` beantwortet; ein Name ohne Domain (etwa `nas`) kann von jedem Gerät des Netzes beantwortet werden, in dem der PC ist, verwenden Sie also `wss://` oder eine Adresse in einem Netz, dem Sie vertrauen, wenn der PC Ihr Heimnetz verlässt. Auch die Daten laufen unverschlüsselt durch das Netz (*Netzwerk und TLS*).

Bisher mit dem echten Spiel und einem Docker-Server unter Windows ausprobiert: das Verbinden und die Live-Seiten, ein Neustart des Servers (`docker restart`), ein Start vor dem Server, ein falsches Token, `Exit` (unter 2 Sekunden) und die Live-Daten des lokalen Modus. Nicht mit dem echten Spiel ausprobiert: der Puffer unter Windows. Nur durch automatisierte Tests abgedeckt: der Verlust des Netzwerks, der Puffer und seine Grenzen, die Ablehnungen außer dem Token und das Erkennen einer stillen Verbindung (einmal mit 48,75 Sekunden gegen einen lokalen Testendpunkt gemessen).

### Aus dem Quellcode bauen

Um einen Stand des Repositorys auszuführen, der nicht veröffentlicht ist, ihn aus einem Checkout dieses Repositorys bauen; die Befehle laufen in dessen Hauptverzeichnis. Edge-Builds werden nicht angeboten. In den übrigen `docker run`-Befehlen dieser Anleitung `--pull never` ergänzen und den lokalen Namen `censio` statt `networlddev/censio:0.4.0` verwenden.

#### Server-Image bauen

Das baut den aktuellen Stand des Repositorys zu einem lokalen Image. Es braucht Docker 23 oder neuer mit BuildKit und Zugriff auf `mcr.microsoft.com`. Im Hauptordner des Checkouts ausführen (siehe [Censio beziehen](../README.md#censio-beziehen)):

```text
docker build -f src/Censio.Server/Dockerfile -t censio .
```

Der Build setzt die Version `0.0.0`; eine andere wird als Semantic Version übergeben (`MAJOR.MINOR.PATCH`, optional mit Pre-Release- und Build-Teil), alles andere lässt den Build mit `VERSION is not a semantic version` scheitern:

```text
docker build -f src/Censio.Server/Dockerfile --build-arg VERSION=1.2.3 -t censio .
```

Das lokale Image starten. `--pull never` lässt Docker den Start verweigern, wenn der Build fehlgeschlagen ist und kein lokales Image `censio` existiert, statt ein fremdes Image dieses Namens zu laden:

```text
docker run -d --name censio --pull never -p 8080:8080 -v censio-config:/config censio
```

Dann `http://localhost:8080/health` (`Healthy`) und `http://localhost:8080/` wie oben prüfen; die Startseite zeigt `Version 0.0.0`. Der Maintainer hat das Image mit diesen Schritten gebaut und gestartet, und `/health` antwortete mit `Healthy`. Noch nicht ausprobiert: die Ablehnung durch `--pull never` nach einem fehlgeschlagenen Build.

#### Companion bauen

Das Bauen braucht das .NET-11-SDK (Version 11.0.100 oder ein späterer Patch oder ein späteres Feature Band), Zugriff auf `nuget.org` und den Quellcode (siehe [Censio beziehen](../README.md#censio-beziehen)), auf jedem Betriebssystem, das das SDK unterstützt; nur das Ausführen des Programms braucht Windows 10 22H2 oder Windows 11, x64. Den Befehl im Hauptordner des Checkouts ausführen. Er verwendet die Flags des Release-Builds, außer der Version, und schreibt in den Ordner `publish`:

```text
dotnet publish src/Censio.Companion/Censio.Companion.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -p:DebugType=embedded -p:PublishDocumentationFile=false -p:PublishReferencesDocumentationFiles=false -o publish
```

Der Ordner `publish` enthält danach nur `Censio.Companion.exe`. Unter Windows starten (`publish\Censio.Companion.exe`); das Tray-Menü zeigt `Version 0.0.0`. Der Befehl ist so geschrieben, dass er in PowerShell 7 und Windows PowerShell 5.1 läuft. Der Maintainer hat den Companion mit diesem Befehl veröffentlicht und gestartet, und sein Tray-Menü zeigte `Version 0.0.0`; welche PowerShell verwendet wurde, wurde nicht festgehalten. Noch nicht ausprobiert: Windows PowerShell 5.1.

## Erste Aufzeichnung Schritt für Schritt

Dieser Weg führt vom Download bis zu einer Aufzeichnungsdatei und ihrem Abspielen, unter Windows 10 22H2 oder Windows 11 (64 Bit) mit installiertem Anno 117. Jeder Schritt endet mit dem, was Sie als Nächstes sehen.

Die Exe nicht aus dem ZIP heraus starten: Sie läuft dann aus einem temporären Ordner, und `Start with Windows` würde einen Pfad eintragen, den Windows später entfernt. Sie sehen die Datei `Censio.Companion.exe`.
3. `Censio.Companion.exe` starten. Zeigt Windows SmartScreen „Der Computer wurde durch Windows geschützt“, „Weitere Informationen“ wählen, dann „Trotzdem ausführen“. Es öffnet sich kein Fenster; ein Tray-Symbol erscheint.

Windows kann ein neues Symbol hinter dem Pfeil `^` neben der Uhr verbergen; auf den Pfeil klicken und das Symbol herausziehen, damit es sichtbar bleibt. Mit der Maus darüber fahren: Der Tooltip lautet `Censio Companion: Waiting for game`. Ein zweiter Start von `Censio.Companion.exe` endet sofort ohne Meldung und lässt den ersten weiterlaufen.

## Erster Start

Server: `http://localhost:8080/` öffnen; die Startseite zeigt die Überschrift `Censio` und die Zeile `Version <version>`. `curl http://localhost:8080/health` antwortet mit `Healthy`, und nach wenigen Sekunden zeigt `docker ps` den Container als `(healthy)`. Beim ersten Start wird der erste Data-Protection-Schlüssel angelegt, und ASP.NET Core meldet einmal die Warnung `No XML encryptor configured` (siehe *Einschränkungen*). Der Server ab dem Release `0.3.0` legt außerdem das Ingest-Token an und schreibt `An ingest token was generated and stored in '/config/ingest-token'.` ins Log (siehe *Ingest-Endpunkt und Token*); er legt außerdem seine Datenbank an und schreibt `The database '/config/censio.db' was created.` ins Log (siehe *Daten und Logs*); ein späterer Start auf demselben `/config` schreibt `The database '/config/censio.db' was opened.`

Companion: Das Programm öffnet kein Fenster, bis Sie `Open diagnostics` wählen, und zeigt nur solange dieses Fenster offen ist eine Schaltfläche in der Taskleiste. Im Infobereich erscheint ein Symbol mit dem Tooltip `Censio Companion: <Zustand>` (die Zustände stehen oben unter *Verbindung zum Spiel*); sein Menü enthält den ausgegrauten Status, letzten Tick, die Spielinstallation (`Game: …`, siehe *Spielinstallation* oben) und den Spielkatalog (`Catalog: …`, siehe *Spielkatalog* oben), `Open diagnostics`, `Start recording` (oder `Stop recording`), `Open recordings folder`, `Open log folder`, `Start with Windows` (mit Häkchen, solange es eingeschaltet ist), `Version <version>` (ausgegraut) und `Exit`, das das Symbol entfernt und das Programm innerhalb von 2 Sekunden beendet (im lokalen Modus innerhalb von 5 Sekunden, und mit der ausgegrauten Zeile `Server: …` und dem Eintrag `Open Censio`, *Lokaler Modus*). Das Symbol ist je nach Zustand ein grauer Ring, ein grüner Kreis oder ein rotes Dreieck. Ein zweiter Start in derselben Windows-Sitzung tut nichts: Er endet sofort ohne Meldung und schreibt keine Logzeile, und der erste läuft weiter. Windows SmartScreen fragt beim ersten Start einmal nach (siehe *Companion* oben).

## Weboberfläche

Die Webseiten des Servers ab dem Release `0.3.0` (nicht des Images `0.2.0`) stehen in einem Rahmen: eine Kopfleiste mit der Navigationsschaltfläche, dem Namen `Censio`, dem Profilschalter, dem Sprachschalter und dem Designschalter sowie links eine Navigation, die die Startseite und die Regionen auflistet. Die Navigationsschaltfläche schließt und öffnet die Navigation; die Seite nutzt dann die frei gewordene Breite.

- Design: Die Seite startet hell. Die Designschaltfläche wechselt sofort und ohne Neuladen zum dunklen Design und zurück.
- Sprache: Die Seite ist deutsch, wenn die Sprachliste Ihres Browsers eine deutsche Variante (`de`, `de-AT`, …) vor Englisch einordnet, sonst englisch. Die Sprachschaltfläche (ein Übersetzungssymbol) bietet `English` und `Deutsch` an und ändert sofort alle Texte.
- Die Auswahlen werden ein Jahr lang in Ihrem Browser in vier Cookies gespeichert: `censio-theme` (`light`, `dark`), `censio-language` (`en`, `de`), `censio-chart-range` (`hour`, `day`, `week`, `all`) und `censio-chart-axis` (`real`, `game`); sie enthalten keine personenbezogenen Daten, und eine gespeicherte Sprache hat Vorrang vor der Liste des Browsers. Ein Cookie-Wert, den der Server nicht kennt, wird ignoriert und die Voreinstellung gilt. Ohne Cookies (blockiert, privates Fenster, gelöscht) gelten bei jedem Besuch die Voreinstellungen; ein Wechsel ändert trotzdem die offene Seite.
- Seiten: Die Navigation listet `Regionen` (`/regions`) und `Handelsrouten` (`/trade-routes`). Die Regionsübersicht zeigt die Regionen des Profils mit den neuesten Daten (Inseln, Gebäude, produzierte Waren, Waren im Defizit); eine Region öffnet ihre Inselliste, eine Insel ihre Warentabelle mit Produktion, Verbrauch, Delta (`+` oder `-`, rot für ein Defizit und grün für einen Überschuss), einem Trend (unten), Gebäuden und Produktivität sowie den Symbolen der Waren, wenn der Companion sie gesendet hat. Die Namen stammen aus dem Katalog des Spiels in Ihrer Sprache; ohne Katalog heißt eine Region `Region <Nummer>` und eine Ware `Ware <Nummer>`. Den Katalog bekommt der Server von der Live-Verbindung eines Companions (*Der Katalog und die Symbole*), nie von einem Abspielen. Jede Seite zeigt `Stand: <Zeit>` (die Zeit ihrer Daten in der Zeitzone Ihres Browsers; die Zeile bleibt leer, bis der Browser geantwortet hat, und die Zeit steht nur dann in UTC, mit dem Zusatz `UTC`, wenn der Browser seine Zeitzone nicht nennen kann) und einen Hinweis, solange der Companion nicht verbunden ist (`Der Companion ist nicht verbunden.`), das Spiel nicht läuft (`Das Spiel läuft nicht.`) oder der Companion die Statistik des Spiels nicht lesen kann. Die Seiten aktualisieren sich ohne Neuladen.
- Handelsrouten: Die Seite `Handelsrouten` (`/trade-routes`, die dem Profil mit den neuesten Daten folgt, oder `/profiles/<Profil>/trade-routes` für das gezeigte Profil) listet die Handelsrouten des Profils in einer Tabelle mit den Spalten `Route`, `Ordner`, `Schiffe`, `Verlorene Schiffe`, `Große Probleme`, `Kleine Probleme` und `Stationen` (die Inseln der Stationen der Route der Reihe nach, verbunden durch `→`). Eine Zeile darüber lautet `<n> Handelsrouten, <p> mit Problemen oder verlorenen Schiffen.`, und die Routen mit großen Problemen, kleinen Problemen oder verlorenen Schiffen stehen zuerst, jede solche Zahl rot (die Zahl trägt die Bedeutung auch ohne die Farbe). Das Spiel sendet alle Routen etwa alle zwei Minuten; die Seite zeigt den neuesten Satz unter einer eigenen Zeit `Stand:` (die Zeit, zu der dieser Satz empfangen wurde, nicht die des letzten Ticks), ersetzt ihn ohne Neuladen, wenn ein neuerer eintrifft, behält keinen Verlauf und hat keine Schaltfläche `Verlauf löschen`. Eine Route ohne Namen heißt `Unbenannte Route`, ein leerer Ordner `–`, eine Route ohne Stationen `–`, und eine Station, deren Insel das Profil nicht benennt, `Insel <Sitzung>/<Insel>/<Bereich>`. Ein Profil, das nie Handelsrouten empfangen hat (ein Spiel mit Pipe-Protokoll 2 oder das Abspielen einer solchen Aufzeichnung), zeigt `Noch keine Handelsrouten empfangen.`, ein leerer neuester Satz `Keine Handelsrouten in den letzten Daten.`. Die Zahlen werden so gezeigt, wie das Spiel sie sendet. Vom Product Manager mit dem echten Spiel ausprobiert: Eine Route, die das Spiel mit einem Problem oder einem verlorenen Schiff zeigt, zeigt nach dem Abspielen ihrer Aufzeichnung eine Zahl über 0 in der passenden Spalte.
- Nur die neuesten Daten: Alle Kennzahlen und Warentabellen stammen aus dem letzten Tick des Profils, dem zuletzt empfangenen (seine Zeit zeigt `Stand:`), außer den Handelsrouten oben; ein älterer Tick wird nicht verwendet (die Diagramme und die Trendspalte unten sind die einzigen Orte, die den Verlauf zeigen). Eine Insel, die der letzte Tick nicht enthält oder für die er keine Werte hat, zeigt `–` in jeder Kennzahlspalte ihrer Inselliste (eine Region, deren Inseln alle keine Werte haben, zeigt `–` auch in der Regionsübersicht), und statt ihrer Warentabelle erscheint `Keine Werte für diese Insel im letzten Tick.`; nichts wird als Null gezeigt. Nach dem Laden eines Spielstands sendet das Spiel zuerst einen Tick ohne Werte, daher endet eine Aufzeichnung, die nach einem Laden endet, beim Abspielen mit `--server` mit `–` bei jeder Insel; das Fenster `Open diagnostics` behält dann denselben letzten Tick, mit `(no data yet)` hinter der Spielzeit. Die Kennzahlen kehren mit dem nächsten Tick mit Werten zurück.
- Trendspalte: Die Warentabelle einer Insel (nach `Delta`) und die Inselliste einer Region (nach `Gebäude`) haben eine Spalte `Trend` mit einer kleinen Linie und einem Pfeil je Zeile: bei einer Ware ihr Delta auf der Insel, bei einer Insel ihre Gebäude, über die letzten 4 Stunden bis zum letzten Tick (der Tooltip der Spaltenüberschrift sagt es, `Letzte 4 Stunden bis zum letzten Tick`). Das Fenster ignoriert den Zeitraum und die Zeitachse der Diagramme, und jeder Tick ist ein Punkt; nur Stunden, die älter als 7 Tage sind und die der Server als Stundenmittel aufbewahrt, sind ein Punkt je Stunde (ein Profil, das eine Woche nicht gespielt wurde). Wie die Linien der Diagramme wird die Linie unterbrochen, nie auf null gezogen, wo ein Wert fehlt oder mehr als 15 Minuten zwischen zwei Punkten vergehen. Der Pfeil vergleicht den neuesten Wert der Linie mit ihrem ältesten, beide gerundet, wie die Tabelle sie rundet (das Delta auf zwei Nachkommastellen, Gebäude auf eine ganze Zahl): `↑` (`Steigend`), `↓` (`Fallend`) oder `→` (`Gleichbleibend`); der Name des Pfeils ist sein Tooltip und wird von einem Screenreader vorgelesen, die Linie selbst ist Dekoration. Eine Zeile mit weniger als zwei Werten im Fenster zeigt `–` (eine neue Ware, eine Insel, die dem Verlauf fehlt), ebenso die zweite Zeile einer Ware, die eine Insel doppelt führt (die erste Zeile erhält die Linie). Die Zellen bleiben leer, bis die Trends gelesen sind, was nach dem Anzeigen der Kennzahlen beginnt, sodass die Kennzahlen nie auf sie warten; ein neuer Tick aktualisiert die Linien ohne Neuladen, und eine Änderung des Zeitraums oder der Zeitachse, die hier nichts ändert, liest sie nicht erneut. Können die Trends nicht gelesen werden, zeigt jede Zelle `–`, und unter der Tabelle steht die Zeile `Die Trends können gerade nicht gelesen werden. Laden Sie die Seite neu, um es erneut zu versuchen.` Einschränkungen: Eine Linie enthält höchstens die neuesten 240 Punkte, daher zeigt ein Abspielen, das schneller als etwa ein Tick je 75 Sekunden ist, weniger als die 4 Stunden, die die Überschrift nennt (der Pfeil vergleicht dann den ältesten und den neuesten dieser 240 Punkte); das Öffnen der Inselliste einer Region mit 256 Inseln kann etwa 13 Sekunden dauern, bis ihre Trendspalte gefüllt ist, bis zu etwa 20 Sekunden, wenn der Server diesen Verlauf zuletzt nicht gelesen hat, und die Diagramme anderer Seiten warten, während sie gelesen wird (die Inselliste selbst erscheint sofort).
- Diagramme: Der Name einer Ware in der Warentabelle einer Insel öffnet die Seite der Ware (`/profiles/<Profil>/islands/<Sitzung>/<Insel>/<Bereich>/goods/<Ware>`) mit den Bedienelementen (unten) und zwei Diagrammen, `Diese Insel` und `Alle Inseln der Region` (die Summe über die Inseln der Region, die einen Wert haben), jeweils mit den Linien `Produktion`, `Verbrauch` und `Delta`. Die Seite der Insel zeigt über ihrer Warentabelle das Diagramm `Übersicht` mit den Linien `Gebäude`, `Produzierte Waren` und `Waren im Defizit`, gezählt, wie die Inselliste sie für den letzten Tick zählt, und unter ihrer Überschrift die Bedienelemente. **Die Bedienelemente** sind zwei Schaltflächengruppen über den Diagrammen und eine Textzeile darunter: der Zeitraum `Letzte Stunde`, `Letzte 24 Stunden` (voreingestellt), `Letzte 7 Tage` und `Gesamt` sowie die Zeitachse `Echtzeit` (voreingestellt) und `Spielzeit`; die Zeile nennt den Zeitraum, zum Beispiel `Letzte 24 Stunden bis zum letzten Tick` (`Gesamter Verlauf bis zum letzten Tick` bei `Gesamt`). Eine Wahl gilt für alle Diagramme der Seite, wirkt ohne Neuladen (jedes Diagramm zeigt `Wird geladen…`, bis seine Punkte da sind, und eine schnelle zweite Wahl ersetzt die erste) und bleibt im Browser gespeichert, sodass die nächste Diagrammseite, ein Neuladen und der nächste Tag mit ihr öffnen; ohne gespeicherte Wahl, in einem Browser ohne Cookies und bei einem gespeicherten Wert, den der Server nicht kennt, öffnen die Diagramme mit `Letzte 24 Stunden` und `Echtzeit`. Ein Diagramm zeigt die Punkte vom Beginn der UTC-Stunde, in der die Zeit 1 Stunde, 24 Stunden oder 7 Tage vor dem letzten Tick des Profils liegt, bis zu diesem Tick (`Gesamt`: jeder Punkt des Profils), höchstens die neuesten 2.880 (eine Zeile unter dem Diagramm sagt dann `Die neuesten 2.880 von <n> Punkten angezeigt.`), und zeigt `Keine Werte in diesem Zeitraum.`, wenn kein Wert da ist. Fährt man über einen Punkt, erscheinen seine Zeit (in der Zeitzone Ihres Browsers, in UTC mit dem Zusatz `UTC`, wenn der Browser sie nicht nennen kann) und die Werte der Linien, `–` für keinen. Eine Linie wird unterbrochen, nie auf null gezogen, wo ein Wert fehlt und wo mehr als 15 Minuten zwischen dem Ende eines Punkts und dem Beginn des nächsten vergehen (eine Pause des Spiels, ein Ausfall); ein Spiel, das weitersendet, zeigt keine Lücke. Die Diagramme übernehmen die Farben des gezeigten Designs, werden beim Zeichnen von links nach rechts aufgedeckt (nicht, wenn ein Browser reduzierte Bewegung wünscht) und noch einmal, wenn ein neuer Tick eintrifft, und folgen einem Sprach- oder Designwechsel sofort. `Letzte 7 Tage` und `Gesamt` zeigen einen Punkt je Stunde, die einen Tick enthält, das Mittel der Ticks dieser Stunde (der Tooltip sagt `Stundenmittel`); ein neuer Tick ändert nur die neueste Stunde. Eine Woche einer großen Region (Hunderte Inseln) kann etwa zwei Minuten zum Lesen brauchen, wenn der Server sie zuletzt nicht gelesen hat, während `Wird geladen…` steht und die anderen Diagramme warten. Die Zeiten folgen der Zeitzone Ihres Browsers beim letzten Tick; bei `Letzte 7 Tage` und `Gesamt` rückt daher eine Sommerzeitumstellung im Zeitraum die Stunden davor um eine Stunde daneben, und eine Zeitzone ohne volle Stunde (+5:30) setzt die Stundenpunkte zwischen die Beschriftungen. Die Beschriftungen sind `HH:mm`, mit Datum (`MM-dd HH:mm`), wenn die Punkte mehr als einen Tag umfassen, und ihr Abstand wächst mit der Spanne (10 Minuten bis 365 Tage, höchstens 8 Intervalle). **`Spielzeit`** setzt jeden Punkt an seine Spielzeit, sodass eine Spielpause keine Lücke lässt: Die Zeitachse hat keine Beschriftungen und keine senkrechten Hilfslinien (nur die waagerechten Rasterlinien der Wertachse), und der Tooltip zeigt die echte Zeit des Punkts und dann `Spielzeit <h>:<mm>` (Stunden nicht auf einen Tag begrenzt; bei einem Stundenmittel die größte); eine Linie wird nur unterbrochen, wo ein Wert fehlt oder mehr als 15 Minuten Spielzeit vergehen; der Tick, den das Spiel nach dem Laden eines Spielstands sendet (keine Insel hat einen Eintrag), entfällt. Die Spielzeit wird als Millisekunden gelesen, was ein Lauf mit 1-facher Geschwindigkeit bestätigt hat; eine Stunde einer zusammengefassten Woche, deren kleinste Spielzeit die eines solchen Ladeticks ist, kann sich ohne Unterbrechung an die Stunde davor anschließen. Ticks, die älter als 7 Tage sind, bleiben als Stundenmittel erhalten: Ein solcher Punkt steht für eine Stunde, und eine Pause innerhalb einer Stunde ist bei `Echtzeit` nicht mehr zu sehen (auch bei `Letzte Stunde` und `Letzte 24 Stunden`, sobald die Stunde zusammengefasst ist). Eine Aufzeichnung, die älter als 7 Tage ist und die Sie mit `--server` abspielen, zeigt daher jede Pause, bis der nächste Aufbewahrungslauf des Servers (er läuft einmal beim Start und danach jede Stunde) sie zusammengefasst hat, und dann als Stundenmittel, untereinander und mit den Ticks der letzten Stunde verbunden (*Verlauf und Löschen eines Profils*).

Die Seiten füllen sich, sobald der Companion Daten sendet.`; eine Adresse, die nichts benennt, zeigt `Nicht gefunden.`

## Verlauf und Löschen eines Profils

Der Server ab dem Release `0.4.0` hält den Verlauf jedes Profils in seiner Datenbank und kann ihn löschen.

- Aufbewahrung: Ein Tick bleibt 7 Tage so erhalten, wie der Server ihn empfangen hat. Liegt eine ganze UTC-Stunde 7 Tage oder länger zurück, fasst der Server die Ticks dieser Stunde, einen Tick nach dem anderen, zu einem Stundenpunkt des Profils zusammen (je Insel und Ware die Summen und Anzahlen ihrer Werte, damit später Mittelwerte gezeigt werden können) und entfernt sie; die Stundenpunkte bleiben ohne Begrenzung erhalten. Die Stunde des letzten Ticks eines Profils wird nie zusammengefasst, ein Profil, das Sie eine Woche nicht gespielt haben, zeigt also weiterhin seinen letzten Tick. Ein Abspielen behält die Zeiten der Aufzeichnung, die Ticks einer alten Aufzeichnung werden deshalb im nächsten Lauf zusammengefasst, außer denen ihrer letzten Stunde; die Diagramme zeigen sie dann als Stundenmittel (*Weboberfläche*). Der Lauf beginnt, nachdem der Server lauscht, läuft einmal beim Start und danach jede Stunde und arbeitet, während der Server bedient: Die Daten eines Companions werden weiterhin sofort gespeichert (sie warten höchstens auf einen Schritt, selbst beim größten Tick, den der Vertrag erlaubt, etwa 4 Sekunden). Ein Lauf, der zusammengefasst hat, schreibt `History reduced to hourly averages: <h> hours from <t> ticks.` ins Log; ein fehlgeschlagener Schritt ändert nichts und schreibt `The history could not be reduced; the next run tries again.`
- Größe: Die Datenbankdatei schrumpft nie, der Platz, den Zusammenfassen und Löschen freigeben, wird von neuen Daten wiederverwendet. Eine zusammengefasste Stunde der Testaufzeichnung des Repositorys (etwa 680 Waren) braucht etwa 5 % des Platzes ihrer Ticks, 137 KB, das sind etwa 1,2 GB im Jahr bei durchgehendem Spielen; der Server behält außerdem die Kennung jedes zusammengefassten Ticks ohne Ende, etwa 108 Byte je Tick (etwa 28 MB im Jahr bei einem Tick alle zwei Minuten) ([`docs/areas/history.md`](areas/history.md), *Measurements*).
- Löschen: Die Regionenübersicht eines Profils (`/profiles/<Profil>/regions`, über den Profilschalter erreichbar) hat die Schaltfläche `Verlauf löschen`. Sie öffnet den Dialog `Verlauf löschen?` mit dem Text `Alle Daten des Profils <Name> werden vom Server entfernt: seine Regionen, Inseln, Waren, Handelsrouten und sein Verlauf. Das lässt sich nicht rückgängig machen.`; `Abbrechen` schließt ihn, `Löschen` entfernt das Profil mit allem, was der Server von ihm hält, ohne Sicherung. Der Katalog, die Symbole und die anderen Profile bleiben. Danach geht die Seite zu `/regions`, das Profil verschwindet aus dem Profilschalter, und eine Seite, die es zeigt, zeigt `Nicht gefunden.`. Schlägt das Löschen fehl, bleibt der Dialog offen und sagt `Der Verlauf konnte nicht gelöscht werden.`; nichts wurde geändert. `/regions`, das dem neuesten Profil folgt, hat keine Schaltfläche. Ein Companion, der noch unter dem gelöschten Profil sendet, legt es wieder an, ohne Namen bis zu seinem nächsten Hello.
- Wer löschen darf: Es gibt keine Anmeldung, deshalb funktioniert die Schaltfläche nur auf einer Seite, die Sie über die IP-Adresse geöffnet haben (zum Beispiel `http://192.168.1.10:8080/`), als `localhost` oder über einen Hostnamen, den die Einstellung `AllowedHosts` nennt (Umgebungsvariable `ALLOWEDHOSTS`, Namen durch `;` getrennt, `*.example.com` für eine Domain; zum Beispiel `-e ALLOWEDHOSTS="nas;censio.example.com;127.0.0.1"`). Auf jeder anderen Seite ist die Schaltfläche deaktiviert und sagt `Löschen setzt voraus, dass diese Seite über die IP-Adresse oder localhost geöffnet wurde, oder über einen Hostnamen, den die Einstellung AllowedHosts nennt.` Das hindert eine Seite einer anderen Website (DNS-Rebinding) am Löschen. Wer den Server über seine Adresse erreicht, kann den Verlauf jedes Profils trotzdem löschen, beschränken Sie also, wer den Port erreicht (*Netzwerk und TLS*). Namen in `AllowedHosts` schalten außerdem die Hostfilterung von ASP.NET Core für jede Anfrage ein: Eine Anfrage für einen anderen Host wird mit `400` beantwortet, tragen Sie also jeden Namen und jede Adresse ein, über die der Server erreicht wird (`127.0.0.1` für den Health-Check des Images, den Namen in `--server` des Companions), `[::1]` für IPv6-Loopback. Ohne Wert ist `AllowedHosts` `*` und filtert nichts.
- Hinter einem Reverse-Proxy sieht der Server den Host, den der Proxy sendet. nginx sendet seine eigene Adresse (`$proxy_host`), wenn nichts anderes gesagt wird, und macht damit jede Seite, die er ausliefert, vertrauenswürdig, auch die Seiten einer anderen Website. Geben Sie deshalb den Host des Clients weiter (`proxy_set_header Host $host;`) und lassen Sie den Proxy nur seine eigenen Namen beantworten, die Sie in `AllowedHosts` eintragen.
- Aufräumen: Ist das Profil weg, entfernt der Server seine Zeilen Schritt für Schritt und räumt sie dann aus der Datenbankdatei (SQLite überschreibt, was es löscht, und das Write-Ahead-Log wird gekürzt). Er schreibt `The history of a profile was deleted.`, wenn das Profil weg ist, und `The deleted history was cleared from the database file.`, wenn kein Name, den nur dieses Profil hielt, mehr in `censio.db` oder den Dateien daneben steht; ein fehlgeschlagenes Löschen schreibt `The history of a profile could not be deleted.` (nichts wurde geändert). Ein Lesevorgang, der das Log festhält, kann das Aufräumen verzögern: Der Server schreibt dann `The deleted history could not yet be cleared from the database file; the next retention run tries again.` und versucht es innerhalb der Stunde erneut. Keine Zeile nennt ein Profil.
- Ältere Kopien von Namen: Ein Server des Releases `0.3.0` hat Gelöschtes nicht überschrieben, deshalb können Kopien von Namen, die er geändert hat, im freien Platz einer von ihm gefüllten Datei übrig bleiben, und das Aufräumen erreicht sie nicht. Um sie zu entfernen, den Server stoppen (`docker stop censio`), eine Kopie der Datei aufbewahren, auf ihr `sqlite3 censio.db "VACUUM;"` ausführen (es braucht noch einmal so viel freien Platz wie die Datei und schreibt die ganze Datei neu) und den Server starten.
- Noch nicht ausprobiert: die Schaltfläche auf echter Hardware mit einem Reverse-Proxy und `AllowedHosts` sowie das Aufräumen und `VACUUM` auf einer Datenbank, die ein früherer Server gefüllt hat.

## Daten und Logs

Server: Das Datenverzeichnis ist im Docker-Image `/config`. Es enthält den Data-Protection-Schlüsselring in `/config/data-protection-keys` und, solange `CENSIO__INGEST__TOKENFILE` nicht gesetzt ist, das Ingest-Token in `/config/ingest-token`; die Schlüssel und das Token sind unverschlüsselt, deshalb das Verzeichnis und seine Sicherungen privat halten. Der Server schreibt kein Token ins Log. Der Server ab dem Release `0.3.0` hält dort auch seine SQLite-Datenbank, `/config/censio.db` (die Einstellung `CENSIO__DATABASE__FILE` nennt einen anderen absoluten Pfad; ohne sie und ohne Datenverzeichnis liegt die Datenbank im Arbeitsspeicher und geht beim Stoppen des Servers verloren). Sie enthält Profil-, Insel-, Handelsrouten- und Ordnernamen, die privat sind: Der Server legt die Datei, die Dateien, die SQLite beim Laufen daneben hält (`censio.db-wal`, `censio.db-shm`), und einen Ordner, den er anlegt, nur für ihren Eigentümer lesbar an (Modus `0600` und `0700` unter Linux) und schreibt den Pfad der Datei ins Log, nie einen Namen oder einen Wert. Der Server speichert jedes Profil, jeden Tick, jede Handelsrouten-Nachricht, jeden Katalog und jedes Symbol, das er empfängt, bevor er es bestätigt, und die Datei wächst mit jedem Tick (etwa 77 KB für einen echten Tick, etwa 55 MB am Tag bei einem Tick alle zwei Minuten), bis der Server Ticks, die 7 Tage alt sind, zu Stundenwerten zusammenfasst (*Verlauf und Löschen eines Profils*). Beim Start stellt er vor dem Lauschen den letzten Stand jedes Profils aus der Datei wieder her und schreibt `Profiles restored from the database: <n>.` ins Log (`<n>` ist die Zahl der gespeicherten Profile, `0` bei der In-Memory-Datenbank); kann er den Stand nicht lesen, endet er mit Exit-Code 1 und der Zeile `The current state cannot be read from the database '<Datei>'; the server stops.` Eine Nachricht, die er nicht speichern kann, bestätigt er nicht: Er schließt die Verbindung und schreibt `A message could not be stored; the connection is closed.` mit der Exception ins Log, und der Companion verbindet sich neu und sendet die Nachricht erneut; `The current state of a profile cannot be read from the database.` und `A follower of the current state failed.` sind die anderen Zeilen über den Stand, und keine nennt ein Profil oder eine Insel. Die Datenseiten zeigen sie (*Weboberfläche*). Eine Sicherung ist eine Kopie von `censio.db`, die bei gestopptem Server gezogen wird (`docker stop censio`, dann aus dem Volume oder dem eingehängten Ordner kopieren); eine wiederhergestellte Kopie darf nur für den Benutzer des Servers lesbar sein (`chmod 600 censio.db` unter Linux, denn die Dateien, die SQLite daneben hält, übernehmen ihren Modus), und die Datei gehört auf einen lokalen Datenträger. Ein neuerer Server bringt eine ältere Datenbank beim Start auf sein Schema und behält ihre Daten, und ein älterer Server verweigert eine neuere Datenbank (`The database '<Datei>' was written by a newer Censio version; the server stops. Start that version or a newer one.`); die anderen Startfehler sind `The database '<Datei>' cannot be opened or written; the server stops. Make its folder writable for the user the server runs as.`, `The file '<Datei>' is not a readable Censio database; the server stops.` und `The database '<Datei>' cannot be updated to the current schema; the server stops.`, jeweils mit Exit-Code 1 vor dem Lauschen des Servers und mit unveränderter Datei. Ausprobiert mit Docker Engine unter Linux und einem aus einem Checkout gebauten Image: die Zeile `created` beim ersten Start, die Zeile `opened` bei einem zweiten Container auf demselben Volume und Modus `600` für die Datei sowie für `-wal` und `-shm`, solange der Server lief. Noch nicht ausprobiert: NAS-Hardware, eine wiederhergestellte Sicherung und die anderen Startfehler in einem Container. Der Server schreibt sein Log auf die Konsole; Lesen mit `docker logs censio`. Die Logzeiten sind UTC. Die Einstellungen stehen in der [README](../README.md#konfiguration).

Companion: Er speichert Spieldaten im Katalog-Cache `%LOCALAPPDATA%\Censio\Cache\catalog.bin` (die Namen und Symbole Ihres Spiels, nach einer vollständigen Extraktion gespeichert, die Datei nie gesendet und beim Entfernen des Companions behalten, also den Ordner von Hand löschen; er enthält temporäre Dateien nur für den Augenblick eines Speicherns, und der Companion löscht Reste, die älter als ein Tag sind) und, nur im lokalen Modus, im Datenordner des lokalen Servers `%LOCALAPPDATA%\Censio\Server` (die Datenbank `censio.db` mit den Profilen sowie den Insel- und Handelsroutennamen, die sie empfangen hat, der Schlüsselring und das Ingest-Token, privat für Ihr Windows-Konto und beim Entfernen des Companions behalten, also den Ordner von Hand löschen; *Lokaler Modus*), und, nur wo Live-Daten gesendet werden, den Live-Puffer in `%LOCALAPPDATA%\Censio\Buffer` (die auf den Server wartenden Nachrichten, wie gesendet: Inselnamen, die Wirtschaft und Handelsrouten, nie das Token; privat für Ihr Windows-Konto und beim Entfernen des Companions behalten, also den Ordner von Hand löschen; *Weiterleitungsmodus*), und das Diagnosefenster speichert nichts (es zeigt den letzten Tick nur auf dem Bildschirm und schreibt nichts auf die Platte oder ins Log). Aufzeichnungsdateien schreibt er nach `%LOCALAPPDATA%\Censio\Recordings` nur, solange eine Aufzeichnung läuft (`--record` oder `Start recording`); sie enthalten die Daten des eigenen Spiels, wie sie gesendet wurden, bleiben auf dem Rechner und werden vom Programm nie gelöscht, also von Hand löschen (*Aufzeichnen und Abspielen*). Außerdem schreibt er ein Log nach `%LOCALAPPDATA%\Censio\Logs`: eine Datei pro Tag, `companion-<yyyyMMdd>.log` (wird eine Datei über 10 MiB groß, wird das Log in `companion-<yyyyMMdd>-2.log` und weiteren Dateien fortgesetzt). Der Companion behält die 10 neuesten dieser Dateien und löscht ältere; andere Dateien im Ordner löscht er nicht. Die Menüeinträge `Open recordings folder` und `Open log folder` öffnen beide Ordner im Explorer. Nur wenn Sie `Start with Windows` einschalten, schreibt er einen Wert `Censio Companion` unter `HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run` (nur Ihr Konto), und er löscht diesen Wert beim Ausschalten; das Log enthält dann `Autostart enabled` oder `Autostart disabled` und eine Warnung, wenn die Einstellung nicht gelesen oder geändert werden konnte (ohne Dateipfad). Eine Zeile enthält die lokale Zeit, die Stufe und die Meldung: den Start, jede Änderung des Verbindungszustands, Aufzeichnung gestartet und beendet, die Namen der Aufzeichnungsdateien, Beginn und Ende eines Abspielens, das Ergebnis der Suche nach der Spielinstallation (die Quelle, der Build und der Spieleordner oder der Grund des Scheiterns; siehe *Spielinstallation*), das Ergebnis des Katalogs (Anzahl der Einträge oder die Fehlerart), ob der Cache benutzt, geladen oder geschrieben wurde, die Dauer einer Extraktion oder eines Cache-Ladens, die Anzahlen seiner Symbole und die GUIDs, die er nicht benennen kann (siehe *Spielkatalog*), und Probleme. Das Log enthält keine Spieldaten, keine Spielnamen und keine Symbole, aber der Spieleordner bei jedem Start und ein Fehlertext können einen Dateipfad und damit den Windows-Benutzernamen enthalten; prüfen Sie ein Log, bevor Sie es weitergeben. Im lokalen Modus enthält das Log außerdem die Zeilen `Local server running on port <port>`, `Local server port <port> in use`, `Local server failed` und `Local server stopped unexpectedly`, `Could not open the browser` sowie die Warnungen und Fehler des betriebenen Servers (nicht seine anderen Zeilen und nie das Token). Im lokalen Modus und im Weiterleitungsmodus wird eine falsche Einstellung als `Server settings invalid: <Problem>` protokolliert, und das Senden im laufenden Betrieb schreibt `Live sending connected to the server` bei jeder angenommenen Verbindung, `Live sending failed: <Grund>; retrying`, wenn sich der Grund eines Fehlers ändert, `Live sending refused by the server: <Grund>; not retried` bei einem abgelehnten Token oder einer abgelehnten Vertragsversion, `Server refused a live message: <Art>`, `Live message not sent: the contract writer refused it` und `Live messages dropped: <n>`, `Live buffer holds <n> messages from an earlier run`, `Live buffer cannot be written; waiting messages are kept in memory until Exit` und `Live buffer entries unreadable: <n>; discarded`, dazu für den Katalog `Catalog sent to the server: <i> icons sent, <r> refused`, `Catalog already on the server`, `Server refused the catalog: <Art>`, `Catalog not sent: the contract writer refused it` und `Catalog not sent: the connection failed 3 times during its upload`, nie das Token, die Adresse, einen Namen, einen Pfad, den Inhalt einer Nachricht oder einen Ausnahmetext (*Weiterleitungsmodus*). Der Companion liest außerdem die optionale Einstellungsdatei `%LOCALAPPDATA%\Censio\settings.json` (den Spielordner, im lokalen Modus `mode` und `localPort`, im Weiterleitungsmodus `mode`, `serverAddress` und `serverToken` und in beiden `bufferHours` und `bufferMegabytes`, sodass die Datei Ihr Ingest-Token enthalten kann: nicht weitergeben) und die Installationseinträge von Ubisoft Connect in der Registry, schreibt sie aber nie.

## Probleme melden

Ein GitHub-Issue mit der Vorlage [Bug report](../.github/ISSUE_TEMPLATE/bug_report.md) auf `https://github.com/LarsLaskowski/Censio/issues/new/choose` öffnen. Angeben:

- die Version: die Startseite (`Version <version>`) oder das Tray-Menü des Companions;
- wie er läuft: den `docker run`-Befehl (ohne Geheimnisse und private Pfade) oder wie der Companion gestartet wurde, und das Host-Betriebssystem;
- das Log: einen Auszug aus `docker logs censio` (Tokens und andere Geheimnisse schwärzen); beim Companion die Logdatei des Tages in `%LOCALAPPDATA%\Censio\Logs` (der Tray-Menüeintrag `Open log folder` öffnet den Ordner). **Das Log vor dem Weitergeben auf den Windows-Benutzernamen prüfen:** ein Fehlertext kann einen Dateipfad wie `C:\Users\<Ihr Name>\...` enthalten, deshalb den Namen ersetzen oder die Zeile entfernen. Eine unbearbeitete Aufzeichnung (`--record`) nie an ein Issue anhängen oder öffentlich posten, sie enthält private Namen und Spieldaten; stattdessen das Problem und den Tooltip beschreiben und die Datei aufheben, bis ein Maintainer sagt, wie sie übergeben werden kann. Ein Screenshot des Diagnosefensters zeigt ebenfalls die Inselnamen Ihres Spielstands: Verdecken Sie sie oder beschreiben Sie das Problem stattdessen, bevor Sie ihn anhängen. Den Katalog-Cache (`%LOCALAPPDATA%\Censio\Cache\catalog.bin`) nie anhängen, er enthält die Namen und Symbole Ihres Spiels.

Eine Sicherheitslücke privat melden, wie [SECURITY.md](../SECURITY.md) es beschreibt, nie in einem öffentlichen Issue.
